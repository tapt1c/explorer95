# Следующие задачи Explorer95

Список сохранён по запросу пользователя для следующего рабочего захода после
сброса лимитов. Все четыре пункта реализованы. Целевая проверка в Windows 95 остаётся обязательной. Порядок пунктов — как
в запросе пользователя; все изменения должны сохранять поддержку Windows 95
и классическое оформление.

## Сейчас: рабочий стол — WIP, пока не выпускать релиз

Запрос: исправить двойной клик по свободному месту рабочего стола и кадры,
в которых исчезают значки/белые подписи, остаются только чёрные тени.

Уже сохранено:

- Пустой WM_LBUTTONDBLCLK поглощается в native ListView и desktop host.
- В WM_PAINT фон, тени и штатный foreground собираются в desktopFrame;
  отдельный WM_ERASEBKGND сохраняет готовые пиксели. Нативный редактор имени
  защищён WS_CLIPCHILDREN, буферы освобождаются вместе с view.
- Учтены WM_SETREDRAW, структурные изменения ListView и исходящий OLE drag.
  Повторное рисование откладывается до завершения операции.
- В NativeDesktopPaintTests есть проверки foreground+shadow, отдельного erase,
  частичного paint, resize, redraw hold и вложенного paint после LVN_DELETEITEM.
  Последняя проверка удаляет только элемент временного view, без удаления файла.
  Она падает на первом WIP-коммите без desktopMutationDepth и проходит с защитой.

Проверено локально: core и x86 make check/PE проходят. Отдельный browser-прогон
с защитой тоже прошёл, но **full по-прежнему падает** после переноса файла
с рабочего стола и следующего F5: comctl32 DPA_GetPtr -> LVM_GETITEMTEXTA ->
desktop_icons Name/Capture -> DesktopIconsBeginRefresh -> NativeViewRefresh.
Исходный коммит 945c8fb проходит тот же browser-сценарий. Не ослаблять тесты
и не считать один удачный subset-прогон достаточным для релиза.

Ключевая последняя находка: временный журнал показал вход NativeViewRefresh
с **paintingDesktop=TRUE, desktopMutationDepth=0** непосредственно перед падением.
Вложенных структурных LVM-операций в этом журнале нет. Следующая задача — безопасно
отложить refresh до выхода из PaintDesktopFrame, сохранив запросы F5 и обновление
после Drag and Drop; добавить регрессию такого повторного входа. Нынешняя защита
рисования во время mutation/drag этого обратного направления не покрывает.
Диагностика heap также обнаружила повторное освобождение блока после desktop move;
включение проверки heap меняет проявление ошибки, а не исправляет её.

Локальные материалы (build игнорируется Git): desktop-final-full.log,
desktop-order.log, desktop-order-trace.log, desktop-guard-core.log,
desktop-guard-build.log, desktop-paint-guard.log, desktop-native.dmp;
регрессия до защиты — в дополнительном worktree explorer95-baseline,
build/desktop-delete-red.log. Временные правки smoke/render_trace для журналирования
убраны из исходников. Публикуемый Win95 EXE не заменять отладочной x64-сборкой.
После исправления нужны полный UI-прогон, x86/PE, просмотр на 640x480 и 1024x768,
а затем проверка исходного видеосценария на настоящей Windows 95. Примечания
будущего релиза обновить только после завершения исправления.

## 1. Выполнено: Drag and Drop

- Добавить Drag and Drop операций с файлами и папками на рабочем столе
  Explorer95 и в файловом Проводнике, включая перенос между ними.
- Учесть существующее свободное перемещение значков рабочего стола: файловые
  операции должны сосуществовать с ручной раскладкой, её сохранением и сеткой.
- Сохранить штатные подтверждения и отмену файловых операций Windows 95.

## 2. Выполнено: Кнопки задач в стиле Windows 7

- Добавить в настройки панели задач выбор вида кнопок/плиток задач в духе
  Windows 7, сохраняя существующий классический вид как вариант.
- Поддержать этот вид как с группировкой окон, так и без группировки.
- Использовать общую вкладку Taskbar и сохранять выбор после перезапуска.

## 3. Выполнено: Порядок правой колонки меню Пуск

Установить следующий порядок сверху вниз; отсутствующие пункты добавить:

1. My Documents
2. Recent Documents
3. Favorites
4. My Computer
5. Network Neighborhood

**Разделитель**

6. Control Panel
7. Printers
8. Command Prompt

**Разделитель**

Сохранить пользовательские переключатели видимости пунктов и проверку
доступности сети. Разделители должны учитывать скрытые пункты и пустые группы.

## 4. Выполнено: Служебные символы Marlett

- Перенести стрелки вроде `>` и аналогичные служебные символы меню Пуск
  и панели задач на соответствующие глифы шрифта Marlett.
- Сохранить совместимость с Windows 95 и запасной способ отрисовки,
  если нужный шрифт недоступен.

## Проверки при реализации

Следовать пропорциональному выбору проверок из AGENTS.md. Для реализации,
затронувшей несколько подсистем, нужны сборка x86/PE, геометрия и полный UI-прогон.
Проверки переноса файлов работают только со своими временными файлами.
Особенности Shell32 Windows 95 RTM/OSR2 и переноса между сторонними приложениями
дополнительно проверяются на целевой системе.
