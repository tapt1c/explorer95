# Следующие задачи Explorer95

## Alt+Tab с предпросмотром: исправить перехват на настоящей Win95

Пользователь проверил alpha.51 на настоящей Windows 95: вместо Explorer95
появляется штатный переключатель. Успешная установка WH_KEYBOARD и Wine-прогон
не подтверждают доставку системного сочетания на Win95. Причина ещё не установлена;
не считать отказ исправленным по одному новому успешному Wine-прогону.
Добавлена диагностика `--trace-render`: этап отказа запуска в `task-switch-hook`
(a: 1 окно, 2 ресурс, 3 временная DLL, 4 загрузка, 5 экспорты, 6 установка hook),
число обращений к владельцу в `task-switch-ready` и команды в `task-switch-command`.
Запись ready отложена до обычного таймера, чтобы I/O не тратил 60ms ответа hook.
Названия окон, содержимое и обычные клавиши в эти события не попадают.

Добавлено окно по образцу пользователя: градиентная шапка, сохранённый снимок
слева, отдельные окна приложений справа, имя приложения и счётчик снизу.
Классический WH_KEYBOARD в отдельной встроенной DLL перехватывает Alt+Tab из
других процессов; Alt+Shift+Tab идёт назад, Alt-up/Enter подтверждают, Esc отменяет.
Общий список задач исключает desktop/tool/owned окна, группировка панели на него
не влияет. Свёрнутые окна восстанавливаются, модальный popup получает активацию.
Миниатюры ограничены восемью ранее видимыми окнами; иначе показывается значок.
Окна не активируются ради получения скрытого содержимого.
Foreground выбранной задаче передаётся до скрытия переключателя: это сохраняет
право активации модального окна при участии внешнего оконного менеджера.

Пройдены новые сценарии и menu-прогон Wine на 640×480, включая повторный запуск
и очистку профиля. Полный локальный прогон останавливается до запуска Explorer95 в старом
DesktopLabelPaintTests: та же проверка не проходит на исходном 8df555e в этом
локальном Wine. Проверку не ослабляли. Реальный перехват штатного Alt+Tab на
Windows 95 RTM/OSR2 ещё нужно проверить в ВМ.
Сборка x86/PE и проверка инкрементальной сборки прошли. Language-прогон также
останавливается на старой проверке пикселей toolbar glyph; отказ повторяется
на исходном 8df555e. Отдельный host layout не запускался из-за отсутствия cc;
геометрия нового окна проверена реальным menu-сценарием на 640×480.
Полный CI основной ветки и релиза v0.9.0-alpha.51 прошёл после проверки порядка
сценариев: Alt+Tab не должен менять фокус до cold-start проверки --open.
Скачанные EXE/ZIP проверены по SHA256, встроенным DLL и Win95 PE baseline.

Обновлены настройки первого запуска: показаны все правые пункты Пуска в заданном
порядке; Recent Documents / Favorites / Printers — подменю, остальные — ссылки.
В начальном списке закреплён только Windows Explorer. Существующие маски и pins
не переписываются. Пользователь подтвердил, что вариант MS-DOS alpha.47 показывает
заглушку. Он заменён галочкой, меняющей только Restart, и подготовкой собственного
PIF через PifMgr Win95 с real-mode флагом, записью и проверкой. Готовый системный PIF
не требуется, запасной диалог убран. Окно осталось 314×200. Реальный переход в DOS
нужно подтвердить в пользовательской ВМ; инертные тесты его не выполняют.

Пользовательский EX95REND.LOG из alpha.48 показал ERROR_INVALID_DATA на стадии 8
MS-DOS PIF. Ошибка повторного открытия исправлена: второй аргумент PifMgr Open
является назначением и пересоздавал PIF из COMMAND.COM. Для проверки теперь
открывается сам PIF первым аргументом, без назначения и обработки INF. Mock
моделирует реальное пересоздание; регрессия упала до исправления и прошла после.
Добавлены числовые подробности проверки в лог без путей. Реальный переход в DOS
после исправления ещё требует подтверждения в ВМ пользователя.

Исправлены пропуски перевода callback-подсказок Проводника, System Folder,
собственных пунктов классического/More меню и отдельных подписей сведений.
ANSI/Unicode-подсказки получают свой правильный текст и шрифт.

GroupTasks определяет приложение по полному пути EXE, а не только PID:
проверены три независимых процесса, объединение двух запусков одного EXE,
отдельная группа для копии с тем же именем в другой папке, выбор обоих окон,
классические кнопки/плитки и отключение группировки.

На CP1251 сохраняется системный русский шрифт; на других кодовых страницах
остаётся встроенный. Исправлен недетерминированный ключ кэша LOGFONT:
очищаются неиспользуемые байты имени шрифта. До исправления реальный tooltip
получал другой HFONT при одинаковом исходном шрифте. После исправления проверки
прошли на Wine с ACP1252 и ACP1251. Результат на настоящей Win95 нужно подтвердить.

После alpha.42 пользователь подтвердил нормальную отрисовку остальных значков,
но заметил оставшееся смещение ярлыка Блокнота влево. Исправлены координаты:
LVIR_ICON старого ListView включает поля выделения, а изображение и ghost теперь
центрируются внутри них по фактическому размеру ImageList. Регрессия с полями
8×2 воспроизвела ошибку до исправления и прошла после; нужна проверка на ВМ.

В меню панели задач Task Manager заменяет Exit Explorer95. Пользователь
подтвердил работу TASKMAN.EXE и отказ Ctrl+Alt+Del в alpha.43 на настоящей Win95.
Неработающий keyboard request и его переключатель удалены; старый ClosePrograms
игнорируется, команда всегда запускает штатный TASKMAN.EXE.

## Не завершено: вызов именно окна Ctrl+Alt+Del и выбор обоих вариантов

Запрос пользователя на персонализацию TASKMAN / системное окно «Завершение
работы программы» сохраняется. Для второго пока не найден подтверждённый вызов
на Win95. Тест инертных keyboard callbacks не доказывает работу этой функции;
шесть вызовов keybd_event не открыли диалог в ВМ пользователя. Не возвращать
переключатель до целевой проверки работающего метода. В старом WinVNC 3.3.3
ветка Win95 отправляет обычные события клавиш; отдельный SimulateCtrlAltDel
относится к NT/Winlogon и не является решением для Windows 95.

отмену, отключённую стрелку и фактически нарисованные линии/рамки/глиф.

## В работе: завершение Explorer95 после переноса на Windows 95

Продолжение проверки закрытия: ВМ 86Box находится локально у пользователя,
доступа к ней из текущего cloud-окружения нет. Само зависание Win95 здесь
не воспроизведено. Добавлена проверка закрытия панели во время активного OLE
переноса (кнопка мыши ещё удерживается, цель приняла перенос). На Wine 10
исходная версия тоже проходит этот сценарий; это не доказательство причины
Win95-остановки. WM_CLOSE теперь явно отменяет перенос через FileDragDeferClose
до отправки WM_QUIT и ждёт возврата OLE перед обычной очисткой.

Для следующего целевого прогона: запустить с --trace-render, повторить перенос,
выйти через Exit и сохранить EX95REND.LOG до перезапуска. Новые exit.* и
view.exit.* показывают этапы вплоть до OleUninitialize/exit.done; резерв 8 КиБ
сохраняет эти строки даже после насыщения основной части журнала. Если exit.done
нет, последняя строка сузит место остановки. Не отмечать Win95-ограничение
исправленным без этого целевого прогона.

Проверены x86/PE (302 импорта в 8 системных DLL), browser и полный UI-прогон
Wine 10 на 640×480. Полный прогон требует сохранности source/пустой destination,
выхода за 5 секунд, восстановления work area, перезапуска и последовательности
этапов журнала вплоть до exit.done после возврата OleUninitialize.

## Выполнено: перенос рабочего стола через ярлык диска на Windows 95

По видео pQja9zQl1y найдено отличие настоящей Shell32 от Wine: Windows 95
заранее регистрирует IDropTarget дочернего desktop ListView. Прежний отказ
DRAGDROP_E_ALREADYREGISTERED оставлял штатный обработчик, поэтому перенос
своего EXE через ярлык диска на пустое место мог создавать ярлык.
FileDropRegister теперь заменяет регистрацию только при наличии удержанного
native fallback; при отказе новой регистрации восстанавливает native target.
Виртуальные цели продолжают использовать тот же fallback.

Регрессия на отдельном собственном окне проверяет замену, сохранение чужой
регистрации без fallback, повторную регистрацию и баланс COM-ссылок.
Прошли x86/PE, browser и полный CI. В тестовой Windows 95 под 86Box проверен
реальный mouse_event-перенос собственного EXE при 32px и свободной расстановке:
через ярлык диска на пустой фон значок переместился с 240,180 на 303,283,
количество элементов осталось прежним, исходный файл сохранился.
Собственные тестовые файлы удалены отдельной Win95-проверкой. Повторный прогон
остановился на ожидании закрытия прежней тестовой копии Explorer95; причина
не установлена, поэтому закрытие после этого сценария требует отдельной проверки.
Этот сценарий не заменяет проверку остальных режимов и вариантов Shell32.

## Выполнено: подсветка целей переноса и размер панели задач

Дополнение по видео YQQ3ygvI83: проход над папкой с возвратом на свободное
место возобновляет расстановку, включая виртуальные Inbox/My Computer/Корзину.
Local Drop не вызывает файловую операцию; позиции применяются после выхода
из OLE, Escape сохраняет их. Ghost приостанавливается и возвращается.
Line up уплотняет текущий визуальный порядок, измеряя значок и текст вместо
пустых частей штатной ячейки. Покрыты виртуальный source, путь через папку,
отмена и Drop в 32/48px, кликабельность подписей и устойчивость после native paint.

Дополнение: исправлена сетка при Snap to Grid и длинных именах ярлыков.
FitPlacement и перенос к границам сохраняют целые ячейки вместо смещения
на несколько пикселей по границе подписи. TryCell учитывает реальный размер
32/48px. Restore нормализует старые смещения при Snap, свободный режим
сохраняет произвольные точки. Регрессия проверяет длинные имена, перенос к краю,
переименование, отсутствие пересечений и повторную загрузку старых координат.

Подсветка следует принятому effect из собственного или native обработчика.
Папки и Корзина используют LVIS_DROPHILITED, не меняя выделение; уход на фон,
возврат, Drop и Escape обновляют состояние старой/новой цели. Объекты с
SFGAO_DROPTARGET без SFGAO_FOLDER сохраняют native обработчик.

Рабочий стол рисует стабильные элементы во время собственного OLE source loop.
Новые native callbacks, структурные изменения, redraw hold и refresh по-прежнему
защищены; F5 откладывается до завершения переноса. Для 48px composite учитывает
подсветку и у значков без overlay.

WM_SIZING сразу привязывает RECT панели к целым строкам, сохраняет сторону
закрепления и учитывает высоту плиток 44px. Есть проверки всех четырёх краёв,
плиток, принятого hover, ухода/возврата и отмены на реальной OLE-операции.
Wine 10 не рисует штатный LVIS_DROPHILITED: его состояние проверяется отдельно,
а реальное изменение пикселей до отпускания мыши проверяется на composite 48px.
Сходство подсветки и поведения resize с исходным видео нужно проверить на Win95.

## Выполнено: размеры значков рабочего стола 32×32 и 48×48

Выбор 16×16 удалён из Desktop settings и Icon Layout → Icon Size. Значения
32 и 48 сохраняются в `[Desktop] IconSize`; старое 16 и неверные значения
трактуются как 32. Предпросмотр показывает полный значок 48px.

Для 48px используется отдельная увеличенная копия системных изображений,
с сохранением индексов, прозрачности, настоящих overlays и состояния выделения/
подсветки цели. Общие списки Windows не меняются. Ghost получает исходные
изображения; цвет и маска composite масштабируются вместе до рисования.
ImageList получает уже готовые 48px-значки и не выполняет увеличение.
При teardown свои списки
освобождаются после возврата исходного NORMAL и его политики владения Shell32.

Проверены размеры, позиции/F5, замена native image list, overlay/composite,
подсветка цели, прозрачный ghost и отмена, Apply/Cancel, старый профиль 16px
и настоящий перезапуск. Ручная проверка Windows 95 RTM/OSR2 остаётся нужна.

## Выполнено: перерисовка и двойной клик рабочего стола

Запрос: исправить двойной клик по свободному месту рабочего стола и кадры,
в которых исчезают значки/белые подписи, остаются только чёрные тени.

Реализовано:

- Пустой WM_LBUTTONDBLCLK поглощается в native ListView и desktop host.
- Фон, тени и штатные значки собираются в desktopFrame и выводятся одним кадром.
  Отдельный WM_ERASEBKGND сохраняет готовые пиксели; пустой/internal WM_PAINT
  не запускает повторный обход списка. Редактор имени защищён WS_CLIPCHILDREN.
- Paint откладывается во время native redraw hold, изменения элементов,
  вложенных shell/control callbacks и исходящего OLE drag. F5/refresh из таких
  callbacks объединяются и выполняются после возврата внешней операции.
- Отдельно найден сбой LV_RenameItem в Wine: неинициализированный iSubItem
  мешает LVM_SETITEMW заменить уже освобождённое item data, затем F5 вызывает
  повторное освобождение. Desktop data-only LVIF_PARAM update направляется
  основному элементу через локальную структуру. Данные остаются непрозрачными;
  владение Shell32, исходная структура и обычные subitem-запросы сохраняются.
- NativeView core проверяет готовый foreground+shadow, отдельный erase,
  частичный paint, resize, redraw hold, вложенный paint после LVN_DELETEITEM,
  refresh из shadow-pass и read-only callback и ANSI/Unicode item-data update.
  Все операции со значениями native списка не удаляют реальные файлы.
- В ShellNew fixture устранена гонка sharing modes между наблюдением за
  зарезервированным ярлыком и дочерним мастером. Проверки точных байтов сохранены.
  OLE fixture синхронизирует начальный порог drag и состояние модификаторов;
  реальные переносы, отмена, подтверждения и проверки файлов сохранены.

Проверены core, полный UI-прогон Wine 10 на 640×480, browser на 1024×768,
сборка x86/PE и кадры обоих размеров. Переносы, последующий F5, Delete и Корзина
прошли без прежнего повреждения native списка. Полный UI остаётся обязательным
перед публикацией: один успешный subset не заменяет его.

Дополнительно исправлены предпосылки UI-тестов: исходная позиция и всё движение
мыши идут через mouse_event, после layout проверяется LVHT_ONITEMICON, Tasks
закрывается отдельно в узком drag-fixture. New → Folder ждёт видимое подменю,
а выделение задаётся через память процесса приложения; проверка создания папки
сохранена. Это не отключает и не заменяет реальные операции файловой системы.

Следующий ручной шаг — проверить исходное видео на Windows 95 RTM/OSR2:
двойной клик по пустому месту, изменение размеров панели, выделение и перенос
значков, затем F5/Delete. Проверка Wine и списка импортов не подтверждает
поведение исходной Shell32 на настоящей системе.

Диагностические дампы остаются только в игнорируемом build/. Временный breakpoint
в Wine убран, исходная DLL восстановлена и сверена по SHA256. В исходниках нет
временных diag.* событий, отладочных задержек/барьеров или отключения trace.
Публикуемый Win95 EXE нельзя заменять тестовой x64-сборкой.

## Выполнено: предпосылка выделения в BrowserColorTests

В `tests/smoke.c` функция `BrowserColorTests` использует `NativeSelectItem`
с памятью целевого процесса вместо прямого `ListView_SetItemState`.
Тест требует непустой список и selected count == 1 до WM_SYSCOLORCHANGE,
затем проверяет сохранность количества элементов и того же количества выделений.
Сравнение двух нулей больше не допускает ложного успеха.
Browser-прогон Wine 10 на 640×480 прошёл для файловой папки и двух открытий
нативной Панели управления. Поведение приложения не менялось; новый EXE-релиз
для этой правки теста не требуется.
