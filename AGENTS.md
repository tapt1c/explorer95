# Инструкции для агентов Explorer95

## Область действия и цель проекта

Этот файл действует для всего репозитория `tapt1c/explorer95`.
Если в подкаталоге появится собственный `AGENTS.md`, учитывайте его дополнительные
инструкции при работе с этим подкаталогом. Явные инструкции пользователя имеют
приоритет над рекомендациями этого файла.

Explorer95 — любительская нативная оболочка для **Windows 95** с устройством
интерфейса в духе Windows XP: рабочий стол, панель задач, трей, Quick Launch,
двухколоночный «Пуск» и отдельные окна Проводника. Используется **классическое
оформление**. Luna, веб-интерфейс, Electron, .NET и современные движки тем
не входят в выбранную архитектуру.

Целевые системы — Windows 95 RTM/OSR2. Принимайте решения с учётом небольшого
объёма памяти, ограниченных USER/GDI-ресурсов и старых версий Shell32/Common Controls.
Сходство с XP не оправдывает зависимость, которая мешает запуску на чистой Win95.

Общайтесь с пользователем по-русски, если он не просит другой язык. Ключи строк интерфейса и большинство комментариев в исходниках написаны
по-английски. Пользователь явно запросил английский и русский интерфейс,
в том числе на английской Windows 95: поддерживайте оба языка через каталог,
не заменяйте ключи произвольным русским текстом в C-коде.

## Начало работы

1. Прочитайте `README.md`, этот файл, относящиеся к задаче исходники и проверки.
   При продолжении отложенных задач прочитайте [BACKLOG.md](BACKLOG.md).
2. Проверьте `git status --short`, текущую ветку и последние коммиты.
   Сохраняйте существующие изменения пользователя; не выполняйте сброс или очистку
   всего checkout ради удобства.
3. Пользуйтесь текущим checkout. Создавайте дополнительные worktree только по
   запросу пользователя. Не предполагайте, что локальная ветка называется `main`:
   облачная среда может использовать ветку `work`.
4. Определите, какие части затрагивает задача: Win95-бинарник, UI, INI-формат,
   установка оболочки, ресурсы или только документация.
5. Используйте `rg` и `rg --files` для поиска. Не включайте `build/` и `.git/`
   в широкое чтение исходников без необходимости.
6. Делайте изменения в рамках задачи. Не добавляйте крупные рефакторинги,
   зависимости или новые платформы без причины, связанной с запросом.

Для документации достаточно проверки содержания и diff. Изменение `AGENTS.md`
само по себе не требует пересборки EXE или нового релиза.

## Обязательные ограничения совместимости

- Основной результат — **32-битный x86/i386 PE32**, GUI subsystem/OS version **4.0**.
- Код приложения — C99 и ANSI Win32. Макросы сборки: `WINVER=0x0400`,
  `_WIN32_WINNT=0x0400`, `_WIN32_IE=0x0200`.
- Сборка freestanding, без CRT startup и runtime: `-nostdlib`, собственная точка
  входа `start`. Не добавляйте вызовы `malloc`, `printf`, `fopen` и других функций
  CRT, которые потребуют MSVCRT/UCRT. Используйте существующие Win32-обёртки.
- Сохраняйте `-march=i386` и текущие ограничения PE в `Makefile`.
  Не исправляйте несовместимость повышением минимальной версии Windows.
- Применяйте ANSI-варианты Win32 API там, где это требуется для Win95.
  Наличие объявления в новых заголовках MinGW не доказывает поддержку функции
  целевой системой.
- Не требуйте IE4, Active Desktop, XP Common Controls или новые shell-интерфейсы
  для базового рабочего стола и Проводника.
- Не применяйте `WS_EX_COMPOSITED`, `LVS_EX_DOUBLEBUFFER`, UxTheme/DWM и аналогичные
  современные механизмы как обязательный путь отрисовки.
- Перед добавлением импорта проверьте поддержку в Win95. Затем осознанно обновите
  `ALLOWED` в `tests/check_pe.py`, если API соответствует базовой системе.
  Не ослабляйте проверку ради успешной сборки.
- Если новая функция недоступна на Win95, используйте её только как необязательное
  расширение с `GetProcAddress` и полноценным запасным путём. Загружайте системную
  DLL по пути из системного каталога; не ищите её в текущем каталоге программы.
- Список разрешённых импортов — необходимая проверка, но не доказательство
  работоспособности на реальной Win95.
- `USER32.EndMenu` не экспортируется Windows 95: импорт в v0.7.0-alpha.1
  подтверждённо мешал загрузке на реальной системе. Для отмены TrackPopupMenu
  отправляйте владельцу меню `WM_CANCELMODE`, как рекомендует документация Microsoft.
  Не возвращайте EndMenu в ALLOWED; независимая регрессия проверяет этот отказ.

## Сборка

Все команды ниже выполняются из корня checkout.

Для основного EXE нужны GNU Make, Python 3, MinGW-w64 GCC для i686 и windres.
Пакеты Debian/Ubuntu: `gcc-mingw-w64-i686`, `binutils-mingw-w64-i686`.
Проверяйте установленные инструменты до установки новых пакетов.

```sh
make check

# Если установлен вариант компилятора с суффиксом -win32:
make check CC=i686-w64-mingw32-gcc-win32
```

Результат — `build/explorer95.exe`. `make check` собирает EXE, запускает быстрые
регрессии самого PE-проверяющего кода (`python3 -m unittest discover -s tests -p test_check_pe.py`)
и проверяет готовый файл через `python3 tests/check_pe.py build/explorer95.exe`.
`make all` выполняет только сборку и не заменяет проверку PE.

Если компилятор и binutils доступны по нестандартному пути, задавайте оба
инструмента. В подготовленной облачной среде могут существовать такие пути:

```sh
make check \
  CC=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-gcc-win32 \
  WINDRES=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-windres
```

Это локальное размещение инструментов, а не обязательная структура машины.
Сначала проверьте существование файлов. Не вшивайте этот абсолютный путь в Makefile,
CI или исходники приложения.

C-файлы компилируются отдельно с `-MMD -MP`: `build/obj32` и `build/obj64`.
Общие объекты приложения и теста переиспользуются в пределах одной архитектуры.
Файлы `.flags` отслеживают компилятор и флаги, не меняя mtime при повторном запуске.
Ресурсы находятся в `build/resources.o` и `build/ui64/resources.o`.
Не возвращайте общую компиляцию всех C-файлов одной командой. При добавлении исходника
обновляйте SOURCES / TEST_SOURCES; зависимости заголовков добавляются автоматически.
Изменение Makefile обоснованно пересобирает объекты. Используйте `make -j2 check`.
Опциональный `CCACHE=ccache` оборачивает только компиляцию, не windres и не линковку.
CI сохраняет ccache отдельно для x86/Ubuntu и x64/Debian; холодный кэш допустим.
`make check-build` проверяет отсутствие лишних пересборок и обновление при изменении
заголовков, C-файлов, флагов и BMP во временном каталоге.

`make clean` удаляет **весь `build/`**, включая диагностические логи и скачанные
релизы. Не используйте его, пока эти материалы нужны для проверки или сравнения.
Генерируемые EXE, объектные файлы, скриншоты и логи оставляйте вне Git.

## UI-проверки и их границы

Для изменения поведения оболочки, отрисовки, настроек или размещения контролов
запускайте относящиеся к изменению проверки. Предпочитайте расширение существующего
smoke-теста воспроизводимым сценарием регрессии. Не добавляйте тесты ради формального
покрытия простого обратимого изменения или повторения реализации.

Сначала выбирайте минимальную достаточную группу, не запускайте весь набор
на каждом промежуточном изменении:

- `make layout` — нативный расчёт геометрии, без Wine, MinGW и EXE оболочки.
  HOSTCC по умолчанию `cc`; test-only `tests/compat` нельзя включать в Win32-сборку.
- `make ui64-smoke TEST_GROUP=menu` — история, закрепления, настройки и геометрия
  «Пуска» в обоих режимах значков, без Проводника/трея/перезапуска.
- `make ui64-smoke TEST_GROUP=language` — каталог, ANSI-кириллица, собственные
  подписи/меню, реальные RU/EN Apply/Cancel и перезапуск на отдельном профиле.
  Не заменяет full перед релизом.
- `make ui64-smoke TEST_GROUP=browser` — файловый браузер и native-folder paint.
- `make ui64-smoke TEST_GROUP=core` — геометрия, флажок, история, временные
  INI, backend установки оболочки и контроллер расстановки значков на отдельном
  ListView. На Linux требуется Wine с дисплеем (например, Xvfb); само приложение
  не собирается и не запускается.
- `make ui64-smoke` — полный набор; это значение по умолчанию. Для x86 те же группы
  доступны через `make smoke`. Опечатка в группе должна приводить к ошибке.

Например, изменение ширины «Пуска» требует `make layout`, `make check`, группы
`menu` и визуальной проверки малого/крупного режима на 640×480 и большем экране.
Полный набор нужен при изменении общей инфраструктуры, жизненного цикла оболочки,
нескольких подсистем и перед релизом. После успешного прогона не повторяйте его
без новых изменений, ошибок или нерешённых вопросов.

Для хоста с рабочей поддержкой 32-битного Wine:

```sh
WINEPREFIX=/tmp/explorer95-wine32 WINEDEBUG=-all \
  xvfb-run -a make smoke WINE=wine
```

Если хост не исполняет 32-битные процессы, используйте отдельную x64-сборку исходников:

```sh
WINEPREFIX=/tmp/explorer95-wine64 WINEDEBUG=-all \
  xvfb-run -a make ui64-smoke WINE=wine
```

Для второго варианта нужны `gcc-mingw-w64-x86-64`, соответствующий windres,
Wine64, Xvfb и xauth. Если доступна только команда `wine64`, задайте `WINE=wine64`.
При нестандартном размещении инструментов переопределяйте `CC64` и `WINDRES64`.
Для извлечённого локального Wine также могут потребоваться `WINEDLLPATH` и другие
настройки его установки; не переносите их в продукт.

Для проверки небольшого экрана задавайте разрешение явно:

```sh
WINEPREFIX=/tmp/explorer95-wine640 WINEDEBUG=-all \
  xvfb-run -a -s '-screen 0 640x480x24' make ui64-smoke WINE=wine
```

- В CI UI-прогон закреплён на Debian 13/Wine 10, совпадающем с проверенной
  облачной средой; целевой x86 EXE собирается отдельно. Контейнер устанавливает
  зависимости от root и выполняет тесты от обычного пользователя. Wine 9 из
  Ubuntu 24.04 не проходил ограниченное ожидание выхода; не удаляйте проверки
  или сроки ожидания ради неподдерживаемой версии эмулятора.
- Используйте одноразовый Wine prefix. Explorer95 меняет рабочую область,
  регистрирует appbar/горячие клавиши и создаёт собственный рабочий стол.
- Не запускайте два UI-прогона одновременно в одном prefix и дисплее.
  Тест ожидает отсутствие другого экземпляра Explorer95.
- Тест создаёт временный профиль и файлы. Backend смены shell проверяется только
  на временных INI; не используйте настоящий `SYSTEM.INI` как тестовый fixture.
- Поток UI-теста использует оконные API. При ожидании выхода другого GUI-процесса
  используйте MsgWaitForMultipleObjects с обработкой сообщений, сохраняя срок
  ожидания: обычный WaitForSingleObject может блокировать встречные сообщения
  фокуса/параметров в старой Windows или Wine и давать ложное зависание.
- Лог должен содержать успешное завершение `Selected smoke group passed.`.
  Проверяйте код возврата; фоновый PID или отсутствие падения не означают успех.
- Сохраняйте сведения о первом падении. Разбирайтесь в причине, а не отключайте
  assert и не повторяйте прогон бесконечно до случайного успеха.
- Не используйте фиксированное число тестов как критерий корректности: набор меняется.
- `build/ui64/explorer95.exe` проверяет поведение исходников и **не предназначен
  для Windows 95**. В Releases должен попадать только `build/explorer95.exe`.
- Реальный Log Off, выключение, загрузка с заменённой оболочкой и межпроцессный
  обмен значками требуют отдельной проверки в целевой Windows 95 в ВМ.

Для визуальных изменений дополнительно осматривайте интерфейс при 640×480
и более высоком разрешении, в обычном и нажатом состоянии, с открытым меню
и перекрывающими окнами. Скриншот Wine полезен для поиска проблем, но цвета,
шрифты и системные значки могут отличаться от настоящей Win95.

### Полный UI-прогон и управление окнами

Для headless-проверок используйте `WINEPREFIX=/tmp/explorer95-ui sh tests/run_ui.sh`.
Скрипт запускает Xvfb и Openbox, ждёт готовности оконного менеджера и передаёт
аргументы существующему `make ui64-smoke` (например, `TEST_GROUP=browser WINE=wine64`).
В `tests/openbox.xml` отсутствуют горячие клавиши: Win/D/Ctrl+Esc должен получать Wine.
`EX95_TEST_SCREEN=1024x768x24` позволяет повторить проверку на большем экране;
по умолчанию используется 640×480. На обычном Linux-дисплее с оконным менеджером
можно вызывать исходные Make-цели напрямую.

Не используйте один Xvfb без оконного менеджера как доказательство корректности
активации и порядка окон: Win32 может считать окно скрытым, пока X11 ещё показывает
его, а topmost-флаг не гарантирует правильного видимого слоя. Не ослабляйте проверки
миниатюр, предпросмотров, desktop Z-order и затемнения ради прохождения такого прогона.
Проверки видимости должны обслуживать сообщения и ждать завершения смены фокуса
с ограниченным сроком, прежде чем вводить следующую клавишу.
- Для OLE-регрессий в Wine вводите модификатор после достижения цели и стабилизации
  X11 focus: переход между окнами может сбросить искусственный Ctrl/Shift в
  GetKeyboardState, хотя проверка GetAsyncKeyState перед переходом была успешной.
  Не добавляйте обходы в продукт: key-down после движения и key-up после drop.
  Во время ограниченного ожидания повторять key-down можно только при реально
  сброшенном состоянии; требуется устойчивое нажатие перед отпусканием мыши.
  Escape проверяйте без Ctrl, иначе зарегистрированный Ctrl+Esc
  открывает Start. Файловые assert и отмена должны оставаться обязательными.
Для fade сначала ограниченно дождитесь реально нарисованного светлого снимка:
IsWindowVisible может опережать отображение поверхности X11. Затем проверяйте
уменьшение яркости и конечный порог без принудительной перерисовки; отсутствие
светлого кадра должно оставаться ошибкой, а не превращаться в пропуск проверки.
- Перед первым Win key-down и после возврата из Start ждите устойчивого
  foreground/focus внешнего fixture и отпущенных Win-клавиш. Одного Sleep после
  SetForegroundWindow недостаточно: поздний X11 FocusIn сбрасывает удержание в Wine.
  Проверку запрета открытия Start до key-up сохраняйте без повторной инъекции.
  В full/browser сначала дождитесь открытия/активации стартовой папки `--open`
  и закройте её. Появление desktop child ещё не означает завершения startup queue;
  позднее окно папки перехватывает фокус у уже запущенного клавиатурного теста.

Wine хранит Unix-корзину через XDG_DATA_HOME вне prefix по умолчанию. Скрипт назначает
ей каталог внутри одноразового WINEPREFIX; иначе отдельный prefix не изолирует
чужие удалённые файлы. Сам тест по-прежнему подтверждает очистку только при наличии
единственного собственного fixture и отменяет её при любых посторонних объектах.

## Оформление, значки и геометрия «Пуска»

- Имя пользователя в шапке двухколоночного меню рисуется жирным вариантом
  env.host.font: сохраняйте размер и native charset. Это системное имя,
  не переводимый ключ каталога. Кэшируйте HFONT на время жизни Start,
  восстанавливайте прежний шрифт DC после рисования и освобождайте свой при teardown.
- Правая колонка: Documents / Recent / Favorites / Computer / Network;
  Control Panel / Printers / Command Prompt; Help / Find / Run. Между непустыми
  группами — 6px с etched-разделителем. Расчёт `CalculateStartLayoutGroups`
  учитывает эти отступы и More; старый `CalculateStartLayout` остаётся обёрткой.
  Не перенумеровывайте VisibleItems/FolderMenus: Favorites — бит12, Command — бит13,
  ItemsVersion=2 предотвращает повторное включение Command после скрытия.
- Собственные стрелки Start/Quick Launch/tray рисуются `PaintArrow`: проверенный
  GetTextFaceA Marlett (3/4/5/6), затем GDI-треугольник при отсутствии шрифта.
  Нативные TrackPopupMenu рисуют свои submenu arrows сами. Функция сохраняет DC,
  клиппинг и цвет; cached font освобождается в PaintShutdown.
- `Taskbar.TaskTiles` включает квадратные кнопки со значками и подсказкой названия;
  `GroupTasks` работает независимо. Используйте общую EnvPaintTaskTile в панели
  и preview. Не удаляйте текст HWND — он нужен подсказкам и доступности.
  Классические кнопки остаются вариантом по умолчанию, их ширина сохраняется
  при временном переходе к плиткам. Плитки используют крупные системные значки,
  высоту 44px на строку и стопку рамок у группы.
- GroupTasks объединяет окна по полному пути EXE, включая отдельные процессы
  сторонних программ. В Win95 Process32 даёт полный путь; NT использует проверенный
  главный модуль через Module32First. Сравнение без учёта регистра, с нормализацией
  DOS-пути; имя файла и класс окна не являются достаточной идентичностью.
  При отказе определения пути сохраняйте группировку только внутри известного PID.
  Снимки процессов/модулей выполняются при перестроении списка задач, а не на каждом
  неизменившемся тике. Перед TrackPopupMenu группы активируйте владельца env.bar;
  выбор должен активировать каждое окно, а не оставлять прежний foreground.

- Используйте системные цвета, шрифты, рамки и метрики. Избегайте жёстко заданных
  современных палитр и зависимости от темы Luna.
- Кнопка Start имеет классический минимальный размер 54×22 при стандартных метриках,
  жирный шрифт системных заголовков и расширяется под пользовательскую надпись.
  Не заменяйте его произвольным жирным шрифтом интерфейса.
  Явно пустой ButtonLabel разрешён: ширина 26px, флажок центрируется без текста.
  Отсутствующий ключ по-прежнему даёт Start. Не возвращайте fallback для пустой
  строки в загрузку, Validate или preview. HWND сохраняет имя Start для доступности,
  а EnvPaintStartButton рисует именно options.startLabel. Preview использует тот же код.
- Иконка EXE — именованный ресурс EXPLORER95 из resources/explorer95.ico:
  палитровые Win95 DIB 32×32/16×16 с AND-маской, без PNG внутри ICO и alpha-зависимости.
  PNG 32×32 — отдельный файл для использования вне EXE. Иконка входит в зависимости
  обоих windres-правил и в временное дерево tests/check_incremental.py.
- Флажок — исходный `resources/Bitmap143.bmp`, 16×16, ресурс `143`.
  Прозрачный цвет — **`RGB(192,192,192)`**. Сохраняйте исходные пиксели;
  bitmap встроен в EXE и не должен требовать файла рядом с программой.
- `PaintColorKey` использует TransparentBlt при наличии системной MSIMG32.DLL
  и GDI-маску в чистой Win95. Не добавляйте статический импорт MSIMG32.
  Проверяйте оба пути на цветном фоне: серый ключ должен исчезать,
  а чёрные и цветные пиксели флажка — сохраняться.
- При нажатии флажок и текст сдвигаются на один пиксель вместе. Кнопка остаётся
  визуально нажатой, пока открыт «Пуск», даже после перехода фокуса в меню.
- Произвольный текст Start, включая буквальный `&`, должен отображаться корректно.
- `Taskbar.LargeIcons` относится к Quick Launch; `Start.LargeIcons` — к «Пуску».
  Не объединяйте эти настройки.
- В крупном режиме загружайте крупный ресурс значка для основных кнопок «Пуска»:
  закреплений, недавних программ и системных команд. Не ограничивайтесь растягиванием 16×16.
  Во всех вложенных списках All Programs и Recent Documents, включая вложенные
  папки, значки всегда 16×16 с компактными строками. More / More pinned также компактны.
- Значки Exit / Log Off / Shut Down всегда 16×16 из малых системных ресурсов;
  высота нижней панели — 38 пикселей в обоих режимах значков.
- Номинальная ширина «Пуска» — 370 пикселей с малыми значками и 410 с крупными;
  используйте общий StartMenuWidth для расчёта размеров и привязки к правому краю.
- Системные значки Shell32 извлекайте по ID ресурса, когда он известен.
  Порядковые индексы могут обозначать разные картинки в разных версиях DLL.
- Геометрию основного меню вычисляйте через `CalculateStartLayout`.
  Учитывайте рабочую область, положение/размер панели, шрифт, размер значков,
  закрепления, недавние программы и видимые команды.
- Переполнение должно сокращать число видимых строк и использовать существующие
  More / More pinned для не поместившихся команд. Не обрезайте команды молча
  и не допускайте ухода меню за верхний край экрана.
- Изменение видимого числа недавних программ не должно удалять историю.

## Отрисовка и владение ресурсами

- Полноэкранный Desktop остаётся под приложениями: WM_WINDOWPOSCHANGING
  меняет hwndInsertAfter на HWND_BOTTOM до применения операции. Один обработчик
  WM_ACTIVATE не предотвращает временный подъём и не защищает от SWP_NOACTIVATE.
  После DefWindowProc для WM_ACTIVATE повторно закрепляйте Desktop внизу при
  получении и потере активации: native view может завершить подъём после ранней проверки.
  Не поднимайте Desktop через SetForegroundWindow ради TrackPopupMenu:
  владелец desktop-menu — env.bar, а NativeViewMenuMessage передаёт IContextMenu2
  только сообщения меню, не owner-drawn кнопок панели.
- Для нерепродуцируемого на Wine мерцания используйте --trace-render на целевой
  системе. Журнал выключен по умолчанию, ограничен 512 КиБ, не пишет названия
  файлов/окон/клавиши. Сохраняйте сообщения и HWND/clip/Z-order до и после сбоя;
  успешный Wine smoke не доказывает отсутствие временного перекрытия на Win95.
- Собственные поверхности панели, «Пуска» и пунктов меню рисуйте через существующие
  `PaintBuffer`/`PaintBufferBegin`/`PaintBufferEnd`. Формируйте законченное изображение
  перед копированием на экран; не возвращайте предварительное стирание фона.
- Сохраняйте `WS_CLIPCHILDREN` у файловых окон, native-frame, панели и «Пуска».
  Удаление этого стиля может снова привести к белым системным папкам, чьи значки
  появляются только после выделения мышью.
- Исключение — Environment Properties и Folder Options: у этих диалогов
  прозрачные внутренние области Win95 TabControl/BS_GROUPBOX. Их родитель должен
  закрашивать фон под контролами, поэтому у самих диалогов нет WS_CLIPCHILDREN.
  При смене страницы используйте RDW_ERASE | RDW_ALLCHILDREN; рамки групп и вкладок
  держите за полями. PaintDialogBackground исключает из стирания непрозрачные
  видимые контролы, сохраняя их готовые пиксели; tab/groupbox и скрытые поля
  исключать нельзя. SaveDC/RestoreDC должны сохранять исходный clip вызывающего.
  Не переносите это исключение на окна с IShellView.
- Предпросмотры настроек используют EnvPaintStartButton / EnvPaintTaskButton —
  те же функции, что настоящая панель. Сохраняйте натуральные размеры Start и
  значка 16×16; рисунок флажка без кнопки не заменяет предпросмотр панели.
- Начальный topmost-режим taskbar задаётся при CreateWindowEx до её Start/tooltip
  popup-окон. StartPosition меняет только геометрию (SWP_NOZORDER); показ и подъём
  Start завершаются с SWP_NOACTIVATE до отдельного SetForegroundWindow. Иначе
  вложенное скрытие при смене фокуса может быть отменено незавершённым показом.
- Сохраняйте корректное обновление всей иерархии shell view после открытия
  и изменения размера. Проверяйте первоначальное открытие, перерисовку только
  родителя, перекрытие другим окном, resize и повторное открытие папки.
- Кэш фона рабочего стола должен обновляться при изменении настроек/размера.
  Не оставляйте устаревшие обои или цвета после системного уведомления.
- Не рассылайте SPI_SETWORKAREA/ABM_SETPOS при неизменившейся рабочей области:
  Win95 Shell32 может перестроить все открытые системные папки. Видимость значков
  рабочего стола не требует полного EnvApplyOptions. WM_SETTINGCHANGE для
  рабочей области меняет размеры, а для обоев/цветов — фон без IShellView_Refresh.
- NativeViewResize пропускает только повторный неизменившийся layout. Первый
  проход и реальные изменения размеров сохраняют перерисовку всей иерархии;
  иначе на Win95 могут снова появиться белые окна до выделения значков.
- EnvMoveControl/EnvShowControl не трогают неизменившиеся контролы. Реальное
  перемещение использует SetWindowPos с SWP_NOCOPYBITS | SWP_NOZORDER |
  SWP_NOACTIVATE: прежнюю область уже мог перекрыть соседний контрол. Не возвращайте
  синхронный MoveWindow(TRUE) с копированием этих пикселей. NativeViewResize
  соблюдает то же правило. После перемещения viewport sidebar перерисовывает
  всю иерархию строк, даже если отдельные HWND сохранили размеры. TrayPrune
  сравнивает рассчитанную видимость с предыдущей, а не перестраивает панель
  на каждом тике при Hide inactive icons.
- WM_SYSCOLORCHANGE не должен вызывать BrowserBuildToolbar/BrowserFilesShow
  или полный layout: уничтожение HWND и повторное заполнение списка создают
  промежуточные пустые кадры и теряют выделение. Передавайте уведомление нативным
  дочерним контролам, сохраняя их HWND/данные. Не пропускайте доставку при прежних
  RGB: палитровые дисплеи Win95 могут требовать обновления stock bitmaps.
  PaintColors хранится отдельно для каждой поверхности; одинаковые значения
  не требуют перезагрузки обоев и повторной перерисовки всей рамки.
- При измерении переноса toolbar не рисуйте пробную высоту. Повторный layout
  с прежней шириной должен сохранять готовое изображение. Проверяйте сохранность
  HWND toolbar и выделения при WM_SYSCOLORCHANGE, а не только готовый скриншот.
- WM_ERASEBKGND рамки Browser не рисует весь фон в переданный чужой DC:
  это может стереть готовый toolbar на старой USER32. Рамку рисует WM_PAINT,
  подкласс toolbar закрашивает его собственный фон локально. Сохраняйте
  WS_CLIPSIBLINGS у соседних контролов и WS_CLIPCHILDREN у native view.
  Навигация приостанавливает redraw видимого Browser только на время фиксации
  уже подготовленной папки, затем рисует всю иерархию. Не показывайте этим
  механизмом ещё скрытое создаваемое окно. Высоту Go берите из реальной высоты
  ComboBox: CB_SETITEMHEIGHT(-1) задаёт содержимое, а не внешнюю рамку.
  BrowserBeginUpdate/BrowserEndUpdate в browser.c объединяют вложенные изменения
  навигации, панели и layout: только внешняя операция выключает redraw видимого
  Browser, а в конце синхронно обновляет всю иерархию. Не включайте redraw у окна,
  которое до операции было скрыто; неизменившийся layout возвращается до транзакции.
  Не оставляйте смену Tasks/Search/History/Folders с последовательной видимой
  перестановкой контролов: на Win95 это даёт пустые участки toolbar, панели и списка.
- Прокрутка Sidebar имеет собственную вложенную транзакцию redraw только для
  viewport: BeginSidebarUpdate/EndSidebarUpdate. Видимое окно сохраняет предыдущий
  кадр до завершения перестановки, затем RDW_ALLCHILDREN | RDW_UPDATENOW рисует
  дочерние строки до возврата из WM_VSCROLL/WM_MOUSEWHEEL. Одной invalidation
  недостаточно: модальный цикл nonclient scrollbar в Win95 может отложить
  WM_PAINT кнопок до отпускания мыши и оставить серые блоки. Не включайте redraw
  ранее скрытой панели и не перерисовывайте файловый список ради её прокрутки.
  ScrollTo меняет только origin содержимого и SIF_POS; измерение текста, размеры
  строк и диапазон скроллбара остаются в Reflow для изменений модели/геометрии.
  Перестройка/сворачивание Tasks входит в ту же транзакцию. В регрессии проверяйте
  видимые строки сразу после SB_THUMBTRACK без PumpFor/UpdateWindow, затем реальное
  перемещение ползунка с удерживаемой кнопкой мыши. Проверка только после её
  отпускания не воспроизводит этот сбой. Снимок сохраняется как
  build/browser-sidebar-tracking.bmp; Wine не заменяет повтор на реальной Win95.
- Wine кэширует GetSysColor по процессам: SetSysColors в smoke-процессе не
  гарантирует смену значений в другом процессе. Проверяйте реальную смену и
  восстановление PaintColors внутри одного процесса; HWND/данные — в интеграции.
- Не перерисовывайте неизменившиеся подписи, состояния и значки задач или часы
  на каждом тике таймера. При оптимизации сохраняйте обновление изменившихся значков.
- Буферизация собственных элементов не является композитором для чужих приложений.
  Не заявляйте, что Explorer95 управляет их отрисовкой под перекрывающими окнами.
- Балансируйте `GetDC`/`ReleaseDC`, `CreateCompatibleDC`/`DeleteDC`,
  создание и удаление bitmap/font/brush, а также COM `AddRef`/`Release`.
- Перед `DeleteObject` выбирайте прежний объект обратно в DC. Один bitmap нельзя
  одновременно выбирать в несколько DC; это относится и к тестам прозрачности.
- Не уничтожайте системные/shared-значки. Значки, полученные с передачей владения
  или через `CopyIcon`, освобождайте согласно соответствующему контракту.
- При subclassing сохраняйте и восстанавливайте исходную процедуру и свойства окна.
  Соблюдайте правила выделения/освобождения PIDL и shell-объектов.
- Сохраняйте работоспособный прямой путь рисования при нехватке памяти на буфер.

## Локализация английского и русского интерфейса

- `src/localization.c/.h` — граница локализации собственных контролов, меню,
  рисования и сообщений. Подключайте `EX95_LOCALIZE_UI` после системных заголовков;
  не распространяйте обёртки на файловый backend и непрозрачные Shell32-данные.
- `resources/translations/ru.json` содержит UTF-8 ключи EN → RU. Генератор
  `tools/generate_translations.py` создаёт игнорируемый `build/localization_strings.h`,
  сохраняет mtime при неизменном результате и добавляет варианты мнемоник/ellipsis.
  Сохраняйте параметры формата, порядок аргументов и клавиатурные сочетания.
- `[Interface] Language=en|ru` сохраняется общим Apply/Cancel. Новая вкладка
  Language имеет индекс 5, прежние индексы сохранены; используйте SETTINGS_PAGE_COUNT.
  Язык применяется после перезапуска, чтобы не смешивать состояния живых окон.
  Стандартное ASCII Start переводится при рисовании; пользовательская надпись
  хранится буквально и не заменяется русским значением в INI.
- При GetACP()==1251 русский интерфейс сохраняет исходные системные HFONT;
  встроенный шрифт не извлекается и не регистрируется. UiFont(NULL) при русском
  языке возвращает DEFAULT_GUI_FONT, а не NULL. На остальных кодовых страницах
  русский Win95-путь использует собственную CP1251-таблицу и встроенный
  Explorer95 UI 95 с SYMBOL_CHARSET и чистой cmap 3,0 F020–F0FF. Не полагайтесь на наличие
  системной CP1251 или русских шрифтов на английской Windows 95. NT Unicode-вызовы
  разрешаются только динамически и не являются импортами загрузчика. NFR_ANSI
  сохраняет договор уведомлений существующих ListView и редактора имени.
- Ключ кэша UiFont должен быть детерминированным: обнуляйте LOGFONT перед
  GetObjectA и хвост lfFaceName после NUL. Не сравнивайте неинициализированные
  байты: одинаковые запросы иначе занимают разные записи и приводят к смене
  семейства после заполнения кэша. Регрессия проверяет повторное использование
  HFONT и настоящий шрифт callback-tooltip.
- Подсказки TTN_NEEDTEXTA/W обходят обычные SetWindowText/TTM_ADDTOOL wrappers.
  UiTooltipText получает уже переведённый UiText либо буквальную native-подпись,
  выбирает соответствующий шрифт и возвращает правильный ANSI/Unicode буфер.
  Не переводите native-заголовки программ по случайному совпадению с ключом.
- В ProgramItem.localize отмечайте собственные подписи классического/More меню,
  All Users и Open this folder. Их измерение и рисование используют один UI-путь;
  имена файлов и пользовательские закрепления используют native-путь, даже при
  совпадении с английским ключом каталога.
- NT TTF, OFL-лицензия и Win95 TTF встроены ресурсами 202/203/204. Шрифт регистрируется через
  AddFontResourceA; Win9x использует CreateScalableFontResourceA(0, ...) и собственный .FOT
  с полным коротким путём к TTF, NT — прямой TTF. Удаляются только свои файлы
  после RemoveFontResourceA, закрытия окон и OLE. Не скрывайте FOT флагом 1:
  временное семейство должно быть доступно старому mapper, реестр не меняется.
  Не подставляйте голое имя TTF
  в FOT: GDI тогда ищет его в Windows/System вместо нашего временного каталога.
  Системные шрифты не меняются. Генерация требует fontTools только для
  сопровождения ресурсов; используйте tools/build_ui_font.py, исходный Liberation Sans
  и оба выходных пути из README. NT-версия сохраняет Unicode/symbol cmap и семейство
  Explorer95 UI; Win95-версия имеет отдельное Explorer95 UI 95, только cmap 3,0
  с U+F000+CP1251-byte, first/last F020/F0FF и Symbol code-page bit. Не возвращайте
  смешанную cmap и диапазон от 0020 в ресурс Win95: alpha.34 регистрировался,
  но не проходил проверку выбранного семейства/charset на настоящей Win95.
  Сохраняйте переименованные семейства и OS/2 version 1.
  Символьной cmap 3,0 должны соответствовать name records 3,0; одних Unicode
  записей 3,1 для старого GDI недостаточно.
- UiFont идемпотентен для уже выбранного собственного семейства. ControlFont
  не должен повторно отправлять WM_SETFONT с тем же шрифтом. Проводник задаёт
  окончательный шрифт toolbar до добавления кнопок; локализованный TB_ADDSTRING
  никогда не меняет шрифт заполненной панели. Старые Common Controls могут
  пересчитать общую ширину кнопок при каждом WM_SETFONT.
- Русские owner-draw меню используют PaintMenuCheck: системный DFC_MENU /
  DFCS_MENUCHECK в монохромной маске, раскрашенной цветами текущего пункта.
  Не возвращайте штрихи LineTo для галочек. Короткие UiMessageBox рассчитывают
  client size по тексту/иконке/кнопкам плюс реальную рамку AdjustWindowRectEx;
  не фиксируйте минимум 500×160. Для длинных сообщений оставляйте read-only EDIT
  с прокруткой. Проверки language сравнивают системный глиф, наблюдают WM_SETFONT
  настоящего toolbar после наполнения и проверяют короткое уведомление/лицензию.
- RenderTraceOpen вызывается после проверки уже запущенной копии, до UiInitialize.
  Не переносите открытие в EnvironmentCreate: оно потеряет этап отказа шрифта.
  font.* фиксируют ресурс, запись, FOT, регистрацию и реальную проверку семейства;
  сообщение ошибки сообщает stage и код (0 — нет расширенной ошибки).
  font.face.selected записывает только имя нашего выбранного GDI-шрифта, charset
  и tmPitchAndFamily; не добавляйте в этот журнал пользовательские подписи/пути.
- Собственный перевод native caption применяется только при полном совпадении
  `(style & WS_CAPTION) == WS_CAPTION` и отсутствии WS_CHILD. WS_CAPTION состоит
  из WS_BORDER и WS_DLGFRAME: проверка любого одного бита ошибочно рисовала серую
  полосу «Пуск» поверх шапки меню при активации Win95. И сохранение titleProperty,
  и Caption проверяют текущий стиль; после удаления caption очищайте старые данные.
  LanguageCaptionStyleTest проверяет реальные WS_BORDER/WS_DLGFRAME/WS_CAPTION
  окна, сохранность пикселей клиентской шапки и изменение стиля; LanguageRestartTests
  дополнительно проверяет отсутствие ложного caption у запущенного русского Start.
- Не переводите имена файлов, пути, пользовательские подписи, чужие заголовки
  и private item data. Для них есть UiSetLiteralWindowTextA, UiDrawNativeTextA,
  UiGetNativeTextExtentA. GetWindowText чужого процесса не должен читать наши
  внутрипроцессные свойства. NULL, integer resources, LPSTR_TEXTCALLBACK и
  owner-draw данные контролов нельзя разыменовывать как строки.
- Собственные русские меню используют различимые owner-draw tokens; чужие
  shell-меню сохраняют обработчики. GetMenuItemInfoA требует исходный Win95
  размер MENUITEMINFO без более позднего hbmpItem. Собственные диалоги сообщений
  нужны для кириллицы/кнопок, системные Shell32-диалоги остаются языком Windows.
- `tests/test_localization.py` проверяет каталог/форматы, детерминизм генератора,
  TrueType cmap/семейство/лицензию. `tests/localization_cases.h` проверяет настоящие
  символы ANSI DrawTextA на английском locale, подписи, мнемоники, имя Copy,
  переименование и сохранение/перезапуск языка. Отдельный тест принудительно
  выбирает настоящий FOT backend на Wine, проверяет доступность семейства для
  mapper и рисунок ANSI-символов против отдельного Unicode-шрифта, удаление
  обоих собственных файлов и реальный отказ временного каталога. Копия EXE в
  собственном fixture проверяет порядок font.* до exit.done, не затирая чужой лог.
  Не называйте Wine доказательством
  работы на Win95: оба языка ОС и native caption требуют целевой проверки в ВМ.

## Настройки, история и закрепления

Настройки по умолчанию находятся в `Explorer95\Explorer95.ini` под каталогом
данных пользователя, который возвращает Shell32. Для ручных проверок используйте
отдельный существующий каталог и аргумент:

```text
explorer95.exe --settings="C:\EX95TEST\Explorer95.ini"
```

- Основные секции: `[Taskbar]`, `[Start]`, `[Desktop]`, `[Pinned]`, `[Recent]`,
  `[TrayPolicies]`, `[SeenShortcuts]`. При записи сохраняйте неизвестные поля
  и отдельные `[Explorer]` / `[ExplorerFavorites]`.
  Сохраняйте совместимость существующих профилей и разумные defaults отсутствующих ключей.
- Закрепления хранятся отдельно от истории. Текущие пределы: 6 закреплений,
  30 записей истории и 64 учитываемых окна; константы находятся в `shell_internal.h`.
  При изменении пределов проверяйте массивы, диапазоны ID команд и тесты.
- В `[Recent]` используется `Format=2`; префикс `!` у сохранённых аргументов
  защищает внешние кавычки от обработки INI API. Закрепления также сохраняют
  аргументы с префиксом. Не убирайте кодирование без совместимого чтения старых файлов.
- Сохраняйте пути и аргументы раздельно. Пути с пробелами и один полностью
  заключённый в кавычки аргумент должны переживать сохранение и перезапуск без изменений.
- Запуск недавней или закреплённой программы должен использовать её аргументы.
  Контекстное закрепление не должно терять параметры запуска.
- Закреплённая команда не дублируется в видимом списке недавних; разделитель
  показывается при наличии обеих групп. Очистка истории не удаляет закрепления.
- Настройки редактируют черновик: OK сохраняет, Cancel отменяет. Не теряйте проверку
  версии списка, защищающую от перезаписи контекстных изменений устаревшим редактором.
- Ограничение Recent programs должно рассчитываться для выбранного размера значков
  и текущего черновика закреплений до сохранения. Учитывайте также ещё не применённые
  edge/rows/large Quick Launch icons из вкладки Taskbar через StartMaximumRecentOptions
  и общий EnvBarThickness. Не меняйте глобальные options ради предварительного расчёта.
- В историю программ не попадают документы, ярлыки на документы/папки и объекты
  из каталога Recent Documents. Проверяйте цель .lnk через IsProgramHistoryEntry,
  не считайте любой ярлык программой. Не вызывайте интерактивный Resolve.
  Существующие не подходящие записи удаляются с сохранением порядка и аргументов программ.
- История фиксирует запуски через Explorer95. Не описывайте её как глобальный
  мониторинг всех запускаемых в системе процессов.
  Левые recent rows ограничены программами из CSIDL_PROGRAMS/CSIDL_COMMON_PROGRAMS,
  включая подпапки с той же глубиной и hidden/system-политикой, что All Programs.
  FindProgramHistoryShortcuts сопоставляет цели EXE/COM/BAT/PIF и .lnk одним обходом
  для всей истории; GetShortPathNameA из базовой Win95 уравнивает DOS/long пути.
  Запуск может происходить через Run, Quick Launch или другую папку. Подпись/значок
  берутся из найденного пункта Programs, исходные path/arguments сохраняются.
  Совпавшие recent rows не дублируются. Неподходящие старые программные записи
  скрываются, а не удаляются из INI при временном отсутствии ярлыка. Новые запуски
  без соответствия не занимают историю. Не создавайте индекс всех дисков и не
  вызывайте интерактивный Resolve; меню перечитывает соответствия при открытии.
  UI-тест создаёт/удаляет только свой уникальный .lnk в Programs изолированного
  тестового пользователя; остальные регистрации меню программ не меняются.

## Общее окно настроек окружения

- `Explorer95.Properties` — единственное окно: Taskbar / Start Menu / Desktop /
  Notifications / System Shell. General / Advanced / Pinned programs — внутренние
  вкладки Start Menu. Не возвращайте отдельное окно `Explorer95.StartSettings`.
  Параметры файлового Проводника остаются в его собственном окне.
- Общие OK / Cancel / Apply работают со всем черновиком. Clear program list и
  Clear recent documents только отмечают очистку до успешного Apply. После Apply
  окно остаётся открытым, а Cancel не отменяет уже применённое.
- Сначала проверьте все поля и pinsVersion, затем запишите копию INI в уникальный
  временный файл. Перенос оригинала в резерв и замена используют Win95 MoveFileA;
  не добавляйте неподдерживаемые MoveFileEx / ReplaceFile. При сбое восстановления
  сохраняйте резерв и сообщайте его путь. Не меняйте живые options/pins/policies
  до успешной записи; read-only профиль должен остаться неизменным.
- Вкладки — штатный Win95 TabControl. Все элементы принадлежат одному окну;
  SettingsControl хранит их страницу/подстраницу. Фоновые tab/groupbox располагаются
  позади полей, с WS_CLIPSIBLINGS, иначе подстраницы могут исчезать при перерисовке.
  У анонимных подписей уникальные ID: не используйте IDOK/IDCANCEL для groupbox.
- Нужны работоспособные Ctrl+Tab, Escape, обычный Tab и окно целиком на 640×480.
  В UI-тестах переключайте вкладки через TCM_SETCURFOCUS. Нельзя передавать указатель
  на NMHDR в WM_NOTIFY из другого процесса: это не поддерживаемая межпроцессная передача.
- Во время Apply SPI work-area broadcast приходит до фактического перемещения
  панели. Не пересчитывайте лимиты по промежуточной геометрии при loading=true.
- В классическом стиле реальные Win95 popup menus, всегда 16×16. Специфические
  для двух колонок size/recent-count/hover/drop отключены, а их значения сохраняются
  для возврата. Все раскрывающиеся списки в любом стиле остаются с 16×16.
- FolderMenus использует те же биты, что VisibleItems; Favorites — бит 12,
  прежние индексы остальных команд не меняйте. My Computer menu получает буквы
  через GetLogicalDriveStrings, без чтения меток/типов/содержимого накопителей.
  Namespace-элементы владеют своими PIDL и вызывают стандартную команду IContextMenu.
- Internet / E-mail — обычные элементы общего массива pins с Client=1/2, максимум
  по одному каждого вида и в общем пределе шести. Не меняйте системные ассоциации.
  Значение Client=0 по умолчанию сохраняет совместимость старых INI и context pin.
- Подсветка относится к новым файлам ярлыков после сохранённого Epoch, с ограниченным
  кольцом 64 открытых путей. Не описывайте её как мониторинг установки программ.
- TrayPolicies сопоставляются по basename процесса + классу окна + ID уведомления,
  не по HWND/PID или меняющейся подсказке. Toolhelp32 — API оригинальной Win95;
  снимок делается при регистрации значка, не на каждом тике/движении мыши.
  При Apply объединяйте черновик с новыми уведомлениями, появившимися после открытия.
  Always hide должен оставлять доступ через `>` даже при выключенном Hide inactive.
  Режимы: 0 inactive / 1 always show / 2 always hide; таймаут 5–3600 секунд.
- Проверяйте общий Cancel, Apply без закрытия, ошибку записи, сохранность Explorer
  section, pending taskbar geometry, стили/hover/клиенты, desktop visibility и tray policies.
  Саму загрузку shell/выход Windows, реальную drag-and-drop совместимость и работу
  на Windows 95 дополнительно проверяют в ВМ; Wine не заменяет эту проверку.

## Расстановка значков рабочего стола

- Пустой WM_LBUTTONDBLCLK в desktop ListView поглощается до исходной процедуры
  Shell32: нельзя передавать его как активацию прежнего выделения/desktop owner.
  Обычный выбор, rectangle selection, двойной клик по значку и Enter остаются
  штатными. Проверка в NativeViewMessageTests наблюдает реальные NM_DBLCLK,
  foreground+shadow, отдельный erase без PumpFor и resize с RDW_ERASENOW.

- Рабочий стол остаётся системным `IShellView`. `native_view` связывает его ListView
  с `DesktopIcons`, а `desktop_icons` отвечает за перенос, сетку и файл позиций.
  Не переносите эту логику в файловый Проводник и не заменяйте системные значки
  собственным списком файлов: должны сохраниться виртуальные объекты Shell32.
  `[Desktop] IconSize` выбирает 32 или 48, default/16/неверное значение — 32;
  настройка независима от Start/Quick Launch/tray. Desktop page и Icon Layout →
  Icon Size используют один параметр, Apply/Cancel и общий preview.
  NativeViewConfigureDesktop принимает размер последним аргументом. Для 32px
  NORMAL использует исходный системный список; для 48px NativeView владеет
  отдельным ImageList 48×48 с теми же индексами. PaintScaleIcon читает XOR/AND
  в исходном размере, затем выбирает для цвета и маски один и тот же исходный
  пиксель. В AddIcon/ReplaceIcon поступает уже настоящий HICON 48×48: не поручайте
  старой Comctl32 увеличение 32px-значка. Общие списки нельзя изменять
  или уничтожать. Копия дополняется при росте source list и обновляется после
  F5/LVM_UPDATE/замены native NORMAL. Ограничение — 4096 системных изображений.
  У исходной Win95 нет публичного запроса overlay mappings. PaintDesktopOverlays
  получает composite HICON из исходного списка с реальным LVIS_OVERLAYMASK и
  выводит его в тот же buffered frame, учитывая selection/cut. Composite уже
  содержит основной значок: перед его выводом восстанавливайте исходные обои
  в пределах LVIR_ICON, сохраняя внешний clip и native-подпись. Иначе при
  различии размещения основного и составного изображения на Win95 значок двоится.
  Используйте кэшированный PaintBackground, а не заливку сплошным цветом. Нельзя терять
  стрелки ярлыков или вводить зависимость от ImageList_GetOverlayImage/IE4.
  LVIR_ICON у старого ListView может включать поля выделения (8px слева/справа,
  2px сверху/снизу). Не используйте его левый верхний край как начало изображения
  и его размер как размер ghost: PaintListIconRect центрирует фактический размер
  NORMAL image list внутри этих bounds. NativePaddedIconProc в регрессии меняет
  только ответ LVIR_ICON, оставляя исходную отрисовку и позиции без изменения;
  ожидаемые пиксели берутся из исходного control без этого shim.
  DesktopIconsSetSourceImages передаёт заимствованный исходный список для ghost:
  при 48px его composite сначала проходит PaintScaleIcon, затем рисуется
  DrawIconEx в фактических размерах LVIR_ICON без дополнительного увеличения.
  Сохраняйте native handle при LVM_SETIMAGELIST из Shell32, включая F5, и возвращайте
  Shell32 прежний native handle вместо своей копии. Перед teardown восстанавливайте
  NORMAL и исходный LVS_SHAREIMAGELISTS; свои 48px списки освобождайте отдельно.
  LVM_SETIMAGELIST входит в desktopMutationDepth. При смене размера контроллер
  раскладки удерживает redraw и восстанавливает позиции существующим refresh-путём.
  Snap/Grid центрируется по ширине активного image list, не всегда SM_CXICON.
  То же правило действует в TryCell при поиске места для вытесненного соседа.
  В grid-режиме FitPlacement не сдвигает точку к краю длинной подписи: либо
  вся ячейка помещается, либо ищется другая целая ячейка. DragDelta у края
  также ограничивает перенос целыми шагами сетки. Restore при SnapToGrid
  нормализует новые и сохранённые точки, включая старые смещения от прежнего
  label-clamp; свободный режим сохраняет произвольные координаты.
  ResolvePositions принимает явный grid: Line up использует TRUE независимо
  от переключателя Snap, остальные операции — текущее значение SnapToGrid.
  Для grid-плана ItemBounds измеряет фактический значок и текст штатным шрифтом
  через DrawText(DT_CALCRECT), ограничивая текст native LVIR_LABEL. Не резервируйте
  пустую часть LVIR_BOUNDS как видимую подпись: старый control может выделять
  ячейку шире/выше выбранного шага. Сам foreground остаётся нативным.
  Свободный режим сохраняет полные native bounds. Регрессия grid проверяет
  реальные icon/label hit tests и итоговый кадр после native paint, а не запрет
  пересечения пустых частей LVIR_BOUNDS.
  В тестах дождитесь DesktopIcons restoration (DesktopPump), после F5 находите
  объект по имени: Shell32 может поменять индекс. Чужой HIMAGELIST нельзя передавать
  ImageList API из smoke-процесса; читайте LVIR_ICON через память приложения.
  NativeDesktopOverlay48Test использует только свой временный source list,
  восстанавливает исходные изображения/состояние и сравнивает buffered результат
  с независимо нарисованным системным composite, включая прозрачные углы.
  Дополнительно заменяет только собственную 48px-копию непрозрачной canary-иконкой:
  под прозрачными пикселями composite не должно оставаться ни одного её пикселя.
  Одной проверки сходства более 90% недостаточно — она пропускала второй силуэт.
  ImageList_Remove/GetIconSize/ReplaceIcon — API исходной Comctl32 4.0/Win95.
- Подписи desktop остаются текстом системного ListView. Desktop WM_ERASEBKGND
  только возвращает TRUE: он не должен стирать готовые значки или оставлять
  на экране один фон с тенями до следующего WM_PAINT. В WM_PAINT NativeView
  собирает фон, PaintDesktopLabelShadows и штатный foreground через исходную
  процедуру WM_PRINTCLIENT в сохраняемом desktopFrame, затем копирует только
  invalidated-область. Обычная Win95 GDI рисует чёрную тень до штатного белого текста.
  Прямой путь при нехватке буфера сохраняется; память кадра освобождается при
  уничтожении view. WM_PAINT с переданным HDC не запускает новый BeginPaint.
  Перед печатью проверяйте GetUpdateRect: пустой/internal WM_PAINT не должен
  повторно обходить Shell32. Вложенный/удержанный paint валидируется через
  ValidateRect без рекурсивного BeginPaint. Оба API входят в USER32 Win95;
  их явное разрешение в PE-проверке не меняет минимальную версию системы.
  Не вызывайте штатное рисование во время WM_SETREDRAW(FALSE), изменения
  элементов/сортировки/геометрии native ListView или внутри native callbacks.
  Собственный OLE source из контроллера расстановки допускает рисование стабильных
  элементов: DesktopFileDrag запоминает глубину внешнего вызова контроллера,
  когда native callbacks уже вернулись, перед DoDragDrop. DesktopPaintBusy запрещает рисование при любой новой вложенной
  глубине, mutation, refresh или активном кадре; не обнуляйте desktopCallDepth.
  Сам refresh остаётся отложенным на всё время исходящего OLE drag.
  Shell32 может уже освободить PIDL в LVN_DELETEITEM, пока Common Controls
  ещё держит запись. desktopMutationDepth и desktopFramePending откладывают
  кадр до возврата исходной процедуры; завершение drag тоже инвалидирует
  отложенный кадр, в том числе после отмены. Нельзя обходить это через
  безусловный WM_PRINTCLIENT, который не всегда учитывает native redraw hold.
  Canary в NativeDesktopPaintTests вызывает вложенную перерисовку после
  штатного LVN_DELETEITEM и проверяет сохранность прежнего кадра; он удаляет
  только элемент временного view, не файл. Интеграционный browser/full
  дополнительно проверяет desktop drag, следующий F5, Delete и Корзину.
  Защита двусторонняя: NativeViewRefresh тоже не должен очищать native список
  из активного кадра, изменения элементов, текущего refresh или исходящего OLE
  drag. desktopCallDepth дополнительно охватывает исходные процедуры view/list
  и контроллер раскладки: даже read-only LVM_GETITEMTEXT держит указатели native
  элементов через callback владельца. Нельзя очищать список до его возврата.
  desktopRefreshPending объединяет запросы; ResumeDesktop ставит одно
  DESKTOP_REFRESH_MESSAGE в очередь только после выхода из внешней операции.
  Не перепосылайте сообщение из занятого callback: вложенный COM message pump
  может зациклить такую очередь. paintingDesktop охватывает BeginPaint/EndPaint;
  desktopRefreshing устанавливается до DesktopIconsBeginRefresh/Capture.
  NativeDesktopRefreshPaintTest проверяет пустой paint, два refresh из WM_GETFONT
  shadow-pass и из LVN_GETDISPINFO при отдельном чтении текста. Очистка должна
  происходить один раз после внешнего вызова, сохраняя его возвращаемый текст.
  Для --trace-render есть этапы desktop.refresh.defer и desktop.refresh.begin;
  формат заголовка журнала не меняется.
  Отдельная причина повреждения после desktop move — LV_RenameItem в Wine:
  старое item data освобождается до LVM_SETITEMW с неинициализированным iSubItem.
  Данные LVIF_PARAM принадлежат основному элементу. Для desktop data-only
  LVM_SETITEMA/W NativeView передаёт локальную структуру с iSubItem=0, сохраняя
  исходную структуру вызывающего кода и непрозрачное значение lParam.
  Не интерпретируйте/освобождайте его как PIDL и не подменяйте shell notifications.
  Смешанные маски и нормальные subitem-текст/изображения остаются штатными.
  NativeDesktopItemDataTest воспроизводит такой update на настоящем control
  для ANSI/Unicode с положительным/отрицательным subitem; заимствованные значения
  обязательно восстанавливаются до message pump и уничтожения view.
  WS_CLIPCHILDREN у desktop ListView защищает нативный редактор имени. Не требуйте NM_CUSTOMDRAW
  или DrawShadowText из более новых Common Controls и не накладывайте собственный
  белый текст поверх готовых native glyphs. Выделенные подписи пропускаются,
  изменение LVIS_SELECTED инвалидирует только их LVIR_LABEL с erase.
  PaintTextShadow ограничен исходным LVIR_LABEL, сохраняет DC/clip/color/font
  и не меняет кэш обоев. Та же тень используется в прозрачном образе drag.
  ApplyPlan после смены координат инвалидирует старый и новый LVIR_BOUNDS,
  без UpdateWindow внутри цикла и без полного desktop Refresh: CLR_NONE
  ListView может иначе оставить старые пиксели текста. Проверки светлого фона,
  native highlight, deselection и очистки только label-footprint — в PaintTests.
- `Desktop.ShowIcons` скрывает представление, сохраняя обои и сам view. Desktop
  parent использует существующий PaintBuffer фона. Не пересоздавайте view ради
  скрытия значков, изменения сетки или применения параметров.
- Параметры `[Desktop]`: `AutoArrange=0`, `LockIcons=0`, `SnapToGrid=0`,
  `GridWidth=80`, `GridHeight=80` по умолчанию; оба шага ограничены 64–200 пикселями.
  Старый профиль сохраняет явно заданный AutoArrange. Для нового профиля не
  наследуйте LVS_AUTOARRANGE штатной оболочки: он мешает ручной расстановке.
- Все параметры расположения доступны через Desktop общих настроек и Icon Layout
  контекстного меню. Меню применяет изменения сразу; вкладка использует общий
  черновик Apply/OK/Cancel. `PropertiesDesktopLayoutChanged` синхронизирует поля
  открытого окна после команд меню, сохраняя черновики остальных страниц.
  Не создавайте отдельное окно параметров рабочего стола.
- Изменение шага само не переставляет значки. Line up Icons Now — немедленная
  уплотнение по уже применённой сетке с сохранением текущего визуального порядка,
  без сортировки объектов Shell32. Курсор поиска ячейки идёт только вперёд,
  чтобы поздний короткий элемент не обгонял ранний длинный. GridPoint исходных
  точек и размер image list вычисляются до цикла размещения, не в каждом сравнении.
  Auto Arrange использует штатное расстояние Windows. При LockIcons команда
  Line up не меняет позиции. `desk.cpl` и смена boot shell остаются отдельными действиями.
- Обычный `LVN_BEGINDRAG` перемещает выделенную группу с сохранением взаимного
  расположения. Модификаторы Ctrl/Shift/Alt и правый drag передаются Shell32 для
  файловых операций. LockIcons запрещает начало обоих типов drag, сохраняя
  выделение, открытие объектов и контекстные меню.
- `SetCapture`/`ReleaseCapture` ограничены временем переноса. Escape, правый щелчок,
  WM_CANCELMODE и потеря capture восстанавливают исходные позиции всей группы.
  Перед изменением состава списка отменяйте drag: сохранённые индексы перестают
  обозначать прежние объекты. При уничтожении контроллера отменяйте перенос,
  снимайте таймер и освобождайте память до уничтожения ListView.
- Сетка использует базовый `LVM_SETITEMPOSITION`: LVM_SETICONSPACING и
  LVS_EX_SNAPTOGRID требуют более новых Common Controls и не являются базой Win95.
  Во время движения меняется только образ перетаскивания, реальные координаты
  остаются исходными. Применяйте сетку при отпускании, по значку, за который
  захватили группу. Не перечитывайте папку, не записывайте файл раскладки и не
  перерисовывайте весь рабочий стол на каждом событии мыши.
- Образ создаётся один раз из штатного image list и шрифта ListView, с отдельной
  монохромной маской прозрачности 50%. Сохраняйте пиксели значков, overlay ярлыков
  и подписи без прямоугольника выделения. LVM_CREATEDRAGIMAGE на CLR_NONE может
  захватывать непрозрачный фон: наличие HIMAGELIST само по себе не проверка вида.
  Используйте исходные ImageList_BeginDrag/DragEnter/DragMove/DragLeave/EndDrag
  Win95, без AlphaBlend/layered окон. Временные GDI-размеры ограничены; при большой
  группе допустим образ захваченного значка, при нехватке ресурсов — курсор переноса.
- Снимайте образ и освобождайте его saved bits до изменения настоящих позиций,
  в том числе при отмене, потере capture и уничтожении view. Восстанавливайте
  выбранные GDI-объекты перед удалением bitmap/brush/DC; не меняйте и не удаляйте
  разделяемый image list Shell32. Каждый BeginDrag имеет соответствующий EndDrag.
- Размещение рассчитывается целиком до применения: целевые позиции группы
  резервируются первыми, незатронутые соседи сохраняют свои места, пересекающиеся
  получают свободные позиции. Учитывайте полные прямоугольники вместе с подписями;
  касание границ допустимо. Группа сохраняет относительное расположение.
  При отсутствии места отменяйте весь перенос, без частичного сдвига соседей и
  записи в DIP. Line up и восстановление старой раскладки тоже разделяют наложения,
  когда места достаточно; не создавайте новую стопку привязкой к одной клетке.
- Изменения состава/размеров списка объединяются отложенным восстановлением
  через `DesktopIconsChanged`, без постоянного опроса Shell32. Пока `pending`
  установлен или первое восстановление не завершено, не сохраняйте неполный
  снимок вместо полной раскладки. Успешный возврат `DesktopIconsSave` может
  означать отложенную запись, а не появление файла на диске.
- Явный F5 / Refresh Desktop обрамляйте DesktopIconsBeginRefresh / EndRefresh.
  Пока Shell32 перечисляет объекты и ожидается восстановление, не показывайте
  промежуточные позиции: контроллер удерживает WM_SETREDRAW и paint/erase.
  Перед возвратом координат включайте внутреннюю отрисовку ListView и завершайте
  отложенное измерение через WM_PRINTCLIENT в memory DC; первый настоящий paint
  иначе может снова расставить новые элементы. Затем разрешайте перерисовку.
  Повторный F5 не должен захватывать неполную раскладку; F5 не требует записи DIP.
  При уничтожении контроллера и ошибке таймера снимайте удержание отрисовки.
- При восстановлении учитывайте возможное повторное включение LVS_AUTOARRANGE
  самой Shell32. Ручной режим должен оставаться ручным после F5. При уменьшении
  рабочей области ограничивайте позиции с учётом полного прямоугольника значка
  и подписи, чтобы значки оставались доступны.
- Координаты лежат в `<полный путь INI>.DIP`, например `Explorer95.ini.DIP`.
  Не вычисляйте имя от EXE: у каждого `--settings` свой файл. Резервное копирование
  профиля включает INI и DIP; сброс раскладки — удаление только DIP после выхода.
  Сам Explorer95 не записывает координаты в реестр штатного Explorer.
- Текущий двоичный формат: три DWORD (magic `0x50443945`, версия `1`, число записей),
  затем до 1024 записей `char name[MAX_PATH]` и два LONG для x/y. Не добавляйте
  указатели, HWND или зависящие от разрядности поля. Проверяйте размер, версию,
  число записей, терминаторы и допустимые координаты до восстановления.
  Изменение формата требует версии и обработки прежних сохранённых раскладок.
- Позиции сопоставляются по полным подписям, не индексам; одинаковые подписи —
  по очереди. Не используйте внутренний LVITEM.lParam Shell32 как PIDL.
  Учитывайте ограничения подписей при переименовании и смене языка; не обещайте
  стабильную идентичность объекта по этому ключу. Новым файлам не назначаются
  записи удалённых объектов только из-за совпадения индекса.
- Записывайте через уникальный временный файл, закрытие handle и MoveFile с
  резервом/восстановлением прежней копии. Не заменяйте полный файл усечённым при
  превышении лимита и не перезаписывайте read-only файл. При провале восстановления
  оставляйте резерв и сообщайте путь; ошибка сохранения не должна отменять
  работающую текущую расстановку или повреждать INI.

Для правок самого контроллера сначала используйте `make check` и группу `core`.
`tests/desktop_icons_cases.h` проверяет реальный ListView в одном процессе:
перенос группы, отмену, capture, блокировку, сетку, read-only файл, восстановление
при другом порядке перечисления, неполное обновление и уменьшение рабочей области.
Образ проверяется по прозрачной маске и движению на один пиксель при включённой
сетке; реальные значки до отпускания остаются неподвижными. Для размещения нужны
сценарии занятого места, сохранности незатронутых соседей, полного отказа при
нехватке места, Line up и восстановления старых наложений.
Интеграция контекстного меню, Apply/Cancel и открытого окна настроек проверяется
в `tests/smoke.c`. Изменения в native_view/settings/environment требуют также
соответствующих интеграционных сценариев; общий жизненный цикл и релиз — full.
Проверка контроллера не заменяет настоящий ввод мыши в системном desktop view.
На целевой Win95 дополнительно проверяйте перенос одиночного значка и группы,
системные drag-операции с модификаторами, F5 и перезапуск с тем же профилем.

## Проводник и совместимость файловых операций

- Файловый Drag and Drop находится в `file_drag`, `browser_files` и `native_view`.
  Используйте штатные IDataObject / IDropTarget / DoDragDrop (Win95 OLE).
  Файловые цели используют ShellFilesPerform / SHFileOperationA совместно
  с clipboard; LINK использует IShellLinkA с уникальным именем без перезаписи.
  Правый drag предлагает Copy / Move / Link / Cancel в TrackPopupMenu.
  Не удаляйте исходники повторно в IDropSource после успешного MOVE.
- В DragEnter валидируйте размер, смещения, двойной NUL и число CF_HDROP-путей,
  конвертацию Unicode в ANSI; снимок путей живёт до Drop/Leave. DragOver работает
  по кэшированным данным текущей папки; не перечисляйте другие диски/сеть.
  Виртуальные цели рабочего стола сохраняют native IDropTarget из IShellView;
  собственный target регистрируется только на child ListView.
  Shell32 Win95 может заранее зарегистрировать и сам child ListView.
  FileDropRegister обрабатывает DRAGDROP_E_ALREADYREGISTERED только при наличии
  сохранённого native fallback этого собственного view: снимает его регистрацию
  и ставит собственный target, продолжая делегировать виртуальные цели native.
  При ошибке повторной регистрации восстанавливает fallback; без fallback
  существующая регистрация не меняется. Не снимайте target с чужих окон.
  FileDropRegistrationTests проверяет настоящий OLE: заранее зарегистрированное
  окно, отказ без fallback, замену с сохранённым делегатом и баланс ссылок.
  Не используйте частные lParam системного ListView в качестве PIDL.
- Не полагайтесь на успех произвольного IShellFolder IDropTarget как доказательство
  переноса: Wine 10 shfldr_fs.c возвращает S_OK, но Copy/Move/Link там — заглушки.
  Регрессии проверяют фактические файлы и обновление списков. Не отключайте их;
  настоящий Win95/внешние приложения всё равно требуют проверки на целевой системе.
- Свободная расстановка рабочего стола остаётся прежней: её ghost переключается
  на OLE только при выходе к другому окну или наведении на folder/drop target.
  Снимок исходных позиций и собственный HIMAGELIST сохраняются до возврата OLE.
  FileDropLocal проверяется до CF_HDROP/native fallback: собственный source без
  Ctrl/Shift/Alt на пустом desktop снова выбирает расстановку, в том числе для
  виртуальных значков без файлового пути. Drop только записывает точку; EndDrag
  применяет её после DRAGDROP_S_DROP/MOVE и подтверждённого local результата.
  Не вызывайте Shell32 copy/move на фон desktop ради переноса Inbox/My Computer.
  Source callback возвращает BOOL только для принятой локальной расстановки;
  файловая операция, Escape и отказ не применяют сохранённые координаты.
  После структурного изменения source-снимок отменяется; restore откладывается
  до конца OLE. WM_CAPTURECHANGED/WM_CANCELMODE приостанавливают наш контроллер,
  но передаются native procedure, чтобы та очистила собственное состояние мыши.
  OLE владеет курсором, WM_SETCURSOR не должен подменяться на IDC_SIZEALL.
  ghostActive и ghostEntered различают BeginDrag и DragEnter: при уходе к native
  цели собственный drag image снимается без уничтожения, на фоне возобновляется,
  на завершении освобождается. Не вызывайте EndDrag для чужого/неактивного image.
  DesktopIconsWindowFromPoint игнорирует собственный образ при hit testing через
  исходный ImageList_DragShowNolock (Comctl32 4.0/Win95), без private HWND/class ABI.
- DoDragDrop содержит вложенный цикл сообщений. Закрытие источника/окружения
  откладывается через FileDragDeferClose до возврата; IDropTarget держит локальную
  ссылку на делегата через внешние вызовы, RevokeDragDrop обнуляет context.
  Обновление списков ставится в очередь после завершения операции.
- FileDropFeedback вызывается после получения effect от собственного либо native
  обработчика, а не во время выбора пути. Подсвечивайте только принятую цель;
  FileDropHighlight меняет LVIS_DROPHILITED и инвалидирует старую/новую область,
  не трогая LVIS_SELECTED. Виртуальные цели и не-папки с SFGAO_DROPTARGET
  сохраняют native обработчик; наличие filesystem-пути не превращает EXE в папку.
  Уход на фон, DragLeave, Escape и Drop снимают подсветку. Wine 10 не рисует
  нативный LVIS_DROPHILITED: тесты проверяют состояние и операции; реальное
  изменение пикселей дополнительно проверяется для нашего composite 48×48.
- В Wine-сценариях FileDragTests используйте один поток mouse_event для исходной
  позиции, DOWN, пересечения порога, пути и UP. Не смешивайте его с SetCursorPos:
  X11 warp с физическим button-up может сбить локальное состояние native ListView.
  Не дублируйте DOWN через SendMessage после реального нажатия: это может вложить
  второй DragDetect и преждевременно закончить OLE. Модификатор ожидается
  в устойчивом нажатом состоянии.
  После resize/selection дождитесь layout, затем проверьте реальный LVHT_ONITEMICON
  перед DOWN. ID_FOLDERS_CLOSE возвращает Tasks, а не скрывает sidebar;
  в узком drag-fixture закрывайте Tasks отдельно, чтобы значок был доступен.
  Проверяйте реальное состояние кнопки, модификаторов и цели;
  ожидаемый файловый результат нельзя заменять успешным HRESULT.
  Регрессия виртуального source проходит через папку обратно на свободное место,
  проверяет Escape, изменение координат и неизменность файлов/числа объектов
  в обоих размерах. Точка назначения должна быть выше appbar: desktop ListView
  может занимать весь экран под ней. Собственный popup образа не равен чужому
  окну; проверяйте owner process/style и конечный результат, не отключайте проверку
  истинной поверхности для остальных переносов.
  Для диагностики есть EX95_TEST_TRACE=1 при запуске smoke: исходный экземпляр
  получает --trace-render. drop-register/drop-dispatch/drag-reject и desktop.drop.*
  пишут только числовые результаты, без имён файлов и PIDL-содержимого.

- `--open`, `--explore`, `--namespace` принимаются до запуска окружения. Именованный
  startup mutex исключает гонку нескольких экземпляров. Запросы существующему
  экземпляру проходят фиксированный versioned WM_COPYDATA, затем ограниченную
  очередь, принадлежащую процессу. WM_APP не должен нести внешние указатели.
  Разрешены только каталоги и shell namespace; это не интерфейс запуска программ.
  `--settings` разбирается тем же tokenizer, без поиска подстроки внутри пути папки;
  неоднозначные повторные параметры профиля и незакрытые кавычки отклоняются.
- На рабочем столе сначала читайте Shell IDList Array для виртуальных папок.
  Проверяйте размер HGLOBAL, число элементов, смещения и окончания PIDL перед
  объединением. Копия принадлежит HeapAlloc; возвращённые Shell32 PIDL освобождайте
  по существующему COM-контракту. CF_HDROP остаётся запасным путём для файлов.
  GetAttributesOf вызывайте у владельца CIDA parent с относительным child, пока
  medium заблокирован. Запрос к Desktop с полным вложенным PIDL в Win95 может
  вернуть SFGAO_FOLDER родительского My Computer для апплета Control Panel.
  Эти же корректные capabilities нужны для действий sidebar; не классифицируйте
  апплеты по расширению, подписи или private PIDL/lParam.
- Регистрация папок отделена от boot shell и запускается из System Shell только
  на Win95 после подтверждения. Backend принимает отдельные classes/storage HKEY:
  тесты используют только свежие HKCU sandbox-ключи. Никогда не тестируйте установку
  через настоящий HKCR машины хоста. В UI резерв общий для машины:
  HKLM\Software\Explorer95\FolderHandler; EXE готовится под новым коротким именем.
- Снимки Before/After всех классов должны быть готовы и flushed до первой записи
  живых ассоциаций. Оригинальные open/explore включают все значения и вложенный DDE.
  Откат не затрагивает посторонние verbs; при изменении принадлежащих нам действий
  третьей программой отказывайте до записи. Не заменяйте неизвестный/первый резерв.
  При неудачном откате сохраняйте резерв и EXE. Общий Folder и неизвестные namespace
  extensions не перехватываются. SHChangeNotify вызывается только после живой операции.
- Полный smoke включает холодный запуск с папкой, передачу open/explore и двух
  namespace-запросов существующему экземпляру, отказ для некорректного IPC и проверку
  блокировки живой регистрации вне Win95. Core проверяет команды, CIDA и восстановление
  реестра на изолированных ключах. Реальную ассоциацию Shell32 Win95 проверяйте в ВМ.

- Обрамление файловых и виртуальных папок единое в `browser.c`. Класс обычного
  окна — `Explorer95.Files`, виртуального — `Explorer95.Namespace`; переход между
  ними возможен в одном окне. Рабочий стол продолжает использовать `NativeView`.
- Навигация сначала готовит новое содержимое и только затем меняет адрес,
  представление и историю. Не уничтожайте текущую папку при ошибке перехода.
  История ограничена 32 адресами на окно; освобождайте скопированные PIDL при
  обрезке ветки Forward, вытеснении и закрытии.
  Адрес — обычный CBS_DROPDOWN | CBS_OWNERDRAWFIXED | CBS_HASSTRINGS, без ComboBoxEx.
  BrowserAddress владеет ограниченным списком целей, их PIDL и значками. В строках
  хранится цель, а не команда, восстановленная из display label. Enter подтверждает
  выбор через внутреннюю очередь с копией пути/PIDL; Escape сохраняет набранный текст.
  Значок текущей папки — child нативного edit с зарезервированным левым полем;
  ComboBox и edit используют WS_CLIPCHILDREN. Соседний с edit значок может
  исчезнуть при раскрытии списка: native ComboBox переставляет своё поле.
  центр значка совпадает с центром текста по EM_GETRECT и метрикам шрифта edit;
  его WM_DRAWITEM передаётся из подкласса edit в Browser, original процедура восстанавливается
  при уничтожении. Строка и значок скрываются вместе. Раскрытие списка получает
  только назначенные буквы, статические системные места и уже известные пути:
  не перечисляйте папки и не считывайте метки/типы/значки по путям всех дисков.
- `IShellBrowser::BrowseObject` ставит переход в очередь владельца. Нельзя
  уничтожать `IShellView` из собственного вызова BrowseObject. Режим виртуального
  представления задаётся через `FOLDERSETTINGS`, без подмены стиля его ListView.
  `ICommDlgBrowser::OnDefaultCommand` и подкласс ListView направляют одиночное
  открытие папки через тот же navigator: старая Shell32 иначе вызывает Explorer.exe.
  Сохраняйте COM identity и счётчик ссылок обеих interfaces. Редактирование подписи,
  Alt+Enter и объекты без folder PIDL остаются у Shell32; не читайте её private lParam.
  В подклассе сначала фильтруйте тип сообщения открытия, только затем вызывайте
  ListView_GetEditControl: SendMessage(LVM_GETEDITCONTROL) синхронно входит в тот же
  подкласс. Обратный порядок переполняет стек Win95 при запуске. Canary теста
  считает реальные вложенные запросы, не полагаясь на ограничение рекурсии Wine.
  Smoke линкует native_view/render_trace; callbacks окружения в тестовом хосте
  запрещают запуск программ, открытие папок и изменение настоящего рабочего стола.
- Дерево при создании читает только `GetLogicalDriveStrings` и ресурсы значков
  системной DLL. Не вызывайте для корней `GetDriveType`, `GetVolumeInformation`,
  `GetFileAttributes`, FindFirstFile или SHGetFileInfo с путём накопителя.
  Чтение дочерних каталогов разрешено только после явного раскрытия узла;
  программная синхронизация не должна раскрывать/перечитывать диски.
  Существующее представление My Computer остаётся под управлением Shell32.
  Во время DestroyWindow дерева блокируйте навигацию из TVN_SELCHANGED, сохраняя
  обработку TVN_DELETEITEM для освобождения узлов. Закрывающееся окно не должно
  принимать новые переходы или обновлять состояние контролов.
- Свойство дерева `Explorer95.TreeReads` используется регрессией: включение,
  раскрытие My Computer и повторное открытие панели дают ноль новых чтений;
  явное раскрытие выбранного диска читает только его непосредственные папки.
  Это проверка собственного кода, а не доказательство отсутствия физического
  обращения к дисководу в целевой ВМ.
- Search файлового окна открывает собственную панель; `EnvironmentFind` остаётся
  системным поиском из окружения. Файловый поиск читает только явно выбранную папку,
  обходит её порциями таймера без фонового слежения, закрывает все find handles
  при Stop, смене панели и закрытии. Лимиты результатов/глубины и пропуски видимы.
  Для новой системы reparse points не обходятся. Результат принадлежит процессу;
  перед переходом из списка копируйте путь, не передавайте внешние указатели.
  Результаты размещаются в принадлежащем Browser окне `Explorer95.SearchResults`:
  штатный report ListView с общим системным image list. Close/Escape останавливает
  обход и скрывает окно, Show results возвращает сохранённый список. Уничтожение
  Browser освобождает окно и результаты; Open containing folder выделяет объект
  в исходном Browser. Не возвращайте результаты в узкий список боковой панели.
- `ExplorerBar` задаёт одну активную панель. Старый `Folders` — только миграционный
  запасной параметр. Tasks использует настоящие команды backend/Shell32; Sharing,
  Publish, Sendmail нельзя показывать без доступного canonical verb. Сведения о
  томе читаются только для явно открытого корня, не для всех узлов дерева.
- Скроллбары панелей и списков скрыты, пока содержимое помещается. Tasks сначала
  измеряется на полной ширине, затем при переполнении с учётом SM_CXVSCROLL.
  Ширина текста при измерении совпадает с отрисовкой, включая поля и значок.
  History задаёт горизонтальный extent по тексту, очищает его вместе со списком.
  Search results использует естественные скроллбары ListView по размерам колонок.
  Не используйте SIF_DISABLENOSCROLL или произвольную ширину 1600.
  Модель owner-drawn строки публикуется до создания/обновления native control:
  WM_SETTEXT может синхронно вызвать WM_DRAWITEM. Буфер всегда закрашивается.
- `[ExplorerHistory]` отделён от Back/Forward: до 32 уникальных MRU-целей на профиль.
  Записывайте только после успешного перехода, валидируйте сохранённые цели как
  folder request. Отключение очищает сохранённые посещения и запрещает новую запись;
  незаписываемая цепочка Back/Forward текущего окна сохраняется. History list хранит
  собственный снимок целей, чтобы изменение MRU другим окном не меняло выбранный адрес.
  Сохраняйте ограниченную секцию одним WritePrivateProfileSectionA; ошибки записи
  сообщаются пользователю без повторяющегося диалога на каждом переходе.
  Для встроенных namespace сопоставляйте PIDL со стабильной GUID-целью:
  Win95 может вернуть локализованное имя даже для SHGDN_FORPARSING. Enter в History
  открывает сохранённую цель; перестановка MRU не должна менять снимок под выделением.
- Toolbar использует GDI-полосу из `browser_toolbar.c` и стандартные bitmap-наборы
  Common Controls как запасной путь. Bitmap принадлежит Browser и освобождается
  после toolbar. FLAT/LIST и индивидуальная ширина — необязательные подсказки;
  базовый путь должен работать со старым toolbar. У Back/Forward/Views всегда
  задавайте TBSTYLE_DROPDOWN как требование интерфейса: при отсутствии DRAWDDARROWS
  toolbar_compat создаёт отдельные области стрелок, а native-кнопке оставляет
  основной переход. Стрелка отправляет TBN_DROPDOWN, основная часть — WM_COMMAND;
  отключение кнопки, уход мыши при отпускании и потеря capture должны учитываться.
  История по правому щелчку сохраняется. Не делайте IE3+ сообщения обязательными.
  toolbar_compat рисует разделители EDGE_ETCHED и вдавленные рамки нажатия/выбора
  EDGE_SUNKEN поверх native-кнопок. При наведении кнопки и стрелки плоские;
  убирайте также собственную hot-рамку Common Controls. Стрелки запасного пути
  используют PaintArrow/Marlett, без зависимости от наличия системного split-button.
  Отдельный hover-таймер не нужен; не добавляйте обязательный TrackMouseEvent
  из новых USER32 ради этого оформления.
  CompactToolbar измеряет каждую подпись выбранным UI-шрифтом, без копирования
  уже растянутого TB_GETITEMRECT. Иконки по умолчанию 16×16; сохранённый выбор
  24×24 уважается. toolbar_compat проверяет результат TB_SETBUTTONINFO по реальной
  ширине: при отказе/игнорировании создаёт отдельный native Toolbar на команду.
  Исходный toolbar остаётся моделью ID/состояний; TB_GETITEMRECT, уведомления,
  правый щелчок и изменение размеров должны соответствовать видимым кнопкам.
  Bitmap-полосы живут до уничтожения всех дочерних toolbar. Не заменяйте этот
  путь одним WM_SETFONT или тестом отсутствия повторной смены шрифта: пользователь
  подтвердил, что исправление alpha.36 само по себе не исправило расстояния на Win95.
  Регрессии должны отключать/имитировать игнорирование TB_SETBUTTONINFO и проверять
  фактические прямоугольники кнопок, а не только число отправленных сообщений.
  Дополнительных команд ровно шесть: Copy, Cut, Paste, Delete, Properties,
  Folder Options. Биты `ToolbarButtons` — 1/2/4/8/16/32 в таком порядке.
- Неизменившаяся геометрия Browser/Sidebar не должна повторно менять размеры,
  scrollbar range или скрытые подписи: это перерисовывает соседний IShellView
  на старых USER/Common Controls. Кэш layout сбрасывается при новой папке/view;
  настоящие resize и смена параметров по-прежнему размещают все контролы.
  После реального resize toolbar требуется RDW_ERASE; WM_ERASEBKGND заполняет
  переданный DC даже при WindowFromDC == Browser, иначе Win95 оставляет следы.
  Все левые панели, включая Tasks, используют видимый splitter из фактического
  layout. Сохраняйте смещение захвата; Escape/потеря capture возвращает ширину,
  отпускание записывает её. Перед capture ставьте фокус Browser для Escape.
  Общий BrowserDrawSymbol рисует close/collapse шрифтом Marlett. Проверяйте
  GetTextFaceA: успешное создание HFONT не исключает подмену шрифта. При отсутствии
  Marlett рисуйте GDI-символы; не показывайте буквальные r/5/6.
  Именованные панели Folders/Search/History используют системный lfSmCaptionFont
  и цвета COLOR_ACTIVECAPTION/COLOR_INACTIVECAPTION с соответствующим текстом.
  Browser владеет полосой заголовка и её шрифтом; STATIC/close имеют непересекающиеся
  прямоугольники, иначе STATIC может закрыть крестик в старой USER32. Content rect
  передаётся BrowserSidebarLayout уже без заголовка: не вычитайте вторую фиксированную
  высоту внутри sidebar. Прокрутка затрагивает только содержимое под заголовком.
- `[Explorer]` хранит настройки Проводника, `[ExplorerFavorites]` — до восьми путей.
  Не связывайте их с размером значков Start/Quick Launch. Новые окна читают
  сохранённые параметры, остальные открытые окна не меняются автоматически.
- Обычные каталоги поддерживают Icons, Small Icons, List, Details, Tiles,
  Thumbnails. Tiles реализован через Win95 owner-draw report и 54-пиксельную строку;
  не используйте современный LV_VIEW_TILE. Эскизы — только BMP штатным LoadImage,
  до 1 МиБ на файл и 128 изображений; другие типы показывают встроенные значки.
  Для виртуальных папок доступны только четыре режима установленной Shell32.
- Общие списки значков Shell32 не принадлежат окну: сохраняйте LVS_SHAREIMAGELISTS,
  не уничтожайте эти списки. Собственные списки дерева/эскизов/плиток освобождайте
  отдельно. Перед ImageList_AddMasked снимайте bitmap с memory DC.
- Copy/Cut публикуют CF_HDROP и Preferred DropEffect. Paste читает стандартный
  формат, не требует частного буфера и передаёт операции SHFileOperationA.
  Списки путей — ANSI, с двойным нулём; MAX_PATH сохраняется.
- Множественный Move использует парные списки с FOF_MULTIDESTFILES. Wine 10
  отклоняет несколько файлов с одним каталогом-назначением и при Move может
  молча перезаписать коллизию. Для коллизий применяется подтверждённое системное
  Copy, затем удаление исходников только после полного успеха без aborted.
  Сохраняйте проверку Cancel: существующие данные и cut-буфер остаются целы.
  Нельзя удалять исходники после неполного, пропущенного или отменённого Copy.
  Отвергайте перенос в самого себя/свой подкаталог до этого запасного пути.
- Обычный Delete использует FOF_ALLOWUNDO и штатное подтверждение; Shift+Delete
  отключает корзину. Properties и контекстные меню должны вызывать системную
  Shell32, а не показывать имитацию свойств. Для выбранных объектов вызывайте
  canonical verb `properties` через IContextMenu: некоторые старые реализации
  Shell32/Wine не поддерживают INVOKEIDLIST-путь ShellExecuteEx. В UI-тесте
  проверяйте наличие SysTabControl32: один класс #32770 может означать ошибку.
  Реальные пути сохраняют расширение,
  даже когда оно скрыто в надписи/редакторе.
- Меню New обычных каталогов читает установленные `.extension\\ShellNew`
  (также `.extension\\ProgID\\ShellNew`) из HKCR при каждом открытии. Общий
  модуль используется и на Desktop, если его IShellView не предоставил New.
  Не заменяйте этот список фиксированными «Folder/Text Document» и не добавляйте
  его в CLSID-папки. Folder идёт первым, зарегистрированный Shortcut — вторым,
  остальные пункты сортируются по имени типа. Чтение меню не открывает шаблоны
  и не проверяет носители; FileName читается только после выбора команды.
  NullFile/Data используют CREATE_NEW, шаблоны — CopyFile с fail-if-exists,
  коллизии получают новое имя. Зарегистрированные Command запускает ShellExecuteEx;
  сохраняйте кавычки вокруг подставленного пути. Не создавайте свою имитацию
  мастера ярлыков. ShellNew владеет своим submenu: отделяйте его от родительского
  меню через RemoveMenu перед ShellNewDestroy. Ограничение — 128 элементов за
  одно открытие для сохранения USER/registry-ресурсов Win95. Тесты используют
  отдельный корень классов, не меняют HKCR или пользовательские шаблоны.
  Асинхронный тестовый мастер .lnk открывает файл с FILE_SHARE_READ, а опрос
  результата — с FILE_SHARE_READ | FILE_SHARE_WRITE: оснастка не должна сама
  запрещать писателю доступ к зарезервированному файлу. Проверки размера и
  точного содержимого остаются обязательными.
  В UI-сценарии New → Folder после Right ограниченно ждите второго видимого
  popup окна того же процесса. Отправлять Home/Enter до создания подменю нельзя;
  проверка созданной папки остаётся обязательной.
  Выделение в чужом ListView задавайте через NativeSelectItem с памятью процесса
  приложения, затем проверяйте selected count. Прямой ListView_SetItemState
  передаёт указатель на локальный стек: LVM_* не маршалит его между процессами.
- Уведомление FindFirstChangeNotification отслеживает только открытый каталог,
  без рекурсии; таймер проверяет handle с нулевым ожиданием. При отключённом
  носителе уведомление закрывается до F5, диалог не должен повторяться в цикле.
  Не обновляйте содержимое во время операции, редактирования или контекстного
  меню. Сохраняйте выделение при обновлении и не опрашивайте остальные диски.
- Закрывайте окна браузера через `EnvironmentHost.closeFolders` / BrowserShutdown
  до освобождения рабочего стола и его Shell32-объектов, затем выполняйте OleUninitialize. При
  закрытии освобождайте view, pending/history PIDL, watch, tree и GDI-буферы.
  WM_CLOSE панели завершает основной цикл; общая очистка Shell32 и других
  верхнеуровневых окон выполняется после возврата из оконной процедуры. Сам HWND
  панели уничтожается последним, после снятия appbar/горячих клавиш.
  Перед уничтожением desktop view обнуляйте env.desktopView и подавляйте его
  callbacks во время env.closing: нельзя повторно фокусировать или обновлять
  освобождаемое представление. ShutdownStage/ViewDestroyStage на HWND помогают
  smoke-тесту показать фазу, если закрытие зависло в старой реализации Shell32.
  WM_CLOSE панели сначала вызывает FileDragDeferClose: нельзя передавать WM_QUIT
  в активный вложенный OLE loop вместо отмены source. После возврата DoDragDrop
  повторяется WM_CLOSE, затем обычный выход. CloseDuringDesktopDrag в browser/full
  закрывает свой процесс при удерживаемой кнопке и принятой цели, требует выхода
  за прежние 5 секунд и неизменности своих source/пустой destination.
  --trace-render пишет exit.* и view.exit.* до возврата OleUninitialize;
  RenderTraceClose вызывается после exit.done. Нормальные события используют
  первые 504 КиБ, последние 8 КиБ из общего лимита 512 КиБ сохраняются для выхода.
  Закрытие отдельной папки до начала exit.* не расходует этот резерв.

Для правок Проводника проверяйте историю и ветку Forward, независимость окон,
нулевые чтения дерева до раскрытия, реальные Copy/Cut/Paste и отмену коллизии,
Rename со скрытым расширением, системные Properties, обновление без F5,
режимы/настройки и первоначальную отрисовку виртуальных папок. Дополнительно
осматривайте перенос полной панели при 640×480, дерево, Tiles и BMP-эскизы.

## Основная оболочка, системные команды и трей

- WM_SIZING панели задач корректирует переданный RECT сразу до целых строк,
  сохраняя закреплённую сторону и длину вдоль экрана. Высота строки соответствует
  EnvBarThickness (28/40/44 для обычных/крупных/плиток). Не откладывайте привязку
  до WM_EXITSIZEMOVE и не рассчитывайте плитки с шагом обычных кнопок.

- Quick Launch использует owner-draw кнопки: BS_FLAT не поддерживается исходной
  Win95. Общие EnvPaintQuickButton / EnvPaintQuickGrip рисуют и живую панель,
  и preview. В покое нет постоянной выпуклой рамки; hover/press/focus сохраняются.
  Короткий hover-таймер работает только над кнопкой; WM_SYSCOLORCHANGE не пересоздаёт
  контролы. Subclass и tooltip должны сохранять цепочку оконных процедур.
- Ручка Quick Launch меняет только длину участка вдоль панели, не размер/позицию
  всей taskbar и не рабочую область. Lock taskbar блокирует ручку. Обрабатывайте
  WM_LBUTTONDBLCLK как начало переноса; Escape / потеря capture отменяют перенос.
  На отпускании сохраняйте Taskbar.QuickLaunchSize (0 — auto, до 4096 пикселей),
  оставляя место для задач/трея. Ограничение текущего экрана не перезаписывает
  сохранённое предпочтение. Новые настройки не должны теряться при общем Apply.
  Скрытые значки доступны через >> с owner-draw меню 16×16; не удаляйте команды
  и не расширяйте участок автоматически после ручного изменения размера.
- Delete на desktop ListView не перехватывает текстовый редактор подписи.
  Для полного файлового выделения используйте IDataObject/CF_HDROP и SHFileOperationA
  FO_DELETE с FOF_ALLOWUNDO (Shift отключает корзину). Пути ограничены MAX_PATH,
  список заканчивается двойным нулём; не удаляйте часть смешанного виртуального
  выделения. Для виртуальных объектов остаётся IContextMenu. Cancel не запускает
  запасной путь повторного удаления. Операция завершается до сохранения раскладки;
  успешное обновление desktop проходит через существующий контроллер Refresh.
- Empty Recycle Bin появляется в toolbar самой корзины и в File, отключается
  при пустом содержимом. Не импортируйте SHEmptyRecycleBinA: его нет в исходной
  Win95. Очистка выделяет все объекты текущего NativeView Корзины и вызывает
  NativeShellDelete; тот же путь обслуживает выбранный Delete. Сначала ищется
  canonical verb delete в IContextMenu выделения, после чего вызывается именно
  числовой offset из QueryContextMenu, не строка и не фиксированный номер.
  Отключённые команды не вызываются (GetMenuState есть в базовой Win95).
  Если команда не найдена до InvokeCommand, VK_DELETE передаётся через
  IShellView::TranslateAccelerator. Только S_FALSE разрешает доставить клавишу
  самому ListView. S_OK, ошибка и отмена не допускают второй попытки.
  Wine возвращает S_FALSE из TranslateAccelerator и не воспроизводит этим
  поведение оригинального Win95 view; реальный Wine-прогон дополняется
  безопасными COM-контрактами в tests/native_view_cases.h. Проверяйте
  числовой offset, ветку S_OK, S_FALSE и отсутствие повтора после E_ABORT.
  Весь вызов, включая COM-ветки, удерживает operationDepth, чтобы отложенный
  Refresh другого окна не сработал внутри native InvokeCommand/подтверждения.
  После Empty/Delete оставляйте NativeViewRequestRefresh в очереди. Не вызывайте
  BrowserRefresh синхронно в этих командах: NativeViewRefresh сбросит pending,
  а отложенное сообщение уже не выполнит обновление после native операции.
  BrowserUpdate может сразу восстановить состояние кнопок; перечисление списка
  выполняет WM_BROWSER_NATIVE_REFRESH после возврата в цикл сообщений.
  Не полагайтесь на успешный HRESULT строкового verb: старый IContextMenu может
  принять неизвестную строку без действия; Wine также не реализует
  GetCommandString для объектов Корзины. Не удаляйте содержимое RECYCLER/RECYCLED
  вручную, не пробуйте второй обработчик после Cancel и не обходите проверку,
  что NativeView действительно относится к CSIDL_BITBUCKET.
  LVN_INSERTITEM/DELETEITEM/DELETEALLITEMS и смена выделения ставят объединённое
  уведомление состояния Browser в очередь; sidebar учитывает и общее число
  объектов. Завершение собственного файлового Delete на рабочем столе или
  в Browser уведомляет все открытые окна Корзины этого процесса: не все старые
  shell view сами получают уведомление о пополнении. Это разовое обновление
  после операции, без постоянного опроса дисков. После native
  WM_CONTEXTMENU/VK_DELETE обновление ставится только
  после возврата исходной процедуры из InvokeCommand и подтверждения.
  WM_EXITMENULOOP наступает раньше выполнения команды и непригоден для Refresh:
  он может освободить PIDL во время ещё работающего системного обработчика.
  Обычные Copy/Cut/Paste/Rename и файловые Move-задачи в Корзине недоступны;
  default action удалённых папок остаётся у Shell32, не у BrowserNavigate.
  Подтверждённая очистка в тесте допустима только для изначально пустой корзины,
  когда перед Yes проверено, что её единственный объект — собственный fixture.
  Проверяйте реальные точки входа, восстановление системным меню, обновление
  без F5 и пустоту после повторного открытия через новый IShellFolder.
  При чужих объектах ограничьтесь отменой. Wine 10 не очищает каталоги корзины:
  erase_trash_item вызывает DeleteFileW и возвращает успех при отказе. Для
  подтверждённой очистки используйте файл; папки проверяются на реальной Win95,
  без обхода системного API в приложении ради ограничения Wine.
  При отказе на настоящей Win95 используйте --trace-render: строки shell
  stage=recycle.* в EX95REND.LOG содержат маршрут, HRESULT, числовые ID и
  количество объектов/выделений, без имён файлов. Отчёт о S_OK не подтверждает
  фактическое удаление; не называйте Wine-успех доказательством исправления Win95.
- Одиночные VK_LWIN/VK_RWIN открывают/закрывают Start при отпускании, включая
  классический TrackPopupMenu. RegisterHotKey сообщает нажатие; краткий таймер
  GetAsyncKeyState работает только до отпускания и отменяет действие при сочетании
  с другой клавишей/мышью. Win+D и Ctrl+Esc не должны дополнительно открывать Start.
  Не добавляйте WH_KEYBOARD_LL (нет в Win95), глобальную hook-DLL или постоянный
  опрос клавиатуры. Освобождайте регистрации и таймер при завершении.
- Видимость Start — сохранённые startItems AND availableStartItems. Сеть определяется
  только битом 0 SM_NETWORK; отсутствие подключения не означает отсутствие компонента.
  Для Win95 Log Off доступен с Network\\Logon\\UserProfiles (REG_DWORD) либо установленной
  сетью и непустым PrimaryProvider (REG_SZ); NT поддерживает сеансы самостоятельно.
  Учитывайте NoNetHood/NoLogoff в Policies\\Explorer HKCU/HKLM. Проверяйте перед открытием
  меню и по WM_SETTINGCHANGE, не опрашивайте сеть/реестр в общем таймере панели.
  Применяйте одну маску к двум колонкам, классическому меню, More и расчёту строк.
  Не перезаписывайте пользовательские галочки при отсутствии компонента.
  Fixtures реестра создавайте под отдельными HKCU-корнями; настоящую конфигурацию
  входа и системные политики тесты менять не должны.
- Обычный запуск работает рядом со штатным Explorer. Не завершайте его процесс
  и не меняйте загрузочную оболочку как побочный эффект запуска или UI-теста.
- При наличии штатной `Shell_TrayWnd` используйте режим appbar; при её отсутствии
  работает режим основной оболочки с совместимым окном для уведомлений.
  При выходе восстанавливайте рабочую область и освобождайте регистрации.
- Поддержка трея ограничена базовым ANSI-протоколом Win95. Соблюдайте размер,
  упаковку и время жизни полей передаваемых структур. Не подменяйте этот протокол
  современными структурами или внутренним форматом Wine.
  Экспериментальное зеркалирование в appbar-режиме Win95 использует встроенную
  `tray_hook.dll` из `src/tray_hook.c` и протокол `src/tray_mirror.h`. Hook ограничен
  потоком штатной панели: WH_GETMESSAGE для запроса снимка из очереди и
  WH_CALLWNDPROCRET для принятых изменений, не клавиатурой или всеми процессами.
  Оригинальные сообщения и результаты не подменяются. Начальный снимок читает
  private ABI классического TrayNotifyWnd через проверяемые ReadProcessMemory;
  формат не универсален для IE4/NT. Модуль извлекается в уникальный временный файл,
  снимается hook, выгружается DLL, затем удаляется только этот файл.
  Оба HHOOK хранятся в shared-секции и передаются в CallNextHookEx: NT игнорирует
  первый параметр, Win95 требует действительный handle. Извлекайте модуль под
  свободным коротким .DLL-именем без замены чужого файла. Постановка запроса
  не подтверждает ответ hook; отказ должен иметь отдельный этап.
  Статусы различают чтение окна, массива, записей, image list и упаковку картинки;
  --trace-render пишет этап/код/detail/value, без подписей и путей уведомлений.
  Входящие ANSI v1 пакеты требуют точного cbSize и допустимых NIF-флагов.
  Сохранённые записи private ABI не являются такими пакетами: не используйте
  их cbSize/uFlags как признак версии. Проверяйте память, диапазон callback
  (0..0xffff) и индекс реально используемого изображения. Закрытый HWND владельца
  пропускается, а не блокирует весь снимок; итоговое число относится к живым записям.
  detail: 1 — нечитаемая строка, 2 — закрытые владельцы, 3 — callback,
  4 — индекс изображения, 5 — сохранённый cbSize, 6 — сохранённые флаги.
  Stage 30/error 0 информационный: он не завершает ожидающий запрос и не очищает
  состояние ожидания. Изменение формата статуса требует версии refresh-протокола.
  `check_pe.py` проверяет также встроенный PE32 DLL, его импорты и .shared-секцию.
  `tests/tray_mirror_cases.h` проверяет настоящий DLL на изолированных окнах,
  в том числе в отдельном процессе. Сравниваются пиксели/маска после освобождения
  исходного HICON, обновления, callbacks, снятие hook и неверные указатели/размеры.
  Не пересылайте HICON: это значение может быть локальным для процесса. Собственный
  IPC несёт фиксированные 32-bit BGR и 1-bit AND DIB, порциями по восемь значков.
  Прежние элементы удаляются только после последней порции полного снимка.
  Запрос снимка — pointer-free PostMessage в Shell_TrayWnd, WH_GETMESSAGE выполняет
  его только при PM_REMOVE. Не заменяйте это sent-message hook с синхронным ожиданием:
  реальная Win95 дала отсутствие ответа при успешной отправке запроса; прежний 1114
  был синтетической ошибкой приложения. Host остаётся в message loop, ждёт до пяти
  секунд без прогресса и сообщает ERROR_TIMEOUT. Одновременно разрешён один запрос.
  Повторный вход/неудачная доставка ставит pointer-free hint владельцу.
  Сверка раз в секунду подхватывает изменения без post-return событий. Кэш исходных
  пикселей сравнивается точно, без hash; неизменившиеся элементы сохраняют changed,
  HWND и HICON. Маска сравнивает только 16 видимых битов строки; DIB padding при
  упаковке обнуляется. Не допускайте, чтобы сверка мешала Hide inactive icons.
  Полный smoke обязателен перед релизом; Wine fixtures не подтверждают private ABI
  настоящего Explorer Win95 RTM/OSR2 и работу systray/internat. Указывайте эту
  границу проверки при публикации экспериментальной сборки.
- Изменение `[boot] shell=` через интерфейс разрешено только на Windows 95.
  Не обходите проверку версии ради тестирования на современной Windows или Wine.
- Устанавливайте новую копию под свободным коротким именем `EX95xxxx.EXE`.
  Не перезаписывайте запущенный EXE: Win95 может блокировать его.
- Сохраняйте исходный `SYSTEM.INI` как `EX95BAK.INI`, данные восстановления —
  в `EX95REC.INI`. Повторная установка не должна заменять первую резервную копию.
- Восстановление возвращает точную исходную команду shell, включая аргументы,
  и сохраняет посторонние изменения INI. Не перезаписывайте оболочку, выбранную
  другой программой после Explorer95, и неизвестные резервные файлы.
- Не удаляйте подготовленный EXE при ошибке записи, если загрузочная конфигурация
  после неудачного восстановления может продолжать ссылаться на него.
- Смена shell действует после перезапуска Windows. Не добавляйте автоматическую
  перезагрузку как побочный эффект применения настроек.
- Log Off, Shut Down и Exit Explorer95 — разные действия. При `Incorrect Function`
  у Log Off сохраняйте штатный запасной диалог; не заменяйте выход из сеанса
  принудительным завершением программ или перезагрузкой.
- В меню панели задач нет Exit Explorer95; команда Task Manager запускает
  полный путь Windows\\TASKMAN.EXE без записи в recent programs. Пользователь
  подтвердил работу штатного Task List в настоящей Windows 95.
  Экспериментальный Ctrl+Alt+Del из alpha.43 не сработал на ВМ пользователя:
  удалены отправка клавиш и выбор режима; старый ClosePrograms игнорируется.
  Не возвращайте этот вариант на основании теста инертных callbacks: он проверяет
  подготовку событий, а не открытие системного окна. Требуется подтверждённый
  способ вызова на Win95; запрос обоих вариантов остаётся в BACKLOG.
  Автотесты не должны вызывать настоящий аварийный диалог.
- В Desktop → Shutdown dialog style выбирается компактное окно 314×200:
  XP по умолчанию или классическое 95 с системными значками. Значение
  `[Desktop] ClassicShutdown` проходит через общий черновик и Apply настроек.
  При изменении геометрии используйте размеры client rect для дочерних кнопок:
  у стиля 95 есть нативный заголовок, у XP — собственный.
- В новом профиле Start включает Favorites; `VisibleItems=16383`,
  `FolderMenus=4130` задаёт подменю Recent Documents / Printers / Favorites.
  Остальные папки — ссылки; порядок и номера битов сохранены. По умолчанию
  закреплён только `@explorer`. Не удаляйте `@command` из существующего `[Pinned]`
  и не переписывайте явные пользовательские маски ради новых значений по умолчанию.
- Кнопка MS-DOS mode находится в нижней полосе рядом с Cancel и не меняет
  геометрию трёх основных действий. Только на Win95 запускайте установленный
  Windows\Exit to Dos.pif (также русские имена); Microsoft KB
  [Q150323](https://jeffpar.github.io/kbarchive/kb/150/Q150323/) и
  [Q151717](https://jeffpar.github.io/kbarchive/kb/151/Q151717/) описывают его
  назначение. При отсутствии PIF используется штатный диалог Shell32 ordinal 60
  с явным выбором пользователем MS-DOS. Ошибка запуска PIF сообщается как ошибка,
  без замены другой операцией питания. Не создавайте/не правьте системный PIF,
  CONFIG.SYS, AUTOEXEC.BAT и MSDOS.SYS. Перед передачей управления закройте
  собственный выбор и восстановите enabled окон для штатных вопросов о сохранении.
  Backend тестируется с собственными файлами и инертными callback; такие проверки
  не доказывают реальный переход в DOS и не должны его выполнять.
- Shut Down открывает Explorer95.Shutdown над Explorer95.ShutdownShade. Это
  модальное окно с возвратом фокуса и блокировкой собственных окон приложения,
  а не механизм защиты/блокировки сеанса. Не отключайте системные аварийные клавиши
  через SPI_SETSCREENSAVERRUNNING, глобальные hooks или BlockInput.
  Shade — самостоятельное tool window без владельца taskbar; choice принадлежит
  Shade, а оба HWND освобождаются через ShutdownClose. Поднимайте choice и ставьте
  Shade непосредственно под ним: группа popup-окон taskbar и чужие topmost-окна
  не должны оказаться между диалогом и снимком.
- Затемнение использует один снимок и один буфер BGR32, целочисленные шаги,
  GetDIBits/SetDIBits. Не добавляйте статические AlphaBlend/layered-window API.
  Первый снимок рисуется до запуска таймера; пиксельный буфер освобождается после
  анимации. При Cancel/Esc/смене разрешения/выходе уничтожайте оба окна, таймеры,
  GDI-объекты и DLL, восстанавливайте только ранее включённые собственные окна.
- Stand By/Hibernate доступны по необязательным экспортам питания; Windows 95
  без соответствующего API/оборудования не должна изображать работающий Hibernate.
  Перед настоящим ExitWindowsEx снимайте перекрытие: приложения вправе отменить
  завершение сеанса или показать сохранение. EWX_FORCE/force-suspend не допускаются.
  Автотесты проверяют выбор, затемнение, модальность и отмену, но никогда не
  запускают выключение, перезагрузку, сон или Log Off на машине теста.
- Команда фона рабочего стола должна вызывать штатный `control.exe desk.cpl`.

При работе над загрузкой сначала изучите восстановление из DOS в README.
Автоматические проверки выполняйте на временных файлах; реальную смену shell,
перезапуск и восстановление проверяйте в предназначенной для этого ВМ.

## GitHub, CI и релизы

Публикуйте изменения и релизы в рамках явного действующего разрешения пользователя.
Учитывайте уже данное в разговоре разрешение и не запрашивайте его повторно без
нового основания. Создание файла или обычная правка документации само по себе
не требует отдельного бинарного релиза.

Перед публикацией кода:

1. Просмотрите diff и `git diff --check`, убедитесь, что нет посторонних файлов,
   временных профилей, бинарников или секретов.
2. Выполните проверки, соответствующие изменению. Для изменения приложения нужны
   PE-проверка и соответствующие UI-сценарии; для документации не запускайте их формально.
3. Обновите README при изменении поведения, настроек или команд сборки.
4. Для релиза обновите `.github/release-notes/environment.md` под итоговое поведение,
   проверки и оставшиеся ограничения. Не копируйте устаревшие результаты тестов.
5. Проверьте имя текущей ветки и целевой remote. Если разрешена публикация в `main`,
   а локальная ветка имеет другое имя, используйте явный refspec `HEAD:main`.
   Не используйте force-push и не заменяйте опубликованные теги.

`build.yml` работает на push в main, pull request и workflow_dispatch. Теги
обрабатывает только `release.yml`. `tests/select_checks.py` выбирает группы по путям:
документация пропускает тяжёлые jobs, menu/browser/backend — соответствующие группы,
общие модули, ресурсы, тесты и инфраструктура — full. Неизвестные пути, отсутствующая
база сравнения и смешанные подсистемы требуют full. Правила проверяются через
`python3 -m unittest discover -s tests -p test_select_checks.py`.
Для main базой служит последний успешный автоматический push-run этого workflow;
для PR проверяется весь diff с базовой веткой. Нельзя сравнивать main только
с github.event.before: docs-push после отменённого code-push иначе пропустит код.
Ручной subset-run не подтверждает базу; ошибка API должна выбирать full.
Выбор по путям не заменяет оценку риска: при сомнении запускайте полный набор.
Не используйте `[skip ci]` для обхода проверок кода.

Устаревшие запуски одной ветки/PR отменяются через concurrency; итоговый Checks
проверяет результаты выбранных jobs, включая допустимые пропуски. Переиспользуемый
`test-ui.yml` сохраняет логи и использует Wine 10/Debian 13. Для ручного полного
прогона используйте workflow_dispatch с group=full.

В release workflow сборка x86 и полный UI job идут параллельно. Публикация зависит
от успешного завершения обоих; не убирайте эту зависимость. concurrency релиза
не отменяет уже начатую публикацию. Правки инфраструктуры и документации
публикуйте без отдельного бинарного релиза, если поведение приложения не менялось.

Публикуемый комплект:

- `explorer95.exe` из `build/explorer95.exe` — целевой Win95-бинарник;
- `explorer95-<tag>-win32.zip` — тот же EXE и README;
- `SHA256SUMS.txt` — контрольные суммы EXE и ZIP.

После публикации проверьте наличие assets, скачайте их с GitHub, сверьте SHA256,
повторно запустите PE-проверку скачанного EXE и убедитесь, что ZIP содержит тот же EXE.
В ответе дайте ссылку на страницу релиза и прямую ссылку на бинарник.

Используйте существующую аутентификацию Git/платформы. Отсутствие `GH_TOKEN`
или недоступность GitHub API не доказывает отсутствие возможности push через HTTPS.
Не извлекайте и не выводите токены или содержимое credential-файлов.
Если среда кэширует старый ответ страницы Actions или ранний 404 asset,
проверьте свежий URL/страницу job; не объявляйте публикацию неуспешной только
из-за закэшированного результата.

## Завершение задачи

Перед ответом проверьте итоговый diff и состояние Git. Сообщите, что изменено,
какие проверки действительно выполнены, где находится результат и какие
существенные проверки остались. Различайте:

- собранный локально Win95 EXE;
- проверку структуры PE и импортов;
- поведение отдельной x64-сборки под Wine;
- реальную проверку Win95 в ВМ;
- публикацию commit/tag и скачиваемых assets.

Не называйте сборку полностью совместимой с Win95 только на основании Wine
и списка импортов. Не записывайте в этот файл временные PID, номера дисплеев,
ID запусков Actions, секреты или фиксированные текущие результаты тестов.
Обновляйте инструкции, если изменились архитектура, команды или гарантии проекта.
