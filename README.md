# Explorer95

Любительская оболочка в духе Windows XP для Windows 95: классическое оформление,
рабочий стол, панель задач, двухколоночный «Пуск» и отдельные окна Проводника.
Luna не используется. Цвета, шрифты и системные значки берутся из установленной Windows;
флажок кнопки Start — приложенный пользователем Bitmap143.bmp.

Проект остаётся экспериментальным. Новую версию сначала проверяйте в виртуальной
машине: реальная загрузка Windows 95 с Explorer95 в качестве shell здесь ещё не проверена.

## Что реализовано

- **Рабочий стол:** системное представление `IShellView` из Shell32, значки,
  открытие объектов, выделение, перетаскивание и системные контекстные меню.
  Поддерживаются цвет фона и BMP-обои из параметров Windows, центрирование и мозаика.
- **Контекстное меню рабочего стола:** команды установленной Shell32, включая
  доступные в ней команды буфера обмена и свойства; дополнительно — упорядочивание,
  создание папки/текстового документа, подменю Explorer95 с настройками панели
  и отдельный пункт **Desktop Background / Display Properties...**, вызывающий `control.exe desk.cpl`.
  Состав и язык системных команд зависят от версии Shell32. «Свойства» Windows
  позволяют менять оформление и фон средствами самой Windows 95.
- **Панель задач:** кнопки окон, восстановление и сворачивание, системное меню окна
  по правому щелчку, группировка окон одного процесса, часы и «Показать рабочий стол»
  с восстановлением ранее свёрнутых этой командой окон. Компактная классическая
  панель с кнопкой Start в классических пропорциях (54×22 при стандартном
  шрифте), штатной системной рамкой, малым флажком 16×16 и жирным шрифтом
  системных заголовков. При нажатии флажок и надпись смещаются вместе на один
  пиксель. Поддерживаются значки окон и утопленная
  область часов; формат времени берётся из региональных настроек Windows.
- **Отрисовка:** панель задач, её кнопки, «Пуск» и пункты меню рисуются через
  сохраняемые GDI-буферы; обои рабочего стола кэшируются до изменения фона или
  размера. Закрытие перекрывающих меню не требует предварительной заливки пустым
  фоном. Это уменьшает мерцание собственных элементов оболочки; перерисовкой
  сторонних приложений по-прежнему управляют Windows и сами приложения.
- **Настройки панели:** четыре стороны экрана, перетаскивание незаблокированной
  панели к краю, изменение толщины с привязкой к трём размерам, одна–три строки,
  ширина кнопок, блокировка, автоскрытие, положение поверх окон, часы,
  быстрый запуск, размер его значков и скрытие неактивных уведомлений.
  Настройки сохраняются между запусками и доступны в общем окне Environment Properties.
- **Быстрый запуск:** значки программ/ярлыков из папки Quick Launch; добавление
  перетаскиванием файла на панель задач создаёт ярлык, исходный файл сохраняется.
  Для дополнительных элементов можно открыть саму папку через меню панели.
- **Трей:** приём базового ANSI-протокола уведомлений Windows 95: `NIM_ADD`,
  `NIM_MODIFY`, `NIM_DELETE`, значки, подсказки и обратные сообщения мыши приложению.
  Скрытые и не поместившиеся уведомления доступны через кнопку `>`. Во вкладке
  Notifications для каждого приложения выбирается Hide when inactive / Always show /
  Always hide, а время неактивности настраивается от 5 до 3600 секунд. Правила
  запоминаются по программе, классу окна и ID уведомления, а не по временному HWND.
- **Пуск:** заголовок с именем пользователя, отдельный список закреплённых программ
  (по умолчанию Explorer и MS-DOS Prompt), последние программы слева, дерево
  All Programs с вложенными папками и значками программ, ярлыков и папок; справа — документы,
  недавние документы, компьютер, сеть, панель управления, принтеры, помощь, поиск и Run.
  Внизу — выход из Explorer95, завершение сеанса и выключение с подтверждением.
  Значки системных команд извлекаются по ID ресурса, чтобы порядок значков
  в разных версиях Shell32 не подменял их случайными картинками.
- **Настройки «Пуска»:** произвольная надпись на кнопке, галочки для команд
  справа и трёх команд внизу; добавление до шести закреплений с именем и аргументами,
  выбор EXE/ярлыка через Browse, удаление и перестановка. Список закреплений
  хранится отдельно от истории. У недавней программы правый щелчок →
  **Pin to Start menu**, у закреплённой → **Unpin from Start menu**.
  Между списками виден разделитель; закреплённая команда не дублируется в недавних.
- **Крупные значки «Пуска»:** Environment Properties → Start Menu → General →
  **Large icons** переключает значки с 16×16 на 32×32: закрепления, недавние программы,
  системные команды и кнопки All Programs / Recent Documents в основном меню.
  В раскрывающихся списках программ, недавних документов и их вложенных папках
  значки всегда 16×16, независимо от этой настройки. Загружаются соответствующие
  ресурсы значков, а не растягиваются малые. В нижней панели Exit / Log Off / Shut Down
  значки всегда 16×16, а высота панели не зависит от режима значков.
  Ширина основного меню — 370 пикселей
  с малыми значками и 410 с крупными (при достаточной ширине экрана); число
  видимых пунктов пересчитывается по экрану. Размер Quick Launch настраивается отдельно.
- **Число недавних программ:** параметр Recent programs в настройках «Пуска»,
  включая 0 для скрытия списка. Верхний предел рассчитывается по разрешению,
  рабочей области, положению панели, высоте шрифта и числу закреплений
  (история хранит до 30 команд, по умолчанию показываются до семи). При уменьшении
  экрана число видимых строк сокращается автоматически; скрытые записи не удаляются.
  Высота «Пуска» не выходит за доступную область. На очень маленьком экране или
  при крупном шрифте не поместившиеся закрепления и системные команды доступны
  через More pinned / More.
- **История программ:** успешные запуски через Run, файловые окна, меню программ,
  быстрый запуск и файловые значки нашего рабочего стола. Аргументы Run сохраняются.
  Документы, ярлыки на документы/папки и объекты из Recent Documents в неё не входят:
  для .lnk проверяется цель. Старые неподходящие записи автоматически убираются,
  порядок и аргументы оставшихся программ сохраняются. Это история запусков через
  Explorer95, а не глобальное наблюдение за всеми процессами.
- **Проводник:** классическая компоновка XP — File / Edit / View / Favorites /
  Tools / Help, панель инструментов, раскрывающаяся адресная строка, переключаемая
  панель Folders и строка состояния. Обычные каталоги и системные папки, включая
  «Мой компьютер» и панель управления, используют одинаковое обрамление.
  Содержимое виртуальных папок остаётся настоящим представлением Shell32.
- **Навигация:** Back, Forward и Up; отдельная история до 32 переходов на окно,
  относительные пути и переменные окружения в адресе. Search / F3 открывает
  штатный поиск установленной Windows, без собственной поисковой панели.
  В Windows 95 используется собственный диалог Find из Shell32.
- **Папки:** дерево Desktop / My Documents / My Computer / накопители / Control
  Panel / Network Neighborhood / Recycle Bin, изменяемая ширина и кнопка закрытия.
  Включение панели и раскрытие My Computer получают только назначенные буквы
  дисков; чтение содержимого, томов и извлечение значков по путям накопителей
  не выполняются. Каталог читается только при его открытии или явном раскрытии;
  вложенные папки не обходятся заранее. Поэтому включение Folders само по себе
  не должно обращаться к пустому дисководу.
- **Вид и инструменты:** Icons, Small Icons, List, Details, Tiles и Thumbnails
  для файловых папок; сортировка по имени, типу, размеру и дате. Плитки показывают
  имя, тип и размер. Эскизы используют встроенный загрузчик BMP, ограничены
  файлами до 1 МиБ и кэшем до 128 изображений; прочие форматы сохраняют системные
  значки. В виртуальных папках доступны четыре штатных режима установленной
  Shell32. Все значки берутся из Windows, отдельные XP-ресурсы не нужны.
- **Операции с файлами:** стандартный файловый буфер обмена Copy / Cut / Paste,
  множественное выделение, Delete через системную корзину (Shift+Delete — без неё),
  переименование, новая папка, системные контекстные меню и штатные свойства
  Windows 95. Скрытие расширений меняет только надпись; переименование сохраняет
  скрытое расширение. Изменения открытого каталога отслеживаются без F5 с сохранением
  выделения; остальные накопители для этого не опрашиваются.
- **Настройка Проводника:** Tools → Folder Options / Customize Toolbar или правая
  кнопка на панели. Можно включать только шесть дополнительных команд: Copy, Cut,
  Paste, Delete, Properties, Folder Options. Настраиваются подписи, размер значков
  панели, скрытые/системные файлы, расширения, режим просмотра и панель Folders.
  View позволяет скрывать панель инструментов, адрес и строку состояния.
  Избранное хранит до восьми файловых папок. Настройки применяются к текущему
  окну и новым окнам; уже открытые другие окна сохраняют свой вид.
  Родительское окно отсекает дочерние области при перерисовке, чтобы значки
  системных папок были видны сразу.

## Два режима работы

При обычном запуске Explorer95 работает рядом со штатным Explorer, не завершает его
процесс и не меняет загрузочную оболочку. Панель регистрируется как appbar и
резервирует свою рабочую область, чтобы развёрнутые окна её учитывали.

Если штатной панели `Shell_TrayWnd` нет, Explorer95 работает как основная оболочка:
резервирует рабочую область самостоятельно и принимает уведомления приложений через
совместимое окно `Shell_TrayWnd`. При выходе рабочая область восстанавливается.

В режиме рядом со штатным Explorer обычные `Shell_NotifyIcon`-уведомления остаются
в его трее. Перехват чужой панели не производится. Трей Explorer95 рассчитан на
базовый ANSI-протокол Windows 95, а не на расширенные протоколы XP/современной Windows,
GUID, всплывающие баллоны или собственный формат Wine. Сквозная совместимость с
реальными приложениями Windows 95 ещё требует проверки на целевой системе.

## Замена оболочки Windows 95 и возврат

Откройте **правый щелчок по панели → Properties** либо
**рабочий стол → Explorer95 → Environment Properties**, затем вкладку **System Shell**.
В секции Windows 95 system shell доступны:

- `Use Explorer95 as shell...` — копирует программу в каталог Windows как
  `EX95xxxx.EXE` со свободным коротким именем, сохраняет исходную настройку
  и устанавливает её в `[boot] shell=`. Существующие и запущенные EXE не перезаписываются:
  обновление основной оболочки не упирается в блокировку старого файла Windows 95.
- `Restore previous shell...` — возвращает точную сохранённую команду, включая
  аргументы. Остальные записи SYSTEM.INI остаются на месте.

Изменения действуют **после перезапуска Windows**. Текущий Explorer автоматически
не завершается. На других версиях Windows изменение загрузочной оболочки запрещено
самой программой; пользовательские настройки панели при этом доступны.

Перед первой сменой создаются файлы в каталоге Windows:

- `EX95BAK.INI` — полная исходная копия SYSTEM.INI;
- `EX95REC.INI` — исходная команда оболочки и путь установленной программы.

Не удаляйте их до восстановления штатной оболочки. Программа отказывается заменять
неизвестную существующую резервную копию и не перезаписывает оболочку, которую после
неё выбрала другая программа.

**Восстановление из DOS:** откройте SYSTEM.INI в каталоге установленной Windows
(например, `C:\WIN95` или `C:\WINDOWS`) и восстановите только строку `shell=` в секции
`[boot]`, взяв её исходное значение из EX95BAK.INI. Для обычной установки это
`shell=Explorer.exe`. Сохраните файл и запустите Windows снова. Не восстанавливайте
весь старый INI поверх более новых системных настроек без необходимости.

## Управление и настройки

- Start → `Exit`: закрыть Explorer95; для основной оболочки требуется подтверждение.
- Правый щелчок по свободной области панели: блокировка, автоскрытие, размер,
  положение, быстрый запуск, свойства и показ/восстановление рабочего стола.
- Сняв блокировку, тяните свободную область панели к нужному краю экрана;
  её внутреннюю границу можно тянуть для изменения толщины.
- Часы: двойной щелчок открывает системные настройки даты и времени.
- Win+D и Ctrl+Esc работают, если эти сочетания доступны для регистрации.
- В файловом окне: Enter/Go — перейти; F5 — обновить; Alt+Up — вверх;
  Ctrl+L/F4 — адрес; Enter/двойной щелчок в списке — открыть объект.
- Пути с пробелами в Run заключайте в кавычки:
  `"C:\Program Files\Example\app.exe" argument`.
- **Environment Properties** — одно окно для Taskbar, Start Menu, Desktop,
  Notifications и System Shell. Во вкладке Start Menu есть General, Advanced и
  Pinned programs. Все вкладки используют общие **OK / Cancel / Apply**: Apply
  сохраняет без закрытия, Cancel отменяет только ещё не применённые изменения.
  Очистка списков также ждёт Apply. Настройки файлового Проводника остаются в
  **Tools → Folder Options / Customize Toolbar**.
- **Start Menu → General**: надпись кнопки, малые/крупные значки, число недавних
  программ и выбор двухколоночного или классического одноколоночного меню.
  Fits on this screen учитывает размер экрана, значки, черновик закреплений
  и ещё не применённое положение/число строк панели задач.
- **Internet / E-mail**: необязательные верхние закрепления. Выберите программу
  из обнаруженных зарегистрированных приложений или кнопкой **...**. Они входят
  в общий предел шести закреплений; системные ассоциации Windows не меняются.
- **Start Menu → Advanced**: видимость команд, Favorites и режим **Link / Menu /
  Hidden** для папок, включая Control Panel и My Computer. В меню My Computer
  показываются буквы дисков без чтения меток или содержимого носителей.
  В двухколоночном стиле можно открывать подменю наведением и разрешить добавление
  программ/ярлыков перетаскиванием на открытый «Пуск». Классический стиль использует
  штатные компактные меню Windows, поэтому параметры размера значков, числа
  недавних программ, hover и drop для него отключены.
- **Highlight new shortcuts** выделяет новые ярлыки в меню программ: созданные
  после первого запуска Explorer95 и ещё не открытые через это меню. Это учёт
  ярлыков, а не слежение за установщиками. **Clear recent documents** очищает
  системный список через Shell32, сохраняя сами документы.
- **Start Menu → Pinned programs**: Browse выбирает файл, Add добавляет запись;
  Remove / Move up / Move down меняют порядок. История программ и закрепления
  остаются отдельными списками. Очистка истории не удаляет закрепления.
- **Desktop**: видимость и автоматическое выравнивание значков, немедленная команда
  Line up icons now, запуск штатного `desk.cpl` для фона, цветов и заставки.
  Скрытие значков сохраняет рабочий стол и его обои. Системное окно дисплея
  применяет свои изменения самостоятельно.
- Правый щелчок по недавней программе → Pin to Start menu; правый щелчок
  по закреплению → Unpin from Start menu. Изменение сохраняется сразу, включая
  аргументы запуска, и не удаляет программу с диска.
- Во вкладке Taskbar можно открыть папку Quick Launch; часы, таймаут и правила
  значков находятся в Notifications. System Shell содержит установку/восстановление
  загрузочной оболочки с прежними отдельными подтверждениями.
- Если Windows 95 отклоняет прямой Log Off с `Incorrect Function`,
  Explorer95 предлагает штатный системный диалог. В нём выберите выход и вход
  другим пользователем. Доступность этого режима зависит от конфигурации Windows;
  принудительное завершение программ или перезагрузка вместо выхода не выполняются.

Настройки по умолчанию лежат в `Explorer95\Explorer95.ini` внутри папки данных
пользователя, возвращённой Shell32; рядом находится папка `Quick Launch`.
Для отдельного профиля можно указать существующий каталог:

```text
explorer95.exe --settings="C:\EX95\Explorer95.ini"
```

Применение окружения сохраняет `[Taskbar]`, `[Start]`, `[Desktop]`, `[Pinned]`
и `[TrayPolicies]` вместе через временный файл в каталоге профиля. При ошибке записи
живые параметры не меняются; существующие секции Проводника и другие неизвестные
параметры сохраняются. В новых ключах `[Start]` хранятся `Classic`, `HoverMenus`,
`AllowDrop`, `HighlightNew` и `FolderMenus` (биты папок соответствуют VisibleItems).
`[Desktop]` содержит `ShowIcons` и `AutoArrange`; `[Taskbar] InactiveSeconds` — таймаут
трея. У закреплений `ClientN=1/2` обозначает Internet/E-mail. Старые INI продолжают
работать без ручной миграции. `[SeenShortcuts]` хранит ограниченный список из 64
открытых пунктов для подсветки новых ярлыков.

## Параметры Проводника

Раздел `[Explorer]` в том же INI не связан с размером значков «Пуска» или Quick Launch:

```ini
[Explorer]
View=0
Folders=0
FolderWidth=180
Toolbar=1
AddressBar=1
StatusBar=1
TextLabels=1
LargeToolbarIcons=1
ShowHidden=0
ShowExtensions=1
ToolbarButtons=0
```

`View`: 0 — Icons, 1 — Small Icons, 2 — List, 3 — Details, 4 — Tiles,
5 — Thumbnails. `FolderWidth` ограничен 120–400 пикселями и доступной шириной окна.
`ToolbarButtons` — сумма флагов: Copy=1, Cut=2, Paste=4, Delete=8,
Properties=16, Folder Options=32; все шесть — 63. Избранные пути хранятся
в `[ExplorerFavorites]` как `Folder0`…`Folder7`.

Клавиши: Alt+Left / Alt+Right — история, Alt+Up / Backspace — выше,
F3 — системный поиск, F5 — обновление, F2 — переименование,
Alt+Enter — свойства, Ctrl+C / X / V / A — файловые операции,
Ctrl+L / Alt+D — адрес, F4 — список адресов.

## Сборка и проверки

Нужны GNU Make и 32-битный MinGW-w64 GCC (`gcc-mingw-w64-i686` на Debian/Ubuntu).
Также нужен `i686-w64-mingw32-windres` (из binutils-mingw-w64-i686) для BMP-ресурса.
Python 3 нужен для проверки структуры EXE.

```sh
make check
# Или, если компилятор имеет суффикс -win32:
make check CC=i686-w64-mingw32-gcc-win32
```

Результат: `build/explorer95.exe`. Это PE32 для x86/i386 с Windows GUI/OS 4.0,
ANSI Win32 API и без MSVCRT/UCRT, .NET или движка тем.
Флажок использует цветовой ключ `RGB(192,192,192)`: TransparentBlt загружается
динамически из системной MSIMG32.DLL, если она установлена. В чистой Windows 95
этой функции нет; используется эквивалентная GDI-маска без обязательной зависимости
от MSIMG32. Сам bitmap встроен в EXE и не нужен отдельным файлом. Shell32 и COM используются
через базовые интерфейсы; IE4 и Active Desktop не требуются.

В текущей облачной среде:

```sh
make check CC=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-gcc-win32 \
  WINDRES=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-windres
```

Сборка инкрементальная: каждый C-файл компилируется отдельно, зависимости от
заголовков создаются автоматически. x86 и x64 используют разные объекты; тесты
повторно используют объекты общих модулей. Изменение компилятора или флагов
сбрасывает соответствующие объекты. Для обычной правки `make clean` не нужен.
Можно использовать `make -j2 check` для параллельной сборки. Если установлен ccache,
`make -j2 check CCACHE=ccache` включает кэш компиляции; в CI он сохраняется между
запусками отдельно для каждой архитектуры. Первый запуск с новым кэшем — холодный.

Для небольших изменений выбирайте относящиеся к ним проверки:

| Команда | Объём |
| --- | --- |
| `make layout` | Расчёт геометрии «Пуска» на обычном C-компиляторе, без Wine и запуска оболочки. |
| `make ui64-smoke TEST_GROUP=menu` | Общее окно настроек, Apply/Cancel/ошибка записи, геометрия, закрепления, оба стиля «Пуска» и подменю. |
| `make ui64-smoke TEST_GROUP=browser` | Навигация, файловые операции, режимы, дерево и отрисовка системных папок. |
| `make ui64-smoke TEST_GROUP=core` | Геометрия, отрисовка флажка, фильтрация истории и установка shell на временных файлах; EXE приложения не требуется. |
| `make ui64-smoke` | Полный сценарий, включая панель задач, трей, выход и повторный запуск. |

У `make smoke` для x86 те же значения `TEST_GROUP`. По умолчанию всегда `full`;
неизвестное имя завершает тест с ошибкой. Wine-группам нужен дисплей, например
`xvfb-run -a make ui64-smoke TEST_GROUP=menu WINE=wine64`; используйте отдельный
одноразовый Wine prefix. `make layout` использует те же случаи геометрии,
что включены в полный Windows smoke-тест, и не заменяет визуальную проверку.
Для изменения ширины меню достаточно `make layout`, сборки/PE-проверки и группы
`menu` с визуальной проверкой обоих размеров значков на маленьком и обычном экране.

Сама инфраструктура проверяется командами
`python3 -m unittest discover -s tests -p test_select_checks.py` и `make check-build`.
Последняя собирает маленький пример по настоящему Makefile во временном каталоге:
проверяет отсутствие лишней компиляции и обновление объектов при изменении C-файла,
заголовка, флагов и bitmap, не меняя рабочие исходники.

В одноразовом Windows/Wine-окружении с поддержкой 32-битных приложений и дисплеем:

```sh
make smoke
```

Тест создаёт свой профиль и временные файлы, проверяет навигацию, рабочий стол,
первичную отрисовку системных папок и сохранение значков после перерисовки
только родительского окна, прозрачность флажка на цветном фоне через TransparentBlt
и запасной GDI-путь, крупные значки и их сохранение, фильтрацию ярлыков
и очистку прежней истории, контекстное закрепление/открепление,
Run, историю, закрепления и их аргументы/порядок, отмену редактирования,
подпись Start, скрытие команд, общее окно настроек, Internet/E-mail, классический стиль,
подменю при наведении, режимы папок, сохранение секции Explorer, видимость рабочего стола,
отказ записи в read-only профиль, отдельные политики трея, быстрый запуск, группировку, уведомления трея, Show Desktop,
сохранение настроек, края экрана и автоскрытие. Расчёт геометрии проверяется
для 320×240, 640×480, 800×600, 1024×768, 1280×720 и 1920×1080, трёх высот
шрифта, обоих размеров значков и всех четырёх положений панели; отдельно проверяется, что реальное окно
«Пуска» и его видимые кнопки помещаются рядом с панелью на каждой стороне экрана. Backend установки/восстановления
оболочки проверяется **только на временных INI-файлах**, не на системном SYSTEM.INI;
также проверяется установка рядом с заблокированным EXE и обновление с сохранением
первой резервной копии. Реальное завершение сеанса и загрузка Win95 требуют проверки в ВМ.
Размер значков во вложенных списках программ/документов и сходство с референсом
дополнительно проверяйте визуально. Перед тестом закройте другие экземпляры Explorer95.

Если хост не исполняет 32-битные процессы, доступна тестовая сборка того же кода:

```sh
make ui64-smoke WINE=wine64
```

Для неё нужен `x86_64-w64-mingw32-gcc`. Файлы из `build/ui64` не предназначены для
Windows 95. Проверка пакетов трея под Wine проверяет регистрацию и callbacks;
передача HICON между процессами Wine отличается от Windows 95 и отдельно не
подтверждена этим тестом.

`make check` проверяет заголовки PE и разрешённые импорты; это не доказательство
полной совместимости с Windows 95. UI-группы CI выполняются от обычного пользователя
под Wine 10/x64 в Debian 13, включая прежний пятисекундный предел выхода.

GitHub Actions запускает проверки при push в `main` и для pull request. Отдельный
workflow `Win32 build` можно запустить вручную с нужной группой; по умолчанию `full`.
`tests/select_checks.py` выбирает проверки по изменённым путям: документация
пропускает сборку и Wine, модули «Пуска» выбирают `menu`, файлового браузера —
`browser`, backend установки shell — `core`. Общие модули, ресурсы, тесты,
Makefile, workflows, неизвестные пути и смешанные изменения запускают `full`.
Это консервативный выбор по файлам: внутри файла он не различает правку отступа
и изменение поведения. Для рискованной правки вручную выбирайте полный прогон.

Устаревшие CI-запуски одной ветки/PR отменяются. Итоговый job `Checks` учитывает
ошибки выбранных проверок и корректно пропущенные задания; его можно использовать
как обязательную проверку ветки. Логи Wine сохраняются в artifacts и при ошибке.
На `main` сравнение идёт с последним успешным автоматическим прогоном, а в PR —
со всей базовой веткой. Поэтому быстрая следующая отправка документации не скроет
изменения кода из отменённого или неуспешного прогона. Если базу найти не удалось,
запускается полный набор; ручной частичный прогон базой не считается.
Теги `v*` запускают только release workflow: сборка x86 и полный UI-прогон идут
параллельно, а публикация EXE, ZIP и SHA256 ждёт успеха обоих. Дублирующего
запуска обычного build workflow на тег больше нет. Документационная или
инфраструктурная правка сама по себе не требует нового бинарного релиза.

Остаются ограничения: эскизы JPEG/PNG и XP-панель задач папки не реализованы;
группировка выполняется по процессу; не реализованы полный shell DDE/appbar-сервер
для сторонних панелей, расширенные уведомления и все внутренние протоколы Explorer.
Новый вариант замены оболочки необходимо проверить при реальной загрузке Win95 RTM/OSR2.
