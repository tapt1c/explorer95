# Explorer95

Независимая любительская реализация оболочки в духе Windows XP для Windows 95.
Только классическое оформление: системные цвета, шрифты и элементы Win32,
без Luna и без ресурсов или кода Microsoft Explorer.

Это **ранний прототип**, пока не замена системного `explorer.exe`.

Уже реализовано:

- панель задач с кнопками открытых окон и часами; восстановление свёрнутых окон;
- двухколоночный «Пуск» с системными папками, панелью управления и выходом;
- диалог Run с запуском программ, аргументами и раскрытием переменных окружения;
- файловые окна с адресной строкой, списком дисков и ярлыками системных папок;
- список файлов с иконками, типом и размером, сортировкой папок перед файлами;
- открытие папок и файлов двойным щелчком или Enter, переход вверх, обновление;
- несколько независимых файловых окон и сообщения об ошибках навигации.

`All Programs` пока открывает папку ярлыков пользователя, а `My Computer` —
корень системного диска со списком остальных дисков слева. Это временные
упрощения, а не реализация виртуальных папок оболочки XP.

## Сборка

Нужны GNU Make и 32-битный MinGW-w64 GCC. Python 3 нужен только для проверки EXE.
На Debian/Ubuntu пакет компилятора называется `gcc-mingw-w64-i686`.

```sh
make
make check
```

Результат: `build/explorer95.exe`. Перенеси его на тестовую Windows и запусти.
При наличии только компилятора с суффиксом `-win32`:

```sh
make check CC=i686-w64-mingw32-gcc-win32
```

В текущей облачной среде инструменты установлены локально, вне репозитория:

```sh
make check CC=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-gcc-win32
```

Программа использует ANSI Win32 API, базовые common controls и собственную точку
входа без C runtime. Сборка нацелена на x86 с набором инструкций i386, PE32 и
Windows GUI/OS 4.0. Не требуются MSVCRT, UCRT, .NET, Internet Explorer 4 или движок тем.

`make check` проверяет формат PE, версию подсистемы и консервативный список
допустимых импортов. **Эта проверка не доказывает работоспособность на Windows 95.**
Реальный запуск на Windows 95 RTM/OSR2 пока не проверен. Готовность полноценной
замены оболочки также не заявляется.

## Запуск и управление

Прототип работает рядом со штатной оболочкой. Его панель располагается над
существующей панелью задач; глобальная рабочая область и настройки shell не меняются.
Не назначай этот прототип системной оболочкой.

- «Пуск» → `Exit Explorer95`: закрыть прототип вместе с его окнами.
- Контекстное меню на свободном месте панели задач: сведения и выход.
- Двойной щелчок по диску слева: открыть диск.
- Enter в адресной строке или `Go`: перейти к папке; относительные пути
  разрешаются относительно текущего файлового окна.
- F5: обновить; Alt+Up: родительская папка; Ctrl+L или F4: адресная строка.
- Enter или двойной щелчок в списке: открыть выбранный объект.
- Escape: закрыть «Пуск» или Run. Tab: перемещение между элементами управления.
- В Run заключай пути с пробелами в кавычки: `"C:\Program Files\Example\app.exe" argument`.

Интерфейс пока на английском. Имена файлов обрабатываются в системной ANSI
кодировке Windows 95; Unicode и пути длиннее `MAX_PATH` не поддерживаются.

## Проверки интерфейса

В отдельном Wine-префиксе с поддержкой 32-битных приложений и работающим дисплеем:

```sh
make smoke
```

Тест запускает свой экземпляр приложения и создаёт временные папки. Он проверяет
перечисление файлов, сортировку, Enter, относительные пути, пустые папки, переход
вверх, ошибку несуществующего пути, Refresh, «Пуск», Run с аргументами и
восстановление окна через панель задач. Перед запуском закрой другие экземпляры
Explorer95. Запускай тест в одноразовой VM/префиксе, а не на рабочем столе с важными окнами.

Если Linux-хост не исполняет 32-битные процессы, есть отдельная тестовая сборка:

```sh
make ui64-smoke WINE=wine64
```

Для неё нужен `x86_64-w64-mingw32-gcc`. Она проверяет поведение того же исходного
кода под 64-битным Wine. Файлы из `build/ui64` **не предназначены для Windows 95**.
В текущей облачной среде этот сценарий выполнен успешно; основной 32-битный EXE
собран и прошёл проверку PE, но его исполнение здесь не проверено.

GitHub Actions собирает 32-битный EXE и проверяет его импорты; GUI-тесты в CI
пока не запускаются.
