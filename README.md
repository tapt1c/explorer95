# Explorer95

Любительская оболочка в духе Windows XP для Windows 95: классическое оформление,
рабочий стол, панель задач, двухколоночный «Пуск» и отдельные окна Проводника.
Luna не используется. Цвета, шрифты и системные значки берутся из установленной Windows;
флажок кнопки Start — приложенный пользователем Bitmap143.bmp.

Проект остаётся экспериментальным. Новую версию сначала проверяйте в виртуальной
машине: реальная загрузка Windows 95 с Explorer95 в качестве shell здесь ещё не проверена.

В `v0.7.0-alpha.1` обнаружен блокирующий запуск дефект: импорт
`USER32.DLL:EndMenu`, отсутствующий в Windows 95. Он удалён в `v0.7.0-alpha.2`;
для закрытия классического «Пуска» используется сообщение `WM_CANCELMODE`.
Если вы получили указанную ошибку загрузчика, замените EXE исправленной версией.

В `v0.9.0-alpha.8` обнаружен stack fault при запуске на Windows 95:
обработчик системного ListView повторно вызывал сам себя через
`LVM_GETEDITCONTROL`. В `v0.9.0-alpha.9` запрос выполняется только после проверки
сообщения открытия. При stack fault по адресу `00428CD7` в alpha.8 замените EXE;
это ошибка программы, увеличивать стек или менять системные DLL не требуется.

## Что реализовано

- **Рабочий стол:** системное представление `IShellView` из Shell32, значки,
  открытие объектов, выделение, перетаскивание и системные контекстные меню.
  Поддерживаются цвет фона и BMP-обои из параметров Windows, центрирование и мозаика.
  Delete удаляет выбранные значки через системную команду Shell32 со штатным
  подтверждением; при редактировании подписи клавиша продолжает удалять текст.
- **Своя расстановка значков:** свободное перемещение одного или нескольких
  выделенных значков левой кнопкой, сохранение относительного расположения группы,
  отмена по Escape или правому щелчку. Во время переноса за мышью плавно следует
  полупрозрачный образ; реальные значки перемещаются при отпускании кнопки.
  Сетка применяется только к конечной позиции. Занятые места освобождаются сдвигом
  пересекающихся значков на свободные позиции с учётом подписей; если места нет,
  весь перенос отменяется. Позиции восстанавливаются после перезапуска
  и обновления рабочего стола. При F5 и Refresh Desktop промежуточная раскладка
  Shell32 не перерисовывается: сначала восстанавливаются сохранённые позиции,
  затем обновляется изображение значков. Для нового профиля Auto Arrange выключен.
  Доступны блокировка позиций, привязка к сетке и отдельный горизонтальный/
  вертикальный шаг 64–200 пикселей. Все параметры находятся в **Desktop** общих
  настроек и в **Icon Layout** контекстного меню рабочего стола.
- **Контекстное меню рабочего стола:** команды установленной Shell32, включая
  доступные в ней команды буфера обмена и свойства; дополнительно — упорядочивание,
  системное меню New, подменю Explorer95 с настройками панели
  и отдельный пункт **Desktop Background / Display Properties...**, вызывающий `control.exe desk.cpl`.
  Состав и язык системных команд зависят от версии Shell32. «Свойства» Windows
  позволяют менять оформление и фон средствами самой Windows 95.
- **Панель задач:** кнопки окон, восстановление и сворачивание, системное меню окна
  по правому щелчку, группировка окон одного процесса, часы и «Показать рабочий стол»
  с восстановлением ранее свёрнутых этой командой окон. Компактная классическая
  панель с кнопкой Start в классических пропорциях (54×22 при стандартном
  шрифте; при крупных значках Quick Launch высота совпадает с кнопками задач),
  штатной системной рамкой, малым флажком 16×16 и жирным шрифтом
  системных заголовков. При нажатии флажок и надпись смещаются вместе на один
  пиксель. Поддерживаются значки окон и утопленная
  область часов; формат времени берётся из региональных настроек Windows.
  Группа собственных окон файловых и системных папок называется Windows Explorer;
  одиночная кнопка и пункты группы сохраняют названия папок.
- **Отрисовка:** панель задач, её кнопки, «Пуск» и пункты меню рисуются через
  сохраняемые GDI-буферы; обои рабочего стола кэшируются до изменения фона или
  размера. Закрытие перекрывающих меню не требует предварительной заливки пустым
  фоном. Повторное применение настроек не рассылает изменение рабочей области,
  если она прежняя; переключение значков рабочего стола не перестраивает панель
  задач и системные папки. При неизменившихся размерах shell view и контролы
  не перерисовываются; таймер трея обновляет раскладку только при изменении
  видимости значков. Настройки сохраняют пиксели кнопок и предпросмотров во время
  стирания фона, отдельно заполняя прозрачные области вкладок и рамок групп.
  Уведомление о системных цветах не пересоздаёт toolbar и не заполняет список
  Проводника заново: существующие контролы получают WM_SYSCOLORCHANGE, включая
  уведомления для палитровых дисплеев. Повторный расчёт размеров не рисует
  промежуточную высоту toolbar. Это уменьшает мерцание собственных элементов оболочки; перерисовкой
  сторонних приложений по-прежнему управляют Windows и сами приложения.
- **Порядок окон:** полноэкранный рабочий стол удерживается под прикладными
  окнами до изменения Z-order и после завершения активации, включая её потерю. Контекстное
  меню рабочего стола использует панель задач как владельца и не поднимает обои
  поверх Проводника; системные расширения меню продолжают получать свои сообщения.
  Режим панели «поверх окон» задаётся до создания её всплывающих окон. «Пуск»
  показывается до передачи ему фокуса, а изменение его геометрии не меняет порядок окон;
  закрытое меню не должно оставаться поверх содержимого Проводника.
- **Настройки панели:** четыре стороны экрана, перетаскивание незаблокированной
  панели к краю, изменение толщины с привязкой к трём размерам, одна–три строки,
  ширина кнопок, блокировка, автоскрытие, положение поверх окон, часы,
  быстрый запуск, размер его значков и скрытие неактивных уведомлений.
  Настройки сохраняются между запусками и доступны в общем окне Environment Properties.
  Предпросмотр во вкладке Taskbar использует ту же отрисовку Start и кнопок окон,
  что настоящая панель: системные рамки, жирный шрифт Start и исходный флажок 16×16.
  Он учитывает черновик подписи Start, Quick Launch, размер его значков,
  группировку, ширину кнопок и видимость часов.
- **Быстрый запуск:** значки программ/ярлыков из папки Quick Launch; добавление
  перетаскиванием файла на панель задач создаёт ярлык, исходный файл сохраняется.
  Кнопки плоские в покое, с объёмной подсветкой при наведении и нажатии, в том
  числе на исходной Windows 95 без поддержки BS_FLAT. Разблокируйте панель задач
  и потяните ручку справа от Quick Launch (снизу на вертикальной панели), чтобы
  изменить размер только этого участка. Escape отменяет перенос; после отпускания
  размер сохраняется в `[Taskbar] QuickLaunchSize` и восстанавливается при запуске.
  Значение `0` означает автоматический размер; уменьшение разрешения временно
  ограничивает видимый размер, сохраняя предпочтение. Не поместившиеся команды
  доступны через `>>` со значками 16×16. Для дополнительных элементов можно открыть
  саму папку через меню панели.
- **Трей:** приём базового ANSI-протокола уведомлений Windows 95: `NIM_ADD`,
  `NIM_MODIFY`, `NIM_DELETE`, значки, подсказки и обратные сообщения мыши приложению.
  Скрытые и не поместившиеся уведомления доступны через кнопку `>`. Во вкладке
  Notifications для каждого приложения выбирается Hide when inactive / Always show /
  Always hide, а время неактивности настраивается от 5 до 3600 секунд. Правила
  запоминаются по программе, классу окна и ID уведомления, а не по временному HWND.
  Значки остаются 16×16; при достаточной высоте панели размещаются в две строки.
  Область часов сохраняет прежние размеры и положение справа.
- **Пуск:** заголовок с именем пользователя, отдельный список закреплённых программ
  (по умолчанию Explorer и MS-DOS Prompt), последние программы слева, дерево
  All Programs с вложенными папками и значками программ, ярлыков и папок; справа — документы,
  недавние документы, компьютер, сеть, панель управления, принтеры, помощь, поиск и Run.
  Внизу — выход из Explorer95, завершение сеанса и отдельное окно завершения работы.
  Левая и правая клавиши **Win** открывают и закрывают «Пуск» при отпускании;
  Win+D и Ctrl+Esc сохраняют своё действие. Это работает и с классическим меню.
  **Network Neighborhood** автоматически скрывается без установленного сетевого
  компонента, **Log Off** — без профилей пользователей и сетевого провайдера входа
  Windows 95. Отключённый кабель не скрывает сеть. Учитываются системные запреты
  NoNetHood/NoLogoff; галочки видимости в профиле Explorer95 сохраняются.
  Значки системных команд извлекаются по ID ресурса, чтобы порядок значков
  в разных версиях Shell32 не подменял их случайными картинками.
- **Shut Down:** компактное окно 314×200 пикселей с тремя действиями
  Stand By / Turn Off / Restart и кнопкой Cancel. В Environment Properties →
  Desktop → **Shutdown dialog style** можно выбрать Windows XP (синий заголовок,
  градиент, цветные значки 32×32) или Windows 95 (системная рамка, серый фон,
  объёмные кнопки и встроенные значки Shell32 32×32). По умолчанию выбран XP;
  стиль сохраняется кнопкой Apply / OK (`[Desktop] ClassicShutdown=0/1`). При открытии снимок рабочего стола плавно темнеет и теряет насыщенность;
  окно удерживает фокус, перекрывает фон и блокирует ввод в остальные окна Explorer95.
  Слой затемнения независим от всплывающих окон панели и располагается сразу под
  диалогом, чтобы сторонние окна «поверх всех» не оставались поверх снимка.
  Tab, Space и Enter работают с кнопками, Cancel / Esc / Alt+F4 возвращают рабочее
  окружение без изменения его настроек. Удерживайте Shift, чтобы заменить Stand By
  на Hibernate. Доступность сна зависит от Windows, драйверов и APM/оборудования:
  отсутствующие режимы отключены; стандартная Windows 95 обычно не предоставляет
  программного Hibernate. Необязательные API питания загружаются динамически.
  Выключение и перезапуск используют обычный ExitWindowsEx без принудительного
  закрытия программ; перед этим затемнение убирается, чтобы приложения могли
  показать вопросы о сохранении. Действия питания включены только на Windows 95.
  Поведение Log Off сохранено.
- **Настройки «Пуска»:** произвольная надпись на кнопке, галочки для команд
  справа и трёх команд внизу; добавление до шести закреплений с именем и аргументами,
  выбор EXE/ярлыка через Browse, удаление и перестановка. Список закреплений
  хранится отдельно от истории. У недавней программы правый щелчок →
  **Pin to Start menu**, у закреплённой → **Unpin from Start menu**.
  Между списками виден разделитель; закреплённая команда не дублируется в недавних.
- **Крупные значки «Пуска»:** Environment Properties → Start Menu → General →
  **Large icons** переключает значки с 16×16 на 32×32: закрепления, недавние программы,
  системные команды и кнопки All Programs / Recent Documents в основном меню.
  В раскрывающихся списках программ, недавних документов и их вложенных папках
  значки всегда 16×16, независимо от этой настройки. Загружаются соответствующие
  ресурсы значков, а не растягиваются малые. В нижней панели Exit / Log Off / Shut Down
  значки всегда 16×16, а высота панели не зависит от режима значков.
  Ширина основного меню — 370 пикселей
  с малыми значками и 410 с крупными (при достаточной ширине экрана); число
  видимых пунктов пересчитывается по экрану. Размер Quick Launch настраивается отдельно.
- **Число недавних программ:** параметр Recent programs в настройках «Пуска»,
  включая 0 для скрытия списка. Верхний предел рассчитывается по разрешению,
  рабочей области, положению панели, высоте шрифта и числу закреплений
  (история хранит до 30 команд, по умолчанию показываются до семи). При уменьшении
  экрана число видимых строк сокращается автоматически; скрытые записи не удаляются.
  Высота «Пуска» не выходит за доступную область. На очень маленьком экране или
  при крупном шрифте не поместившиеся закрепления и системные команды доступны
  через More pinned / More.
- **История программ:** успешные запуски через Run, файловые окна, меню программ,
  быстрый запуск и файловые значки нашего рабочего стола. Аргументы Run сохраняются.
  Документы, ярлыки на документы/папки и объекты из Recent Documents в неё не входят:
  для .lnk проверяется цель. Старые неподходящие записи автоматически убираются,
  порядок и аргументы оставшихся программ сохраняются. Это история запусков через
  Explorer95, а не глобальное наблюдение за всеми процессами.
- **Проводник:** классическая компоновка XP — File / Edit / View / Favorites /
  Tools / Help, панель инструментов, раскрывающаяся адресная строка, переключаемая
  левая панель Tasks / Folders / Search / History и строка состояния. Обычные каталоги и системные папки, включая
  «Мой компьютер» и панель управления, используют одинаковое обрамление.
  Содержимое виртуальных папок остаётся настоящим представлением Shell32.
  Открытие диска или панели управления из «Моего компьютера» продолжает навигацию
  в том же окне Explorer95, включая двойной щелчок и Enter.
  Апплеты Панели управления выполняют штатное действие Shell32; они не принимаются
  за папки по признакам родительского «Моего компьютера» в старой Windows 95.
- **Навигация:** Back, Forward и Up; отдельная история до 32 переходов на окно,
  списки переходов рядом с Back/Forward, относительные пути и переменные окружения
  в адресе. Toolbar по умолчанию: Back, Forward, Up, Search, Folders, History, Refresh, Views;
  подписи остаются у Back, Search, Folders и History. Навигационные значки рисуются через GDI;
  при поддержке Common Controls рядом с Back/Forward доступны стрелки истории,
  на исходной Win95 список переходов открывается правым щелчком.
  Дополнительные файловые команды включаются отдельно.
  В адресной строке показан значок текущей папки. Раскрывающийся список содержит
  системные места, назначенные диски, иерархию текущего пути и недавние переходы
  этого окна — со значками и отступами. Открытие списка не читает содержимое
  накопителей. Enter открывает выбранное место в том же окне, Escape сохраняет
  набранный адрес; относительные пути и переменные окружения остаются доступны.
  Изменение размеров перерисовывает перемещённые контролы без копирования старых
  пикселей соседей; значок адреса защищён от перерисовки поля и раскрытия списка.
  Смена боковой панели и размещение контролов сохраняют предыдущий готовый кадр
  до завершения всей операции, затем перерисовывают рамку и дочерние элементы вместе.
- **Поиск:** Search / F3 / Ctrl+E открывает встроенную панель поиска по части имени
  или маске `*` / `?`. Look in задаёт папку, Include subfolders включает её обход.
  Результаты открываются отдельным окном с системными значками и колонками Name /
  In folder / Type. Двойной щелчок или Enter открывает файл/папку; Open containing
  folder показывает каталог и выделяет найденный объект в исходном окне.
  Show results повторно показывает список, закрытие окна останавливает поиск.
  Поиск работает порциями, Stop / Escape закрывает перечисление.
  Максимум 1024 результата и 64 уровня вложенности; пропущенные папки и ограничение
  показываются в статусе. Чужие накопители без явного выбора не обходятся.
- **История папок:** View → History / Ctrl+H показывает до 32 последних мест
  из текущего профиля, включая поддерживаемые системные папки. Записи сохраняются
  между запусками, Clear history очищает список. Tools → Folder Options →
  Remember visited folders отключает запись и удаляет сохранённые посещения.
  Back/Forward текущего окна продолжает работать в памяти независимо от этой настройки.
- **Панель действий:** Common Tasks включена по умолчанию. «Мой компьютер» показывает
  System Tasks, Other Places и Details; диск — также File and Folder Tasks и сведения
  о томе. При выделении появляются Move/Copy, Rename, Delete и Properties по
  возможностям объекта. Move/Copy открывает штатный выбор папки назначения.
  Hide the contents скрывает представление только в текущем окне, без изменения
  атрибутов или прав. Группы сворачиваются; команды доступны с клавиатуры.
  Видимый разделитель меняет ширину любой левой панели, включая Common Tasks;
  Escape отменяет изменение. Крестик и стрелки сворачивания используют Marlett
  (при отсутствии шрифта — GDI),
  между toolbar, адресом и содержимым расположены классические разделители.
  Folders / Search / History имеют единый неподвижный заголовок с системным
  шрифтом малого окна, цветами активного/неактивного заголовка и кнопкой закрытия.
  Крестик возвращает Common Tasks; прокрутка содержимого не сдвигает заголовок.
  Во время перемещения ползунка строки задач перерисовываются до возврата в
  системный цикл прокрутки Windows 95; отпускать мышь для появления текста не
  требуется. Прокрутка перемещает готовое содержимое без повторного расчёта строк.
  Скроллбары панелей и списков Search / History появляются только при переполнении.
  Share / Publish / E-mail появляются только при наличии соответствующего действия
  установленной Shell32; Shared Documents — только если система предоставляет такую папку.
- **Папки:** дерево Desktop / My Documents / My Computer / накопители / Control
  Panel / Network Neighborhood / Recycle Bin, изменяемая ширина и кнопка закрытия.
  Включение панели и раскрытие My Computer получают только назначенные буквы
  дисков; чтение содержимого, томов и извлечение значков по путям накопителей
  не выполняются. Каталог читается только при его открытии или явном раскрытии;
  вложенные папки не обходятся заранее. Поэтому включение Folders само по себе
  не должно обращаться к пустому дисководу.
- **Вид и инструменты:** Icons, Small Icons, List, Details, Tiles и Thumbnails
  для файловых папок; сортировка по имени, типу, размеру и дате. Плитки показывают
  имя, тип и размер. Эскизы используют встроенный загрузчик BMP, ограничены
  файлами до 1 МиБ и кэшем до 128 изображений; прочие форматы сохраняют системные
  значки. В виртуальных папках доступны четыре штатных режима установленной
  Shell32. Все значки берутся из Windows, отдельные XP-ресурсы не нужны.
- **Операции с файлами:** стандартный файловый буфер обмена Copy / Cut / Paste,
  множественное выделение, Delete через системную корзину (Shift+Delete — без неё),
  переименование, новая папка, системные контекстные меню и штатные свойства
  Windows 95. Скрытие расширений меняет только надпись; переименование сохраняет
  скрытое расширение. Изменения открытого каталога отслеживаются без F5 с сохранением
  выделения; остальные накопители для этого не опрашиваются.
- **New на свободном месте:** в обычных каталогах и в запасном меню рабочего
  стола варианты создания читаются из тех же регистраций `HKEY_CLASSES_ROOT`
  `ShellNew`, что и в штатном Explorer. Поддерживаются `NullFile`, бинарные `Data`,
  шаблоны `FileName` и зарегистрированные команды `Command` (в том числе мастер
  ярлыков). Список обновляется при каждом открытии меню, существующие файлы не
  перезаписываются. Встроенное меню New установленной Shell32 на рабочем столе
  сохраняется, если она его предоставляет. CLSID-разделы используют свои
  системные меню; файловые шаблоны туда не добавляются.
- **Очистка корзины:** при открытии Recycle Bin появляется кнопка **Empty Recycle
  Bin**, та же команда есть в File. Пустая корзина отключает команду. Используются
  штатное подтверждение и обработка Windows; отмена сохраняет содержимое.
  Очистка передаётся команде Delete системного меню выбранных объектов
  с выделением всей Корзины; если меню не предоставляет команду, используется
  обработчик клавиши самого shell view. Зависимости от `SHEmptyRecycleBinA`
  или IE4 нет.
  Выбранные объекты удаляются тем же системным обработчиком; восстановление
  доступно в их штатном контекстном меню. Список, кнопка очистки и задачи слева
  обновляются после удаления и восстановления без F5. Обычные команды переноса,
  копирования, вставки и переименования для удалённых объектов отключены.
  В адресной строке можно ввести `Recycle Bin`, чтобы открыть корзину.
- **Настройка Проводника:** Tools → Folder Options / Customize Toolbar или правая
  кнопка на панели. Можно включать только шесть дополнительных команд: Copy, Cut,
  Paste, Delete, Properties, Folder Options. Настраиваются подписи, размер значков
  панели, скрытые/системные файлы, расширения, режим просмотра и панель Folders.
  View позволяет скрывать панель инструментов, адрес и строку состояния.
  Избранное хранит до восьми файловых папок. Настройки применяются к текущему
  окну и новым окнам; уже открытые другие окна сохраняют свой вид.
  Родительское окно отсекает дочерние области при перерисовке, чтобы значки
  системных папок были видны сразу.

## Два режима работы

При обычном запуске Explorer95 работает рядом со штатным Explorer, не завершает его
процесс и не меняет загрузочную оболочку. Панель регистрируется как appbar и
резервирует свою рабочую область, чтобы развёрнутые окна её учитывали.

Если штатной панели `Shell_TrayWnd` нет, Explorer95 работает как основная оболочка:
резервирует рабочую область самостоятельно и принимает уведомления приложений через
совместимое окно `Shell_TrayWnd`. При выходе рабочая область восстанавливается.

В режиме рядом со штатным Explorer на Windows 95 доступно экспериментальное
зеркалирование трея: встроенная DLL наблюдает только поток штатной панели,
передаёт начальный список классического TrayNotifyWnd и принятые изменения значков.
Штатный Explorer продолжает работать, клики направляются исходным приложениям.
DLL извлекается из EXE под уникальным коротким именем `.DLL` в каталоге профиля
и освобождается при выходе. Запросы снимка обрабатывает WH_GETMESSAGE после
извлечения PostMessage из очереди Explorer; принятые изменения — WH_CALLWNDPROCRET.
Оба hook ограничены одним потоком Explorer. Ожидание ответа не блокирует панель;
одновременно допускается один запрос с тайм-аутом пяти секунд.
Цепочки получают настоящие общие HHOOK, необходимые старой USER32.
Запуск требует ответа DLL, а не только успешной отправки запроса. При отказе
сообщение указывает этап; `--trace-render` добавляет подробности в EX95REND.LOG.
Передаются пиксели и маска 16×16: дескрипторы картинок другого процесса не используются.
Начальный список передаётся небольшими порциями; завершение списка подтверждается
перед удалением прежних значков. При сбое доставки запрашивается новый снимок.
Раз в секунду выполняется запасная сверка: она подхватывает изменения и без
события sent-message hook. Неизменившиеся картинки, подсказки и callbacks не
пересоздают контролы и не сбрасывают время неактивности. Точное сравнение пикселей
использует ограниченный кэш: до 64 картинок 16×16, около 70 КиБ.
Поля `cbSize/uFlags` сохранённых записей не считаются заголовком входящего
уведомления: снимок читает используемые поля с проверкой памяти, callback и индекса
изображения. Записи с уже закрытым окном владельца пропускаются. Входящие пакеты
по-прежнему требуют точного размера ANSI v1 и допустимых флагов.
Клики не забирают фокус у активной программы; поддерживается двойной щелчок.
На других ОС этот механизм не включается. Пользователь подтвердил появление значков
штатного трея на настоящей Win95 в alpha.15. Проверки в Wine используют отдельный процесс с классическим форматом данных,
сравнивают пиксели и прозрачность и проверяют callbacks исходному приложению.
Сборки с IE4/иным устройством трея могут не поддерживать начальный список.
Трей Explorer95 рассчитан на
базовый ANSI-протокол Windows 95, а не на расширенные протоколы XP/современной Windows,
GUID, всплывающие баллоны или собственный формат Wine. Сквозная совместимость с
реальными приложениями Windows 95 ещё требует проверки на целевой системе.

## Замена оболочки Windows 95 и возврат

Откройте **правый щелчок по панели → Properties** либо
**рабочий стол → Explorer95 → Environment Properties**, затем вкладку **System Shell**.
В секции Windows 95 system shell доступны:

- `Use Explorer95 as shell...` — копирует программу в каталог Windows как
  `EX95xxxx.EXE` со свободным коротким именем, сохраняет исходную настройку
  и устанавливает её в `[boot] shell=`. Существующие и запущенные EXE не перезаписываются:
  обновление основной оболочки не упирается в блокировку старого файла Windows 95.
- `Restore previous shell...` — возвращает точную сохранённую команду, включая
  аргументы. Остальные записи SYSTEM.INI остаются на месте.

Изменения действуют **после перезапуска Windows**. Текущий Explorer автоматически
не завершается. На других версиях Windows изменение загрузочной оболочки запрещено
самой программой; пользовательские настройки панели при этом доступны.

Перед первой сменой создаются файлы в каталоге Windows:

- `EX95BAK.INI` — полная исходная копия SYSTEM.INI;
- `EX95REC.INI` — исходная команда оболочки и путь установленной программы.

Не удаляйте их до восстановления штатной оболочки. Программа отказывается заменять
неизвестную существующую резервную копию и не перезаписывает оболочку, которую после
неё выбрала другая программа.

**Восстановление из DOS:** откройте SYSTEM.INI в каталоге установленной Windows
(например, `C:\WIN95` или `C:\WINDOWS`) и восстановите только строку `shell=` в секции
`[boot]`, взяв её исходное значение из EX95BAK.INI. Для обычной установки это
`shell=Explorer.exe`. Сохраните файл и запустите Windows снова. Не восстанавливайте
весь старый INI поверх более новых системных настроек без необходимости.

## Открытие папок через Explorer95

В **Environment Properties → System Shell → Windows 95 folder opening**:

- **Use Explorer95 for folders...** — после отдельного подтверждения назначает
  Explorer95 обработчиком `open` / `explore` для файловых папок, дисков,
  «Моего компьютера» и «Корзины». Изменение действует сразу для всей системы;
  `SYSTEM.INI` и выбор загрузочной оболочки не меняются.
- **Restore folder handler...** — возвращает исходные команды, выбранные действия
  по умолчанию, DDE и дополнительные данные затронутых действий. Если другой
  файловый менеджер изменил эти действия, восстановление останавливается до записи.
  Посторонние действия, например Find, сохраняются вместе с их поздними изменениями.

Живая регистрация разрешена только на Windows 95. Сначала проверьте её в ВМ.
Программа готовит отдельный `Windows\EX95xxxx.EXE`, не перезаписывая запущенные
файлы. Полные исходные и устанавливаемые настройки сохраняются **до изменения
ассоциаций** в `HKEY_LOCAL_MACHINE\Software\Explorer95\FolderHandler`.
Резерв не заменяется при повторной установке; перед обновлением обработчика
выполните Restore, затем включите новый EXE. Не удаляйте подготовленные EXE или
этот раздел до успешного восстановления. При ошибке отката резерв сохраняется;
после прерванной записи может потребоваться ручное восстановление затронутых
`shell\open`, `shell\explore` и значения по умолчанию из снимков `Before`.

Регистрация меняет только `Directory`, `Drive` и CLSID двух указанных системных
объектов. Общий класс `Folder`, неизвестные namespace-расширения, файловые
ассоциации документов и диалоги «Открыть/Сохранить» остаются системными.
Прямой запуск сторонней программой `EXPLORER.EXE` также обходит регистрацию.
Штатный Explorer не заменяется и не завершается; полного DDE-сервера нет.

Двойной щелчок / Enter по папке, «Моему компьютеру» или «Корзине» на рабочем
столе Explorer95 открывает наше окно независимо от системной регистрации.
Виртуальные папки сохраняют настоящее представление Shell32 и его операции.

Для запуска извне доступны команды ANSI, пути с пробелами заключаются в кавычки:

```text
explorer95.exe --open="C:\My Documents"
explorer95.exe --explore="C:\"
explorer95.exe --namespace=computer
explorer95.exe --namespace=recyclebin
```

Можно добавить `--settings="C:\EX95\Explorer95.ini"`. Explore включает панель
Folders только в открываемом окне, не меняя сохранённые настройки. Уже работающий
Explorer95 принимает проверенный запрос через `WM_COPYDATA`; клиент завершается,
не создавая вторую панель задач. При отсутствии Explorer95 команда запускает
обычное окружение с нужным файловым окном. Это не режим отдельного файлового процесса.
Ключи штатного `explorer.exe` (`/e`, `/select`, `/idlist`) не эмулируются.

## Управление и настройки

- Start → `Exit`: закрыть Explorer95; для основной оболочки требуется подтверждение.
- Правый щелчок по свободной области панели: блокировка, автоскрытие, размер,
  положение, быстрый запуск, свойства и показ/восстановление рабочего стола.
- Сняв блокировку, тяните свободную область панели к нужному краю экрана;
  её внутреннюю границу можно тянуть для изменения толщины.
- Часы: двойной щелчок открывает системные настройки даты и времени.
- Win+D и Ctrl+Esc работают, если эти сочетания доступны для регистрации.
- В файловом окне: Enter/Go — перейти; F5 — обновить; Alt+Up — вверх;
  Ctrl+L/F4 — адрес; Enter/двойной щелчок в списке — открыть объект.
- Пути с пробелами в Run заключайте в кавычки:
  `"C:\Program Files\Example\app.exe" argument`.
- **Environment Properties** — одно окно для Taskbar, Start Menu, Desktop,
  Notifications и System Shell. Во вкладке Start Menu есть General, Advanced и
  Pinned programs. Все вкладки используют общие **OK / Cancel / Apply**: Apply
  сохраняет без закрытия, Cancel отменяет только ещё не применённые изменения.
  Очистка списков также ждёт Apply. Настройки файлового Проводника остаются в
  **Tools → Folder Options / Customize Toolbar**.
- **Start Menu → General**: надпись кнопки, малые/крупные значки, число недавних
  программ и выбор двухколоночного или классического одноколоночного меню.
  Fits on this screen учитывает размер экрана, значки, черновик закреплений
  и ещё не применённое положение/число строк панели задач.
- **Internet / E-mail**: необязательные верхние закрепления. Выберите программу
  из обнаруженных зарегистрированных приложений или кнопкой **...**. Они входят
  в общий предел шести закреплений; системные ассоциации Windows не меняются.
- **Start Menu → Advanced**: видимость команд, Favorites и режим **Link / Menu /
  Hidden** для папок, включая Control Panel и My Computer. В меню My Computer
  показываются буквы дисков без чтения меток или содержимого носителей.
  В двухколоночном стиле можно открывать подменю наведением и разрешить добавление
  программ/ярлыков перетаскиванием на открытый «Пуск». Классический стиль использует
  штатные компактные меню Windows, поэтому параметры размера значков, числа
  недавних программ, hover и drop для него отключены.
- **Highlight new shortcuts** выделяет новые ярлыки в меню программ: созданные
  после первого запуска Explorer95 и ещё не открытые через это меню. Это учёт
  ярлыков, а не слежение за установщиками. **Clear recent documents** очищает
  системный список через Shell32, сохраняя сами документы.
- **Start Menu → Pinned programs**: Browse выбирает файл, Add добавляет запись;
  Remove / Move up / Move down меняют порядок. История программ и закрепления
  остаются отдельными списками. Очистка истории не удаляет закрепления.
- **Desktop**: видимость, Auto Arrange, Lock icon positions, Snap to grid и два
  поля шага сетки (64–200 пикселей). Те же параметры доступны через правый щелчок
  на пустом месте → **Icon Layout**; в меню есть готовые шаги и **Desktop Settings...**
  для произвольного значения. Изменения в меню применяются сразу и отражаются
  в открытых настройках; изменения полей вкладки ждут Apply / OK.
  **Line up icons now** немедленно привязывает текущие позиции к применённой сетке.
  Auto Arrange использует штатное расстояние Windows; для свободной расстановки
  выключите его и блокировку позиций. Изменение шага само не переставляет значки.
  Обычное перетаскивание левой кнопкой расставляет значки в пределах рабочего стола;
  образ движется по пикселям даже при Snap to grid. При отпускании сдвигаются
  только пересекающиеся значки; остальные сохраняют места. До отпускания и при
  отмене реальные позиции не меняются. Line up и загрузка прежней раскладки также
  устраняют наложения, когда доступного места достаточно.
  для системных операций с файлами используйте перетаскивание с Ctrl/Shift/Alt
  или правой кнопкой. Lock icon positions блокирует начало перетаскивания значков.
  Штатный `desk.cpl` используется для фона, цветов и заставки.
  Скрытие значков сохраняет рабочий стол и его обои. Системное окно дисплея
  применяет свои изменения самостоятельно.
- Правый щелчок по недавней программе → Pin to Start menu; правый щелчок
  по закреплению → Unpin from Start menu. Изменение сохраняется сразу, включая
  аргументы запуска, и не удаляет программу с диска.
- Во вкладке Taskbar можно открыть папку Quick Launch; часы, таймаут и правила
  значков находятся в Notifications. System Shell содержит установку/восстановление
  загрузочной оболочки и обработчика открытия папок с отдельными подтверждениями.
- Если Windows 95 отклоняет прямой Log Off с `Incorrect Function`,
  Explorer95 предлагает штатный системный диалог. В нём выберите выход и вход
  другим пользователем. Доступность этого режима зависит от конфигурации Windows;
  принудительное завершение программ или перезагрузка вместо выхода не выполняются.

Настройки по умолчанию лежат в `Explorer95\Explorer95.ini` внутри папки данных
пользователя, возвращённой Shell32; рядом находится папка `Quick Launch`.
Для отдельного профиля можно указать существующий каталог:

```text
explorer95.exe --settings="C:\EX95\Explorer95.ini"
```

Применение окружения сохраняет `[Taskbar]`, `[Start]`, `[Desktop]`, `[Pinned]`
и `[TrayPolicies]` вместе через временный файл в каталоге профиля. При ошибке записи
живые параметры не меняются; существующие секции Проводника и другие неизвестные
параметры сохраняются. В новых ключах `[Start]` хранятся `Classic`, `HoverMenus`,
`AllowDrop`, `HighlightNew` и `FolderMenus` (биты папок соответствуют VisibleItems).
`[Desktop]` содержит `ShowIcons`, `AutoArrange`, `LockIcons`, `SnapToGrid`,
`GridWidth` и `GridHeight`; `[Taskbar] InactiveSeconds` — таймаут
трея. У закреплений `ClientN=1/2` обозначает Internet/E-mail. Старые INI продолжают
работать без ручной миграции. `[SeenShortcuts]` хранит ограниченный список из 64
открытых пунктов для подсветки новых ярлыков.

Позиции значков лежат отдельно рядом с выбранным профилем: например,
`Explorer95.ini.DIP`. При резервном копировании забирайте INI и этот файл вместе.
Это собственный двоичный формат Explorer95, до 1024 значков; приложение само
не записывает координаты в реестр штатного Explorer. Запись выполняется после переноса и при выходе,
через временный файл и резерв предыдущей копии. Сопоставление идёт по подписям
значков, а не индексам списка; одинаковые подписи сопоставляются по очереди.
После переименования сохранится новая подпись при следующей записи; при смене
языка системных подписей может потребоваться расставить эти значки заново.
При уменьшении рабочей области позиции ограничиваются её границами. Новые файлы
не получают позиции удалённых по старым индексам. Чтобы сбросить сохранённую
расстановку, выйдите из Explorer95 и удалите только файл `.DIP` своего профиля.

## Параметры Проводника

Раздел `[Explorer]` в том же INI не связан с размером значков «Пуска» или Quick Launch:

```ini
[Explorer]
View=0
Folders=0
FolderWidth=200
ExplorerBar=1
RememberHistory=1
Toolbar=1
AddressBar=1
StatusBar=1
TextLabels=1
LargeToolbarIcons=1
ShowHidden=0
ShowExtensions=1
ToolbarButtons=0
```

`View`: 0 — Icons, 1 — Small Icons, 2 — List, 3 — Details, 4 — Tiles,
5 — Thumbnails. `FolderWidth` ограничен 120–400 пикселями и доступной шириной окна.
`ToolbarButtons` — сумма флагов: Copy=1, Cut=2, Paste=4, Delete=8,
Properties=16, Folder Options=32; все шесть — 63. Избранные пути хранятся
в `[ExplorerFavorites]` как `Folder0`…`Folder7`.
`ExplorerBar`: 0 — нет панели, 1 — Tasks, 2 — Folders, 3 — Search, 4 — History.
Старый `Folders` читается как запасное значение и сохраняется для совместимости.
`RememberHistory=0` отключает сохраняемую историю. Её раздел `[ExplorerHistory]`
хранит до 32 пар `TargetN` / `LabelN`; служебный префикс `!` сохраняется вместе со значениями.

Клавиши: Alt+Left / Alt+Right — история, Alt+Up / Backspace — выше,
F3 / Ctrl+E — панель поиска, Ctrl+H — история папок, F5 — обновление, F2 — переименование,
Alt+Enter — свойства, Ctrl+C / X / V / A — файловые операции,
Ctrl+L / Alt+D — адрес, F4 — список адресов.

## Диагностика перекрытия и мерцания

Если проблема повторяется на Windows 95, полностью выйдите из уже запущенного
Explorer95, затем запустите новую сборку с параметром:

```text
explorer95.exe --trace-render
```

В Run укажите полный путь к EXE, если он не находится в текущем каталоге.
Можно совместить параметр с `--settings="C:\EX95TEST\Explorer95.ini"`.
Если другой экземпляр работает, диагностический запуск сообщит об этом,
чтобы не принять старую запущенную версию за новую.

Повторите проблему и выйдите из Explorer95. Рядом с **запущенным** EXE появится
файл **EX95REND.LOG**, который можно приложить к отчёту. Для проблем Корзины
строки `shell stage=recycle.*` записывают выбранный обработчик, код результата
и количество объектов без их имён. Если оболочка установлена
под именем EX95xxxx.EXE в каталоге Windows, журнал будет лежать в этом же каталоге.

Журнал содержит версию ОС, разрешение/глубину цвета, время и сообщения окон,
порядок соседних HWND, активное окно, прямоугольники и clip области стирания.
Для зеркала трея он также записывает номер этапа, ошибку и число значков:
1 — данные TrayNotifyWnd, 2 — массив, 3 — записи, 4 — image list, 5 — упаковка
картинки, 10 — извлечение DLL, 11 — загрузка, 12 — установка hook,
13 — постановка запроса в очередь, 14 — тайм-аут ответа, 20 — получен снимок.
Уточнение `detail` указывает причину: 1 — нечитаемая запись (`value` — индекс
строки), 2 — число записей закрытых окон, 3 — callback, 4 — индекс изображения,
5 — сохранённый `cbSize`, 6 — сохранённые флаги. Этап 30 с `error=0` информационный:
он отмечает пропущенные записи и необычные неиспользуемые поля, не прерывая снимок.
Журнал с `stage=3 error=50` из alpha.14 подтверждает ответ DLL, но ещё не различает
конкретную проверку записи; для этого нужна текущая версия с `detail/value`.
Код 1114 в старой сборке при этапе 14 выставлял сам Explorer95; он не доказывал
ошибку загрузчика DLL. Текущая сборка сообщает ERROR_TIMEOUT (1460).
Он не собирает имена открытых файлов, заголовки окон или нажатия клавиш.
Размер ограничен 512 КиБ, следующий диагностический запуск перезаписывает журнал.
По умолчанию журнал не создаётся; режим нужен только для диагностики.

## Сборка и проверки

Нужны GNU Make и 32-битный MinGW-w64 GCC (`gcc-mingw-w64-i686` на Debian/Ubuntu).
Также нужен `i686-w64-mingw32-windres` (из binutils-mingw-w64-i686) для BMP-ресурса.
Python 3 нужен для проверки структуры EXE.

```sh
make check
# Или, если компилятор имеет суффикс -win32:
make check CC=i686-w64-mingw32-gcc-win32
```

Результат: `build/explorer95.exe`. Это PE32 для x86/i386 с Windows GUI/OS 4.0,
ANSI Win32 API и без MSVCRT/UCRT, .NET или движка тем.
Флажок использует цветовой ключ `RGB(192,192,192)`: TransparentBlt загружается
динамически из системной MSIMG32.DLL, если она установлена. В чистой Windows 95
этой функции нет; используется эквивалентная GDI-маска без обязательной зависимости
от MSIMG32. Сам bitmap встроен в EXE и не нужен отдельным файлом. Shell32 и COM используются
через базовые интерфейсы; IE4 и Active Desktop не требуются.

В текущей облачной среде:

```sh
make check CC=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-gcc-win32 \
  WINDRES=/workspace/.explorer95-tools/root/usr/bin/i686-w64-mingw32-windres
```

Сборка инкрементальная: каждый C-файл компилируется отдельно, зависимости от
заголовков создаются автоматически. x86 и x64 используют разные объекты; тесты
повторно используют объекты общих модулей. Изменение компилятора или флагов
сбрасывает соответствующие объекты. Для обычной правки `make clean` не нужен.
Можно использовать `make -j2 check` для параллельной сборки. Если установлен ccache,
`make -j2 check CCACHE=ccache` включает кэш компиляции; в CI он сохраняется между
запусками отдельно для каждой архитектуры. Первый запуск с новым кэшем — холодный.

Для небольших изменений выбирайте относящиеся к ним проверки:

| Команда | Объём |
| --- | --- |
| `make layout` | Расчёт геометрии «Пуска» на обычном C-компиляторе, без Wine и запуска оболочки. |
| `make ui64-smoke TEST_GROUP=menu` | Общее окно настроек, Apply/Cancel/ошибка записи, геометрия, закрепления, оба стиля «Пуска» и подменю. |
| `make ui64-smoke TEST_GROUP=browser` | Навигация, файловые операции, режимы, дерево и отрисовка системных папок. |
| `make ui64-smoke TEST_GROUP=core` | Геометрия, отрисовка флажка, фильтрация истории и установка shell на временных файлах; EXE приложения не требуется. |
| `make ui64-smoke` | Полный сценарий, включая панель задач, трей, выход и повторный запуск. |

У `make smoke` для x86 те же значения `TEST_GROUP`. По умолчанию всегда `full`;
неизвестное имя завершает тест с ошибкой. Wine-группам нужен дисплей, например
`WINEPREFIX=/tmp/explorer95-ui sh tests/run_ui.sh TEST_GROUP=menu WINE=wine64`;
используйте отдельный одноразовый Wine prefix. Для headless-прогона нужны Xvfb,
xauth и Openbox. Скрипт запускает оконный менеджер без сочетаний клавиш, чтобы
Win/D/Ctrl+Esc получал Wine, и ждёт его готовности. Данные Unix-корзины Wine
изолированы внутри prefix: одного нового prefix для изоляции корзины недостаточно.
По умолчанию проверяется 640×480; `EX95_TEST_SCREEN=1024x768x24` выбирает больший экран.
Без оконного менеджера Xvfb может оставлять скрытые окна видимыми и неверно
обрабатывать положение «поверх окон»; пиксельные проверки в таких условиях недостоверны.
`make layout` использует те же случаи геометрии,
что включены в полный Windows smoke-тест, и не заменяет визуальную проверку.
Для изменения ширины меню достаточно `make layout`, сборки/PE-проверки и группы
`menu` с визуальной проверкой обоих размеров значков на маленьком и обычном экране.

Сама инфраструктура проверяется командами
`python3 -m unittest discover -s tests -p test_select_checks.py` и `make check-build`.
Последняя собирает маленький пример по настоящему Makefile во временном каталоге:
проверяет отсутствие лишней компиляции и обновление объектов при изменении C-файла,
заголовка, флагов и bitmap, не меняя рабочие исходники.

В одноразовом Windows/Wine-окружении с поддержкой 32-битных приложений и дисплеем:

```sh
make smoke
```

Тест создаёт свой профиль и временные файлы, проверяет навигацию, рабочий стол,
первичную отрисовку системных папок и сохранение значков после перерисовки
только родительского окна, прозрачность флажка на цветном фоне через TransparentBlt
и запасной GDI-путь, крупные значки и их сохранение, фильтрацию ярлыков
и очистку прежней истории, контекстное закрепление/открепление,
Run, историю, закрепления и их аргументы/порядок, отмену редактирования,
подпись Start, скрытие команд, общее окно настроек, Internet/E-mail, классический стиль,
подменю при наведении, режимы папок, сохранение секции Explorer, видимость рабочего стола,
отказ записи в read-only профиль, отдельные политики трея, быстрый запуск, группировку, уведомления трея, Show Desktop,
сохранение настроек, края экрана и автоскрытие. Расчёт геометрии проверяется
для 320×240, 640×480, 800×600, 1024×768, 1280×720 и 1920×1080, трёх высот
шрифта, обоих размеров значков и всех четырёх положений панели; отдельно проверяется, что реальное окно
«Пуска» и его видимые кнопки помещаются рядом с панелью на каждой стороне экрана. Backend установки/восстановления
оболочки проверяется **только на временных INI-файлах**, не на системном SYSTEM.INI;
также проверяется установка рядом с заблокированным EXE и обновление с сохранением
первой резервной копии. Реальное завершение сеанса и загрузка Win95 требуют проверки в ВМ.
Размер значков во вложенных списках программ/документов и сходство с референсом
дополнительно проверяйте визуально. Перед тестом закройте другие экземпляры Explorer95.

Если хост не исполняет 32-битные процессы, доступна тестовая сборка того же кода:

```sh
make ui64-smoke WINE=wine64
```

Для неё нужен `x86_64-w64-mingw32-gcc`. Файлы из `build/ui64` не предназначены для
Windows 95. Проверка пакетов трея под Wine проверяет регистрацию и callbacks;
передача HICON между процессами Wine отличается от Windows 95 и отдельно не
подтверждена этим тестом.

`make check` проверяет заголовки PE и разрешённые импорты, а также запускает
быстрые регрессии самого проверяющего кода (`tests/test_check_pe.py`). Независимые
PE-примеры проверяют разрешённый импорт, отказ для `EndMenu`, новых API, CRT,
непроверенных ordinal-импортов, неправильной архитектуры, новой версии ОС и TLS.
Повторное ошибочное добавление `EndMenu` в allowlist сломает регрессию.
Это не доказательство полной совместимости с Windows 95: allowlist — список
проверенных проектом импортов, а не выгрузка экспортов конкретной установленной ОС.
Тесты под Wine не обнаруживают отсутствия экспортов в DLL Windows 95.
Для отмены меню используется [рекомендованный Microsoft запасной путь](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-endmenu#remarks)
через `WM_CANCELMODE`; группа `menu` проверяет повторное нажатие Start,
освобождение кнопки и повторное открытие классического меню.
UI-группы CI выполняются от обычного пользователя
под Wine 10/x64 в Debian 13, включая прежний пятисекундный предел выхода.

GitHub Actions запускает проверки при push в `main` и для pull request. Отдельный
workflow `Win32 build` можно запустить вручную с нужной группой; по умолчанию `full`.
`tests/select_checks.py` выбирает проверки по изменённым путям: документация
пропускает сборку и Wine, модули «Пуска» выбирают `menu`, файлового браузера —
`browser`, backend установки shell — `core`. Общие модули, ресурсы, тесты,
Makefile, workflows, неизвестные пути и смешанные изменения запускают `full`.
Это консервативный выбор по файлам: внутри файла он не различает правку отступа
и изменение поведения. Для рискованной правки вручную выбирайте полный прогон.

Устаревшие CI-запуски одной ветки/PR отменяются. Итоговый job `Checks` учитывает
ошибки выбранных проверок и корректно пропущенные задания; его можно использовать
как обязательную проверку ветки. Логи Wine сохраняются в artifacts и при ошибке.
На `main` сравнение идёт с последним успешным автоматическим прогоном, а в PR —
со всей базовой веткой. Поэтому быстрая следующая отправка документации не скроет
изменения кода из отменённого или неуспешного прогона. Если базу найти не удалось,
запускается полный набор; ручной частичный прогон базой не считается.
Теги `v*` запускают только release workflow: сборка x86 и полный UI-прогон идут
параллельно, а публикация EXE, ZIP и SHA256 ждёт успеха обоих. Дублирующего
запуска обычного build workflow на тег больше нет. Документационная или
инфраструктурная правка сама по себе не требует нового бинарного релиза.

Остаются ограничения: эскизы JPEG/PNG не реализованы;
группировка выполняется по процессу; не реализованы полный shell DDE/appbar-сервер
для сторонних панелей, расширенные уведомления и все внутренние протоколы Explorer.
Новый вариант замены оболочки необходимо проверить при реальной загрузке Win95 RTM/OSR2.
